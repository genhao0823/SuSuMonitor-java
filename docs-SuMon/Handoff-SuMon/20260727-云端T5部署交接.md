## 一、目的和边界

本手册用于在域名备案、DNS 解析和 TLS 证书准备完成后，继续完成 SuSuMonitor 的云端部署。

- 云端仅运行一个 Java 实例；终端路由状态保存在单 JVM 内存，禁止横向扩容。
- Java 仅监听 `127.0.0.1:18080`，Nginx 是唯一 HTTP/HTTPS/WSS 公网入口。
- MySQL 仅供本机 Java 使用，不得开放公网。
- 浏览器和家庭 Go Agent 都通过正式域名使用 HTTPS/WSS，不使用裸 IP 作为生产地址。
- Java、Nginx、MySQL 和 Agent 日志不得记录终端输入、输出、JWT、Monitor Ticket、Agent Token、数据库密码或私钥。
- 本文不含真实 IP、域名、密码、私钥、Token 或证书内容。示例中的 `SERVER_IP_OR_DOMAIN` 必须在目标环境替换，替换后的真实配置不得提交仓库。

## 三、当前阻塞项

域名仍在备案中，因此以下工作尚不能执行或验收：

- 域名 DNS 解析到云服务器。
- HTTPS 证书申请、安装和自动续期。
- Nginx `443` HTTPS 虚拟主机创建。
- 生产 CORS 的实际域名配置。
- Go Agent 的正式 `wss://SERVER_IP_OR_DOMAIN` 连接。
- 浏览器 Monitor WebSocket、Agent WebSocket 与终端公网链路验收。

备案完成不等于可上线。必须确认 DNS A/AAAA 记录已指向目标云服务器，并确认 HTTPS 证书签发与 Nginx 配置生效。

## 五、推荐执行顺序

### 阶段 A：建立域名与 TLS 站点

1. 在 DNS 服务商确认域名解析结果。
2. 在宝塔创建目标域名站点；不要覆盖默认站点或现有 Docker 服务配置。
3. 在宝塔申请或安装 TLS 证书，并确认 Nginx 监听 `443`。
4. 先备份实际 Nginx 站点配置。备份必须存在、非空、可读，且记录其路径。
5. 将 `server-java-SuMon/deploy/nginx-susumonitor.conf.example` 合并到目标 HTTPS `server` 块。
6. 将 Vue 构建产物的实际目录替换为 `root` 指令中的占位符路径。
7. 在 Nginx 配置中保留：

```text
/api/          -> http://127.0.0.1:18080/api/
/ws/agent      -> http://127.0.0.1:18080/ws/agent
/ws/monitor    -> http://127.0.0.1:18080/ws/monitor
```

8. 在目标主机执行 `nginx -t`。仅在语法检查通过后重载 Nginx。

禁止直接用仓库示例覆盖宝塔生成的完整配置，也禁止为调试而记录 WebSocket 帧正文。

### 阶段 B：收紧 MySQL 网络边界并备份

当前 MySQL 监听 `*:3306` 和 `*:33060`。即使 firewalld 当前未放行 MySQL，也不应只依赖防火墙。

1. 先确认没有需要远程访问 MySQL 的现有服务、容器或运维流程。
2. 备份当前 MySQL 配置文件，验证备份存在、非空和可读。
3. 确认 MySQL 监听地址配置的实际文件与生效优先级，再将经典协议端口限制到 `127.0.0.1`。
4. 如 X Plugin 的 `33060` 无业务依赖，应一并限制到本机或按实际业务明确关闭；不要猜测配置项。
5. 重启 MySQL 前再次确认影响范围和维护窗口。
6. 重启后验证：

```bash
ss -ltnp | grep -E '(:3306|:33060)'
```

期望结果是 MySQL 仅绑定回环地址，且应用健康检查可访问数据库。

7. 在首次启动会触发 Flyway 前，使用已确认的 MySQL 专用账户和备份方案创建逻辑备份。不得在命令行、Shell 历史、日志或本文档中暴露密码。
8. 验证备份文件存在、大小大于零且可读，再记录备份路径、时间和校验结果。

数据库恢复、清空、删除、Flyway 历史重置或回退迁移不属于正常发布流程；必须单独确认影响范围并验证备份可恢复后才能执行。

### 阶段 C：部署 Java 后端

在受信任构建环境的 `server-java-SuMon` 目录执行：

```bash
./mvnw clean package
sha256sum target/server-java-SuMon-0.0.1-SNAPSHOT.jar
```

上传已校验的 JAR 到云服务器新版本目录，例如：

```text
/opt/susumonitor/releases/RELEASE_ID/
```

首次安装需要创建：

- `susumonitor` 系统用户，禁止交互登录。
- `/opt/susumonitor/server`，由 root 管理。
- `/var/lib/susumonitor`，仅服务用户可写。
- `/etc/susumonitor/server.env`，必须为 `root:root`、`0600`。
- `/etc/systemd/system/susumonitor-server.service`。

完整的人工安装命令见 `server-java-SuMon/deploy/DEPLOYMENT.md`。不要在未核对目标路径和权限前直接批量执行。

环境文件至少需要正确设置：

```text
APP_ENV=prod
SERVER_ADDRESS=127.0.0.1
SERVER_PORT=18080
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=实际生产数据库名
DB_USER=专用数据库用户
DB_PASSWORD=仅写入 root-only 环境文件
JWT_SECRET=随机高熵密钥
AES_GCM_KEY=有效的 AES-256-GCM 密钥
AGENT_REGISTER_KEY=随机高熵密钥
AGENT_TRUSTED_PROXY_CIDRS=127.0.0.1/32,::1/128
CORS_ALLOWED_ORIGINS=https://SERVER_IP_OR_DOMAIN
```

禁止将真实环境文件上传、复制或提交到仓库。禁止将敏感值作为 systemd Unit 的明文 `Environment=`、shell 命令行参数或日志输出。

启用服务前执行：

```bash
systemd-analyze verify /etc/systemd/system/susumonitor-server.service
systemctl daemon-reload
systemctl enable susumonitor-server
systemctl start susumonitor-server
systemctl status susumonitor-server --no-pager
journalctl -u susumonitor-server -n 200 --no-pager
ss -ltnp | grep ':18080'
```

期望 Java 仅在 `127.0.0.1:18080` 监听。若启动失败，先查看 journald，不要将环境文件内容或密钥复制到日志。

### 阶段 D：验证与上线

按层级分别记录，不以低层级验证替代高层级验证：

| 层级 | 验证内容 | 成功标准 |
| --- | --- | --- |
| systemd | Unit 语法、进程状态、重启策略 | `systemd-analyze verify` 与 `systemctl status` 成功。 |
| 本机 HTTP | Java 回环健康检查 | `/api/health`、`/api/ready` 正常。 |
| Nginx | 配置语法与代理 | `nginx -t` 通过，重载后无错误。 |
| HTTPS | 正式域名证书与应用响应 | 浏览器和 curl 可经 HTTPS 访问。 |
| WebSocket | `/ws/agent`、`/ws/monitor` 升级 | Nginx 代理日志无握手错误，Java 可接收合法连接。 |
| Agent | 家庭 Linux Agent 出站 WSS | 不开放家庭入站端口，Agent 正常鉴权、心跳和指标上报。 |
| 终端 | Agent PTY 到 Monitor | `terminal.open/input/resize/close` 正常；不记录终端内容。 |
| 网络边界 | Java/MySQL 不公开 | 公网无法直接连接 `18080`、`3306`、`33060`。 |

真实终端慢消费者背压 `1011` 仍未在 WSL loopback 环境验证；部署后如需覆盖，必须使用受控网络限速或真实慢客户端专项验收，不能为压测任意扩大 PTY 输出或修改生产发送模型。

## 六、升级和回滚

### Java JAR 回滚

保留当前可用版本 JAR。升级仅替换 `/opt/susumonitor/server/susumonitor-server.jar` 的软链接并重启服务。

若新版本健康检查失败：

1. 停止进一步流量和配置变更。
2. 将软链接恢复到上一个已验证 JAR。
3. 重启 `susumonitor-server`。
4. 重新检查 `systemctl status`、journald、`/api/health` 和 `/api/ready`。

### 数据库回滚

Flyway 已执行的向前迁移不能通过替换 JAR 自动回滚。只有在明确影响范围、验证备份可恢复并取得最终确认后，才可进行数据库恢复。不得删除或修改已执行的 Flyway 迁移历史。

### Nginx 回滚

使用已验证的站点配置备份恢复目标站点文件，先运行 `nginx -t`，通过后再重载 Nginx。不得用不相关的宝塔默认配置覆盖目标站点。

## 七、后续 T6 家庭 Agent 部署

T5 HTTPS/WSS 验证完成后才推进 T6：

1. 在家庭 Linux 主机构建 Linux amd64 Agent：`make build-linux`。
2. 使用 `agent-go-SuMon/deploy/install.sh` 安装 root systemd 服务。
3. 将 `agent-go-SuMon/deploy/agent.env` 中的后端地址设置为 `wss://SERVER_IP_OR_DOMAIN`。
4. 使用一次性 Agent Token，环境文件必须为 `root:root`、`0600`。
5. 验证 Agent 重启、断网重连、云端重启和 Token 轮换。
6. 验证家庭网络无入站端口映射时，浏览器仍可经云端使用终端。

不要在域名/TLS 未就绪时将 Agent 配置为生产 WSS 地址，也不要把 Agent Token 写入仓库、聊天、日志或脚本参数。

## 八、交接时应提供的信息

备案完成后，继续部署前只需提供以下非敏感事实，不要发送密码、私钥或 Token：

1. 正式域名，以及 DNS 已解析生效的确认。
2. TLS 证书是否已在宝塔申请/配置完成。
3. 目标宝塔站点配置文件路径和 Web 根目录。
4. MySQL 是否存在远程访问依赖，是否允许重启和收紧监听地址。
5. 生产数据库名称、备份目录和维护窗口。
6. 云厂商安全组中已开放的端口列表。
7. 是否允许执行已明确影响范围的备份、Nginx 配置合并、MySQL 配置调整、systemd 服务安装和 Java 服务启动。
