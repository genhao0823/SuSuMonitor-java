## 二、部署架构

```
浏览器(手机热点) ──HTTP:80──→ nginx(82.156.245.102:80)
                                ├── / → SPA 静态文件(/www/wwwroot/susumonitor/)
                                ├── /api/ → proxy_pass 127.0.0.1:18080/api/
                                ├── /ws/agent → proxy_pass 127.0.0.1:18080/ws/agent (Upgrade)
                                └── /ws/monitor → proxy_pass 127.0.0.1:18080/ws/monitor (Upgrade)
                                        │
                          Java 后端 (127.0.0.1:18080) ←── MySQL (127.0.0.1:3306)
                                        ↑
                          WSL Agent (ws://82.156.245.102/ws/agent)
```

- Java 后端**仅监听 127.0.0.1:18080**，不对外，nginx 是唯一公网入口。
- Agent 从被监控主机**出站 WebSocket** 连 nginx 80，走 `/ws/agent`。
- 浏览器监控订阅走 `/ws/monitor`（带 ticket）。

## 三、前端部署

### 3.1 构建

```bash

npm run build      # vue-tsc 类型检查 + vite build → dist/
```

产物：`dist/index.html` + `dist/assets/*-[hash].js|css`

### 3.2 部署

```bash
# 传到 nginx webroot（覆盖）
scp -r dist/* root@82.156.245.102:/www/wwwroot/susumonitor/
ssh root@82.156.245.102 "chown -R www:www /www/wwwroot/susumonitor"
```

### 3.3 nginx 缓存策略（关键）

`/www/server/panel/vhost/nginx/susumonitor.conf` 已配置：
- `index.html` → `Cache-Control: no-cache, must-revalidate`（每次校验，确保拿最新资源哈希，避免浏览器缓存旧 HTML 引用到已不存在的旧 JS）
- `assets/` → `Cache-Control: public, immutable` + `expires 30d`（哈希化资源可安全长缓存）
- 开启 `access_log /www/wwwlogs/susumonitor.access.log`（排查请求是否到达、资源是否 404）

## 四、后端部署

```bash
cd server-java-SuMon
mvn package -DskipTests    # 产物 target/server-java-SuMon-0.0.1-SNAPSHOT.jar
```

### 4.2 部署（release + symlink 模式）

```bash
# 1. 创建新 release 目录
ssh root@82.156.245.102 "mkdir -p /opt/susumonitor/releases/cloud-YYYYMMDD"

# 2. 上传 jar
scp target/server-java-SuMon-0.0.1-SNAPSHOT.jar \
  root@82.156.245.102:/opt/susumonitor/releases/cloud-YYYYMMDD/

# 3. 切 symlink + 重启
ssh root@82.156.245.102 "
  ln -sfn /opt/susumonitor/releases/cloud-YYYYMMDD/server-java-SuMon-0.0.1-SNAPSHOT.jar \
    /opt/susumonitor/server/susumonitor-server.jar
  systemctl restart susumonitor-server
"
```

旧 release 目录保留可回滚（`ln -sfn` 切回旧目录 + restart）。

### 4.3 systemd 服务

`/etc/systemd/system/susumonitor-server.service`：
- `ExecStart=/usr/bin/java -jar /opt/susumonitor/server/susumonitor-server.jar`
- `Restart=always`
- 日志：journald（`journalctl -u susumonitor-server`）

### 4.4 后端配置

jar 内 `application.yml`，通过环境变量覆盖：
- `DB_HOST`/`DB_PORT`/`DB_NAME`/`DB_USER`/`DB_PASSWORD`（MySQL 连接）
- `CORS_ALLOWED_ORIGINS`（CORS，默认 `http://localhost:5173`）

实际部署通过 systemd 环境变量或 jar 启动参数注入（当前从进程 `/proc/<pid>/environ` 可查）。

## 五、Go Agent 部署

### 5.1 一键部署（推荐）

云服务器 nginx 托管二进制 + 脚本，目标机一行命令：

```bash
curl --fail --silent --show-error --location \
  http://82.156.245.102/agent/install-agent.sh | \
  sudo -E env \
    AGENT_BASE_URL=http://82.156.245.102 \
    AGENT_ALLOW_INSECURE_HTTP=true \
    AGENT_VERSION=1.0.0 \
    bash
```

脚本通过环境变量配置（`AGENT_BASE_URL`/`AGENT_ALLOW_INSECURE_HTTP`/`AGENT_VERSION`），交互式输入 admin 账密（从 `/dev/tty` 读，不回显），自动完成：登录→预建 server→发 token→下载二进制（sha256 校验）→写 `/etc/susumonitor/agent.env`(600)→装 systemd→启动验证。安装失败自动回滚旧版本。

**环境变量**：

| 变量 | 默认值 | 说明 |
|---|---|---|
| `AGENT_BASE_URL` | `https://monitor.example.com` | 后端地址，生产必须 HTTPS |
| `AGENT_ALLOW_INSECURE_HTTP` | `false` | 临时明文 HTTP 模式，仅允许 `http://82.156.245.102` |
| `AGENT_VERSION` | `1.0.0` | release 版本号（对应 `/agent/releases/` 子目录） |
| `AGENT_NAME` | `hostname -s` | 主机显示名 |
| `AGENT_SERVER_ID` | 空（新建） | 已有 server 时复用，跳过登录+预建 |
| `AGENT_ROTATE` | `false` | 是否轮换 token（生产应显式调后端 rotate 接口） |
| `AGENT_TERMINAL_ENABLED` | `false` | 是否开启 Web 终端（设 `true` 启用） |

> 临时 IPv4 测试用 `AGENT_ALLOW_INSECURE_HTTP=true`（仅允许 82.156.245.102）。生产环境上 HTTPS 后去掉此变量，`AGENT_BASE_URL` 改为 `https://域名`。

### 5.2 手动部署

```bash
# 构建（交叉编译 linux amd64 静态二进制）
cd agent-go-SuMon
GOOS=linux GOARCH=amd64 CGO_ENABLED=0 go build -o bin/susumonitor-agent-linux-amd64 ./cmd/susumonitor-agent

# 目标机部署
sudo install -m 0755 susumonitor-agent-linux-amd64 /usr/local/bin/susumonitor-agent
sudo mkdir -p /etc/susumonitor /var/log/susumonitor
sudo install -m 0600 agent.env /etc/susumonitor/agent.env    # 填真实值
sudo install -m 0644 susumonitor-agent.service /etc/systemd/system/
sudo systemctl daemon-reload && sudo systemctl enable --now susumonitor-agent
```

### 5.3 Agent 配置

`/etc/susumonitor/agent.env`（权限 0600）：

| 配置项 | 说明 |
|---|---|
| `SUSUMONITOR_BACKEND_URL` | `ws://82.156.245.102`（走 nginx，**不要**直连 18080） |
| `SUSUMONITOR_SERVER_ID` | 预建 server 的 id |
| `SUSUMONITOR_AGENT_TOKEN` | 预发的 token（一次性，不写日志） |
| `SUSUMONITOR_TERMINAL_ENABLED` | `true` 开启 Web 终端，`false` 关闭 |
| `SUSUMONITOR_LOG_LEVEL` | `info`/`debug`（debug 可见 metrics sent/reported） |

### 5.4 WSL 调试机

- WSL2 需 `/etc/wsl.conf` 设 `[boot] systemd=true`（`wsl --shutdown` 后重启生效）
- agent systemd 已 `enable`，WSL 启动后自动跑
- **WSL 不会随 Windows 开机自动启动**（WSL2 设计），需手动打开 WSL 终端或 `wsl` 命令拉起

## 六、本次会话修复的 Bug

| Bug | 根因 | 修复 |
|---|---|---|
| 登录点击无反应 | HTTP 非安全上下文下 `crypto.randomUUID` 不可用，请求拦截器抛错阻断请求 | `client.ts`/`websocket.ts` 加 `typeof crypto.randomUUID==='function'` 守卫 + 降级 |
| 服务器状态显示离线 | `updateAgentHeartbeat` 只更新 `agent_status` 不更新 `status` | `ServerMapper.xml` 三处 SQL 同步 `status` |
| Agent 断开后仍显示在线 | `afterConnectionClosed` 只清内存 registry 不更新 DB | 加 `markOfflineOnDisconnect`（乐观锁 `markAgentOffline`） |
| 终端黑框无响应 | `terminal.open` 的 `message_id` 非 UUID（crypto.randomUUID 降级成 Date.now()-random），后端 validator 拒绝 40003 | `terminal-ws.ts` 用 `getRandomValues` 生成 UUID v4 fallback |
| 终端 cols 极小 | `mountXterm` fit 时容器 CSS 布局未完成，cols=2 | `TerminalView.vue` onSocketReady 前重新 fit |
| 采集时间显示 UTC | `MetricsView` 直接显示 raw ISO 没调 `formatDateTime` | 改用 `formatDateTime` 转本地时区 |

详细记录见 `docs-SuMon/Difficulty-log/`。

## 七、已知问题

### 7.1 宽带运营商劫持 WebSocket（高优先）

宽带网络下 `/ws/monitor` 握手失败（后端 `invalid Upgrade header: null`）。根因：宽带运营商劫持明文 HTTP，去掉 WebSocket 的 `Upgrade: websocket` 头 + 注入 `ij.so9.cc` 脚本。

- 手机热点不受影响（已验证终端可用）
- **彻底方案：上 HTTPS + 域名 + WSS**（运营商无法劫持加密流量）
- 临时：用手机热点

### 7.2 明文 HTTP 安全上下文 API 受限

`crypto.randomUUID`、`crypto.subtle`、`navigator.clipboard` 等仅安全上下文可用。当前已全部加降级 fallback，但每次新增功能都需注意。HTTPS 一劳永逸。

## 九、预建 Server + 发放 Agent Token（后端 API）

```bash
# 1. 登录拿 JWT
curl -X POST http://82.156.245.102/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"ADMIN","password":"PASS"}'
# → data.token = JWT

# 2. 预建 server（SSH 字段占位，agent 模式不用）
curl -X POST http://82.156.245.102/api/servers \
  -H "Authorization: Bearer JWT" -H 'Content-Type: application/json' \
  -d '{"name":"my-host","host":"my-host","ssh_host":"127.0.0.1","ssh_port":22,
       "ssh_user":"agent","ssh_auth_type":"password","ssh_password":"placeholder"}'
# → data.id = SERVER_ID

# 3. 发放 agent token（明文一次性）
curl -X POST http://82.156.245.102/api/servers/SERVER_ID/agent/register \
  -H "Authorization: Bearer JWT"
# → data.agent_token
```
