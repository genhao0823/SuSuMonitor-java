## 二、MySQL 初始化

本机 MySQL 初始化脚本：

```text
scripts/local-mysql-init.sql
```

脚本职责：

- 创建数据库 `susumonitor`。
- 创建本机开发用户 `susumonitor@localhost`。
- 创建本机开发用户 `susumonitor@127.0.0.1`。
- 授权 `susumonitor` 用户访问 `susumonitor` 数据库。
- 刷新 MySQL 权限。

说明：

- 该脚本只用于本机开发。
- 业务表结构后续由 Java 后端 Flyway 迁移脚本管理。
- 生产环境不得使用本机开发密码 `732682`。

- 日志不得输出数据库密码、JWT、Token、SSH 密码、SSH 私钥、AES 密钥、Agent 注册密钥。
- 本机开发密码 `732682` 不得用于生产环境。
- Java 代码必须遵循《阿里巴巴 Java 开发手册》。

## 七、时间与时区约定（2026-07-31 补充）

**总原则：内部 UTC、展示层本地化（东八区）**。用户（前端）看到的页面时间即为北京时间。

| 层 | 口径 | 约定 |
|---|---|---|
| 应用时钟 | UTC | `ClockConfig` 返回 `Clock.systemUTC()`；所有 `LocalDateTime.now(clock)` 与业务时间字段（`collected_at`/`triggered_at`/`next_attempt_at`/`last_heartbeat_at` 等）一律 UTC |
| API 输出 | UTC ISO-8601（带 Z） | VO 的 `OffsetDateTime`；WS 帧 `timestamp`、消息契约 `occurred_at`/`collected_at` 同口径 |
| 前端展示 | 东八区（浏览器本地化） | `formatDateTime` 使用 `new Date(iso)` + 本地时间方法，页面上显示北京时间；前端不做时区转换代码 |
| 数据库默认时间戳 | MySQL 会话时区（本机为东八区） | `created_at`/`updated_at` 的 `DEFAULT CURRENT_TIMESTAMP` 为东八区——**已知混合现状**，仅作审计/排序展示，不参与业务时间比较 |
| SQL 时间函数比较 | UTC 口径 | 应用写入为 UTC，凡与 SQL 时间函数比较必须用 `UTC_TIMESTAMP()`（**禁止 `NOW()`**——会话时区东八区会造成 8 小时偏差，参见 outbox 退避失效修复 `519211d`） |

注意事项：

1. 新增时间字段必须使用应用时钟（`Clock.systemUTC()`）写入 UTC 值，不得依赖数据库默认时间戳参与业务逻辑。
2. 新增 SQL 若需与时间列比较，统一 `UTC_TIMESTAMP()`。
3. 若未来希望数据库默认时间戳也统一 UTC，需在迁移中显式 `DEFAULT (UTC_TIMESTAMP())` 或调整 MySQL 服务器 `time_zone`，并评估存量数据。
