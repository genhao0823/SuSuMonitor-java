### 2. 部署架构(云端实测拓扑)

```
浏览器(任意网络)
   │ http://82.156.245.102(明文,HTTPS 待域名备案)
   ▼
Nginx(宝塔,唯一公网入口)
   ├── /            → Vue 静态资源(dist,SPA fallback)
   ├── /api/        → proxy_pass 127.0.0.1:18080
   ├── /ws/agent    → Upgrade 代理(Agent 通道,3600s 超时)
   └── /ws/monitor  → Upgrade 代理(浏览器通道)
   ▼
Java 后端(仅监听 127.0.0.1:18080,systemd 托管,非 root 账户)
   ├── MySQL 8.4(127.0.0.1:3306,susumonitor 专用账号)
   └── RabbitMQ 4.3.4 + Erlang 27(vhost: susumonitor)
   ▲
Go Agent(被监控机,WSL/家庭 Linux/云端,出站 ws:// 或 wss://,不需要入站端口)
```

关键运维事实:
- Java 只用 `127.0.0.1:18080`,公网仅 80/443/22;MySQL/RabbitMQ 仅内网。
- JAR 发布采用 `releases/RELEASE_ID/ + symlink + systemctl restart` 模式,可回滚。
- 密钥文件 `server.env` root:root 0600,**JWT_SECRET/AES_GCM_KEY 丢失 = SSH 凭据永久不可解密**。
- 明文 HTTP 部署被验证存在运营商劫持风险(见 05 文档),HTTPS/WSS 为已规划未完成项。

## 三、数据库设计(MySQL,Flyway V1~V19)

| 表 | 关键字段/索引 | 用途 |
|---|---|---|
| `users` | username 唯一、password_hash、role、review_status、enabled | 用户 |
| `auth_bootstrap_state` | admin_initialized、initialized_user_id | 首管理员单例行锁 |
| `servers` | host+delete_token 唯一、credential 密文字段、ssh_host_key_fingerprint、status/agent_status、last_heartbeat_at | 服务器 |
| `agent_tokens` | token_sha256、status、created/rotated/revoked_at | Agent Token |
| `metrics` | (server_id, collected_at) 索引、固定宽表 13 字段 | 指标宽表 |
| `metrics_ingestions` | (server_id, message_id) **唯一** uk_metrics_ingestions_server_message | 上报幂等 |
| `message_outbox` | event_id 唯一、status pending/published、attempts、next_attempt_at、last_error | Outbox 待发布事件 |
| `alert_rules` | 生成列 + **唯一索引 uk_alert_rules_active_signature**(软删除行 NULL 不参与) | 告警规则 |
| `alert_records` | server_id/rule_id、status unread/read/resolved | 告警记录 |
| `alert_states` | active、version(乐观锁) | 告警状态机 |
| `message_consume_records` | (consumer, event_id) **唯一** | 消费幂等 |
| `terminal_sessions` | (user_id, open_message_id) 唯一、status/配额字段 | 终端会话元数据 |
| `commands` | 孤儿表(无代码引用,V4 遗留) | — |

设计要点:
- **软删除统一风格**:servers / alert_rules 均 `deleted=1`,唯一约束通过"delete_token/生成列"规避软删除行占用。
- **幂等两张表**:metrics_ingestions(入口幂等)、message_consume_records(出口幂等),支撑"至少一次"投递语义。
- **时间口径**:内部 UTC(`UTC_TIMESTAMP()` 比较,禁用 `NOW()`),展示层东八区本地化。

## 四、RabbitMQ 拓扑(冻结契约,`rabbitmq-topology-v1.md`)

```
                 producer                          consumer
 ┌───────────────┴───────────────┐
 │  metrics-service(Outbox 发布器) │
 └───────────────┬───────────────┘
                 │ metrics.reported.v1
                 ▼
        ┌──────────────────┐
        │ susumonitor.events│(topic, durable)
        └──────────────────┘
                 │ metrics.reported.v1
                 ▼
        ┌──────────────────────┐  重试耗尽/不可重试   ┌─────────────────┐
        │ susumonitor.alert.    │ ──────────────────► │ susumonitor.dlx │
        │ metrics(durable+DLX) │                     └───────┬─────────┘
        └──────────────────────┘                             ▼
                 │ AUTO ACK(事务成功)             ┌──────────────────────────┐
                 ▼                               │ susumonitor.alert.metrics │
        AlertMessageConsumer(幂等+3次重试)          │ .dlq(不自动回投,人工重放)  │
                                                 └──────────────────────────┘
  后续:alert-service 向 events 发 alert.triggered.v1(已预留 routing key)
```

- 全部 durable;队列名不含实例 ID;拓扑由 `RabbitMqTopologyConfig` 启动幂等声明,broker 重启自动重建。
- 消息信封统一:`event_id(UUID)/event_type/schema_version/occurred_at(UTC ISO-8601)/producer/payload`,冻结于 `message-contracts-v1.md`。
- 语义:**至少一次投递** + 消费侧幂等兜底;发布侧失败无限退避(Outbox 保证恢复后必补发),消费侧有限重试(3 次指数退避)→ DLQ。

## 五、WebSocket 双通道协议(冻结于 `websocket-protocol.md`)

公共消息结构:`{type, message_id(UUID), timestamp(UTC ISO-8601), payload}`,错误帧 `{type:"error", payload:{code, message}}`,code 与 REST 错误码同一套枚举。

### /ws/agent(Go Agent → 后端)

| 消息 | 方向 | 说明 |
|---|---|---|
| `agent.authenticate` | Agent→Java | **首帧必须**,server_id + token;10s 未认证关闭;成功回 `agent.authenticated` |
| `heartbeat` | Agent→Java | 30s 周期;回 `heartbeat.ack`;**90s 无心跳置离线** |
| `metrics.report` | Agent→Java | 每 5s;message_id 幂等键;collected_at 严格递增 |
| `terminal.*` | 双向 | open/input/resize/close + opened/output/closed/error |

### /ws/monitor(浏览器 → 后端)

| 消息 | 说明 |
|---|---|
| `metrics.subscribe/unsubscribe` | 订阅指定 server_id 的实时指标(幂等) |
| `metrics.update` | 服务端推送(事务提交后) |
| `alert.push` | 服务端推送(告警触发时,事务提交后) |
| `server.status.update` | 服务端推送(仅 online/offline **转换**时,普通心跳不推) |
| `terminal.*` | 终端请求/回显(控制帧限流 + 输出字节限流) |

安全细节:
- 浏览器 WS URL **不带长期 JWT**,而是先 `POST /api/ws/monitor-ticket` 换 30 秒一次性 ticket(内存 ConcurrentHashMap,原子消费,过期/重复用均 401)。
- Monitor 通道校验 Origin 白名单(防 CSWSH);Agent 通道靠首帧 token + IP 限流。
- 消息上限 64 KiB;非法 JSON 关 1007、超大 1009、策略失败 1008。

## 六、统一响应与错误码体系

REST 统一信封:`{code, message, data}`,前端拦截器按 code 分发。核心错误码(20 个,与 OpenAPI/前端 `error-code.ts` 三方对齐):

| 码 | 含义 | 码 | 含义 |
|---|---|---|---|
| 0 | 成功 | 40001 | 用户名或密码错误 |
| 40002 | 参数错误 | 40003 | 终端非法载荷 |
| 40100 | 未认证 | 40300 | 无权限 |
| 40301 | SSH 目标被禁止(SSRF 防护) | 40400 | 资源不存在 |
| 40900 | 资源冲突 | 40901/40902 | 主机指纹未确认/不匹配 |
| 42900~42904 | SSH 并发超限 / WS 限流 / 终端限流 | 50000/50001 | 内部错误/数据库错误 |
| 50002/50003 | SSH 连接失败/认证失败(HTTP 502) | 50400 | SSH 超时 |
| 50301 | RabbitMQ 不可用(ready 检查) | | |

可观测性:
- `X-Request-ID`(服务端生成 UUID,写响应 + MDC)+ `X-Correlation-ID`(前端透传,正则白名单),全局异常处理器保证 401/403 也带 request id。
- `GET /api/health`:进程存活(恒 UP);`GET /api/ready`:MySQL `isValid(2s)` + RabbitMQ 探测,失败 50301 —— **"存活但未就绪"**:Broker 挂了应用不退出,指标照常落库,outbox 退避重试。

## 七、关键设计决策(面试高频,附理由)

| 决策 | 理由 |
|---|---|
| **Go Agent 主动出站 + WS 长连接** | 被监控机无需公网 IP/开放入站端口,家庭内网可监控;一条长连接复用(心跳+指标+终端) |
| **指标宽表而非动态行模型** | 查询简单可索引,监控数据点固定;扩展新指标成本低(加列) |
| **Transactional Outbox 模式** | 解决"DB 事务 + 消息发布"双写一致性:指标与事件同事务,发布失败不丢、恢复必补;为未来微服务拆分留好边界 |
| **至少一次投递 + 双端幂等** | 比"恰好一次"工程上可行:入口 message_id 幂等,出口 event_id 幂等,重复不可怕 |
| **告警评估从本地事件切到 MQ 消费(MVP-11)** | 解耦 metrics 与 alert;消费侧 AUTO ACK + 幂等表,业务事务成功才确认 |
| **AES-256-GCM + AAD 绑定上下文** | 密文与 serverId+凭据类型绑定,换库/跨类型解密失败;12B IV + 128b tag 为 GCM 安全基线 |
| **JWT 每请求回查 DB 状态** | 审核拒绝/角色变更立即生效,不等 token 过期;代价是每次请求一次查询,单实例可接受 |
| **JWT 不放在 WS URL** | 防日志泄露;一次性 ticket(30s)替代 |
| **Java 不落终端内容** | 终端是敏感通道,只存元数据、内容直通,减少安全与合规风险 |
| **固定白名单而非用户输入拼接** | 排序字段 `<choose>` 固定分支、SSH 出站 CIDR/端口白名单、token 格式正则 —— 防注入/SSRF 的通用姿势 |
| **乐观锁(CAS 条件更新)贯穿** | 心跳防旧连接覆盖新连接、指纹防并发轮换、状态机 version、outbox status 条件写 —— 无分布式锁也能防并发错乱 |
| **时间统一 UTC + 应用 Clock 注入** | 测试可控(29.999s/30s 边界);避免 MySQL 会话时区 8 小时偏差类 Bug |
| **模块化单体 + 数据所有权契约** | 每个模块 Service 接口声明其拥有的表,跨模块访问走 Service 契约(审计收口 3 处违规) |
| **本地事务事件 → AFTER_COMMIT** | 事务提交成功才推送,回滚不推送;单 JVM 内可靠,跨实例问题已知并留痕 |
