# 2026-09-07 F2 运维问答工具化后端实现

## 一、背景与目标

按《20260903-AI阶段2规划》阶段 B：管理员通过自然语言提问，模型经**只读工具注册表**自主取数后回答。上一迭代（09-04 命令域 M1、09-05 F1 告警解释）已满足 F2 的前置依赖（M1 命令提案链路）。本日完成后端全链路，默认关闭（`AI_QA_ENABLED=false`）零影响合入。

## 二、Spring AI 选型评审（规划任务 B-1）

- **版本**：`spring-ai-bom:1.0.0`（2025-05 GA 线，支持 Boot 3.x / JDK17+；与本项目 Boot 3.4.13 + Java 21 兼容）。2.x 需要 Boot 4，不采用。版本经官方 BOM 统一管理，Maven Central 查询确认 1.0.0 为最新 GA。
- **依赖树审计**（`mvn dependency:tree`）：直接引入 6 个官方 jar——`spring-ai-openai` / `spring-ai-model` / `spring-ai-commons` / `spring-ai-template-st` / `spring-ai-retry` / `spring-ai-client-chat`（1.0.0）；传递 `spring-webflux:6.2.15` 与 `reactor-core:3.7.14`（spring-ai-retry 依赖，仅类路径存在，不启用响应式服务器）。无 Kotlin、无 r2dbc、无额外 HTTP 客户端。许可证 Apache-2.0。
- **不用 starter 自动配置**：引 `spring-ai-openai` + `spring-ai-client-chat` 模块而非 `spring-ai-starter-model-openai`，避免 `spring.ai.openai.*` 空配置时自动装配的不确定性；`SpringAiChatClient` 由 `susumonitor.ai.qa.enabled=true` 条件装配，默认零加载。工具机制直接使用官方 `@Tool`/`@ToolParam` 注解与 ChatClient Tool Calling 循环，不自研回调框架。

| 层 | 文件 | 说明 |
|---|---|---|
| 契约 | `pom.xml` | BOM + 2 依赖 |
| 契约 | `db/migration/V31__create_ai_qa_runs.sql` | 问答最小审计表（question_hash 代替原文、tool_calls_json 调用审计、三索引） |
| 契约 | `docs-SuMon/OpenApi-SuMon/openapi-ai.json` | v0.4.0，新增 `POST /api/ai/qa`（AiQaRequest/AiQa/AiToolCall schemas） |
| 配置 | `AppProperties.Ai.Qa` + `application.yml ai.qa` 段 | `AI_QA_*` 环境变量化（enabled/prompt-version/max-tool-iterations=6/max-question-length=2000/限流/日预算/清理） |
| Provider | `provider/SpringAiChatClient` | 手动装配官方 `OpenAiChatModel`（baseUrl+`/chat/completions` 与现有 provider 出站一致、超时共用）+ `ChatClient`；错误映射 42906/50303/50304/50401/50305 |
| Provider | `OpenAiCompatibleProvider.askWithoutTools` | 无工具单次问答降级路径（复用受控出站/重试/响应上限，不带 response_format） |
| 工具 | `tools/AiReadOnlyTools` | 6 个 `@Tool` 只读工具：get_server_status / get_latest_metrics / get_metrics_history(minutes≤240,points≤50 服务端 clamp) / list_alert_records(status 白名单,page≤5,size≤20) / list_command_templates / **propose_command_run（仅创建 pending_approval 提案，proposer 绑定 ThreadLocal 管理员，模型无法伪造）**；全部经模块 Service 契约取数 |
| 工具 | `tools/AiQaToolContext` | ThreadLocal 请求级上下文：actorId、轮次预算（超限抛异常终止 tool-loop）、调用审计（≤50 条） |
| 编排 | `service/AiQaService` | 仿诊断编排：qa kill switch → fail-closed 校验（敏感词同款保守表）→ 独立限流 → 独立日预算（查 V31）→ 并发许可 → beginAudit → **工具版 → 无工具版 → 确定性摘要三级降级**（HTTP 200 + model_used/degraded 标记，错误码只进审计） |
| 接口 | `controller/AiQaController` + `SecurityConfig` | `POST /api/ai/qa` admin-only；ai.enabled 装配 + qa.enabled 服务层双开关 |
| 审计 | `entity/AiQaRunEntity` + `mapper/AiQaRunMapper` + XML | insert/complete/fail/deleteExpiredBatch/selectTotalTokensBetween（与 V28 同模式） |
| 清理 | `service/AiQaAuditCleanupService` + `scheduler/AiQaAuditCleanupScheduler` | 30 天保留分批清理（cron `0 15 4 * * ?`） |

设计偏差说明：规划原文为"`SpringAiProvider` 实现 `AiProvider` 端口的第二个实现"；实际落地为独立 `SpringAiChatClient` 组件 + 既有 `OpenAiCompatibleProvider` 增无工具方法。原因：`AiProvider` 现有 3 个特化方法的实现都在 `OpenAiCompatibleProvider`（含 provider 配置 fail-closed 校验），注册第二个实现 Bean 会造成注入歧义或委托穿透；独立组件语义等价（QA 主路径 Spring AI、降级回退 OpenAiCompatibleProvider），且对既有诊断/解释/命令建议链路零改动。
