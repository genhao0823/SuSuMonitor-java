# 整体迁移部署收尾：公网切流与老后端下线

- **日期**：2026-09-13
- **性质**：整体迁移部署 Phase 5–7 收尾（Phase 0–4 构建产物/环境/数据库/服务已在前一日完成）
- **迁移路径**：老云服务器 `82.156.245.102`（genhaosan.online）→ 内网机 `10.177.3.70`（tx4），公网入口经云机 frps 隧道回流
- **结果**：老后端已停止并禁用自启，3 台在线 agent 全部落位新后端，域名 `https://genhaosan.online` 全链路（静态/API/双 WS）由新后端应答

## 一、拓扑与关键发现

| 项 | 结论 |
| --- | --- |
| 生产公网入口 | 云机 nginx 443 `genhaosan.online`（Let's Encrypt）承载 SPA 静态 + `/api` + `/ws/agent` + `/ws/monitor` 反代，是所有 agent 与浏览器用户的实际入口——并非此前设想的裸 IP:8443 |
| 腾讯云安全组 | 仅放行 22/80/443/7000/8888/8045/18080/25566/17860 等端口；**8443 被拦**（SSH 层无法修改，需控制台操作）；18080 安全组放行但被老后端 loopback 占用 |
| 云机 8045 | nginx `antigravity-tools.conf` 监听，代理 `127.0.0.1:18045`（frps ← AI 网关机器）；对外放行，带 Key 实测 `/v1/models` 正常返回 |
| frps（0.71.0，bindPort 7000） | 已有代理：17860（7860 webui）、18045（AI 网关）、25566（MC）、25580；目标机 `~/frp/` 早已存在 frpc 0.71.0 二进制及两个既有隧道服务（frpc-7860/frpc-mc，每隧道一个 systemd 服务的既定模式） |

## 二、本轮实施（按序）

1. **frpc-susu 隧道**：新建 `~/frp/frpc-susu.toml` + `/etc/systemd/system/frpc-susu.service`（沿用既有模式），最终代理为 `susumonitor-api-18081`：云机 18081 → 目标机 127.0.0.1:18080（仅云机本机回环使用，无需安全组暴露）。目标机 nginx `server_name` 补充 `82.156.245.102`，`/api` `/ws/*` 反代至本机 18080。
2. **最终数据同步**：停新后端 → 老库 `mysqldump --single-transaction` 双跳管道（云机 → 本机 → 目标机）全量重导入（137MB，dump 自带 DROP TABLE 幂等）→ 起新后端。
   - **踩坑修复**：首次重启 Flyway V34（create ai health reports）失败——该表在早前迁移时已由 V34 建出，不在老库 dump（V33）内，重导入后成为孤儿表，CREATE TABLE 撞已存在 + failed 记录导致校验卡死启动循环。处理：确认表为空 → 删孤儿表 → 清理 `flyway_schema_history` failed 行 → 重启，V34 success=1。
3. **server.env 修正**：`CORS_ALLOWED_ORIGINS=http://10.177.3.70,https://genhaosan.online`（移除安全组不可达的 8443 裸 IP 源）；`AI_BASE_URL=http://82.156.245.102:8045/v1`（目标机本机无 8045，改走云机对外放行的 AI 网关代理，带 Key 实测通过；`AI_ALLOW_INSECURE_HTTP=true` 已具备）。
4. **云机 nginx 切换（切换时刻）**：新前端 dist 覆盖部署至 `/www/wwwroot/susumonitor/`（保留 `agent/` 安装包、`.well-known/` 证书续期、`releases/`；整体备份 `susumonitor.bak-20260913`）；`susumonitor.conf` 上游 `127.0.0.1:18080 → 127.0.0.1:18081`（11 处，含 Host 头；备份 `susumonitor.conf.bak-20260913`）；`nginx -t` 通过后 reload。
5. **老后端下线**：`systemctl stop susumonitor-server && systemctl disable`。存量 WS 断开后，3 台 agent 依重连机制（5–60s 退避）经域名重连，全部认证到新后端。

## 四、决策与备注

- **agent 配置**：三台 agent 统一 `SUSUMONITOR_BACKEND_URL=wss://genhaosan.online`（域名切换法免逐台登机改动；8/10 两台本无 SSH 凭据，域名切流是唯一可行路径）。目标机 `/etc/susumonitor/agent.env` 含完整必填键。
- **8443 裸 IP 入口未启用**：安全组拦截且域名入口已覆盖全部场景；如后续需要，控制台放行 8443 + frpc 增补代理 + CORS 增补源即可。
- **老服务器现状**：后端已停禁；MySQL/RabbitMQ/nginx/AI 网关代理仍在运行（nginx 为域名+静态+AI 链路必需），老库保留作冷备，择期再下线。
- **回滚预案**：docroot 与 nginx conf 均有 20260913 备份；恢复 = 还原 conf 上游 18080 + 启用云机老后端。
