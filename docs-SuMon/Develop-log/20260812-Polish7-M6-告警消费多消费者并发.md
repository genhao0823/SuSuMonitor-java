# 开发日志: 告警消费多消费者并发（幂等去重保障 + 本地 broker 验收）

**日期**: 2026-08-12
**操作人**: ZCode
**阶段**: Polish-7 M6

## 背景

告警消费（`AlertMessageConsumer`）默认单消费者串行消费 `susumonitor.alert.metrics` 队列。文档遗留清单"多消费者并发消费"为后续阶段项。本模块落地可配置并发消费：幂等由 V15 `message_consume_records` 唯一键（consumer + event_id）+ 业务事务保障，并发下不产生重复消费。

## 设计决策（留痕）

- **默认保持单消费者**（`ALERT_CONSUMER_CONCURRENCY=1`）：兼容既有部署行为，仅当显式配置 >1 时设置容器并发与预取。
- **幂等保障不变**：V15 唯一键 + AUTO 确认（业务事务提交后 ACK）→ 并发下同一 event_id 只会被一个消费者成功落库，其余走 DuplicateKeyException 幂等路径。
- **边界声明**：outbox 发布器仍为单实例轮询；多 JVM（in-memory 注册表）仍不支持——均写入文档，属多实例阶段。

## 改动内容

### `module/alert/consume/AlertRabbitConfig.java`

- `rabbitListenerContainerFactory` 新增两个 `@Value` 参数：
  - `spring.rabbitmq.listener.simple.concurrency`（env `ALERT_CONSUMER_CONCURRENCY`，默认 1）
  - `spring.rabbitmq.listener.simple.prefetch`（env `ALERT_CONSUMER_PREFETCH`，默认 1）
- concurrency > 1 时设置 `setConcurrentConsumers` / `setMaxConcurrentConsumers` / `setPrefetchCount`；否则维持单消费者（不设置）。

### `application.yml`

- `spring.rabbitmq.listener.simple` 下新增 `concurrency` / `prefetch` 两键（`${ENV:default}` 风格）。

### 测试（`AlertRabbitConfigTests` 新增 2 例）

- 并发字段 setter-only 无 getter，反射读取（concurrentConsumers/maxConcurrentConsumers 在工厂类、prefetchCount 在父类）。
- 默认 concurrency=1：并发/预取均为 null（单消费者，与历史一致）；concurrency=4：并发 4/4、预取 2 生效。

## 真实验收（本地隔离 broker + MySQL，2026-08-12）

环境：本机 RabbitMQ 4.3.4（vhost `susumonitor`，用户 susumonitor 全权限）+ 后端 `ALERT_CONSUMER_CONCURRENCY=4` + 本机 MySQL。

1. **并发消费无重复**：向 `susumonitor.events` 发布 100 条合法 `metrics.reported.v1`（独立 event_id/message_id）→ 20s 后查询：
   - `message_consume_records`：consume_total=100、distinct_events=100、distinct_keys=100 → **(consumer, event_id) 唯一键零重复**
   - 队列 `susumonitor.alert.metrics`：0 消息、**4 consumers**（并发容器生效）
2. **DLQ 分类正确**：发布 3 条非法消息（schema_version=99 / event_type 错误 / occurred_at 非法）→ `susumonitor.alert.metrics.dlq` 3 条；`message_consume_records` 状态分布 100 consumed + 3 failed（失败留痕）。
3. 验收后已停止后端与本地 broker，环境复原。

**验收结论**：并发 4 下 100 条消息全部消费、无重复、无丢失，非法消息正确进 DLQ 并留痕。

## 调试实录（留痕）

1. **rabbitmq-start.cmd 编码坑**：.cmd 内 UTF-8 中文 REM 注释在 cmd(GBK) 下被误解析执行；改用项目自带 `rabbitmq.ps1 start`（Start-Process 包装）启动成功。
2. **vhost 错位**：后端经 `susumonitor.rabbitmq.uris` 连接 vhost `susumonitor`（本地开发既有布局），初版脚本发到默认 vhost `/` 导致 100 条消息堆积；修正发布 URI 后消费正常。
3. **新 broker 权限缺失**：免安装 broker 首次启动只有 guest 有 vhost `/` 权限，`susumonitor` 用户无权限 → 连接被拒；`set_permissions -p / susumonitor ".*" ".*" ".*"` 授权（注意 git-bash 的 `/` 路径转换需 `MSYS_NO_PATHCONV=1`）。
