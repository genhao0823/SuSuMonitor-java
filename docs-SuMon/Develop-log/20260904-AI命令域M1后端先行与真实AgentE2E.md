## 五、真实 Agent E2E（WSL Ubuntu 24+，全部真实执行）

环境：Windows 后端（dev 库，V29 前向迁移，`AI_COMMAND_ENABLED=true`）+ WSL2 Ubuntu Linux Agent（交叉编译二进制，`ws://172.26.112.1:18081`）。

| 路径 | 结果 |
|---|---|
| 手动建 pending → 审批下发 → Agent 真实执行 `uptime` | ✅ succeeded，stdout 真实 load average |
| 带参数模板 `journalctl -u ssh -n 5 --no-pager` | ✅ succeeded，stdout 真实日志 |
| 模板外命令 `rm -rf /` | ✅ 40004 拒绝，未执行 |
| 参数注入 `unit="nginx; rm -rf /"` | ✅ 40004 拒绝，未执行 |
| pending → reject → 再审批 | ✅ rejected → 40905 状态冲突 |
| AI 建议"检查磁盘空间使用情况" | ✅ 建议 `df -h` → 审批 → 真实执行 succeeded |

E2E 发现并修复 2 个真实问题：①模型自作主张在 params 塞未声明 `server_id` 键被严格校验拒绝（防线有效），增加"按模板声明过滤参数键"兼容层——渲染防线不变；②`@Scheduled` SpEL 引用 `@ConfigurationProperties` 生成 bean 名失败，改独立参数 bean。E2E 后清理：Agent 停止、测试服务器软删。

## 六、当前状态与剩余事项

**结论**：命令域 M1 审批制后端全链路（AI 建议 → 人工审批 → Agent 受限执行 → 审计回查）已在真实环境验证。AI 只能输出白名单模板 ID + 类型化参数，shell 元字符与模板外命令双侧拒绝；执行输出脱敏截断后落审计。

**剩余**：Web 前端审批 UI（外部依赖）；`ai_command_approvals` 独立表推迟到多人审批策略；M2 风险分级需 M1 审计积累；CI 门禁仍缺（RC1 阶段 3）。
