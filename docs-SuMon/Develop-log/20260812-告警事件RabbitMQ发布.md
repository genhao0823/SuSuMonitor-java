# 开发日志: 告警事件 RabbitMQ 发布（alert.triggered.v1 契约落地）

**日期**: 2026-08-12
**操作人**: ZCode
**阶段**: 告警事件发布（Polish-7 收口后下一阶段）

## 背景

`rabbitmq-topology-v1.md` §二 与 `message-contracts-v1.md` §四 冻结了 `alert.triggered.v1`
事件契约（信封 + payload 字段），但标注「预留，尚未实现 Broker 发布」。本模块将其落地为
真实发布：告警触发时经 Transactional Outbox 可靠发布到 `susumonitor.events`，并声明
`susumonitor.alert.triggered` 业务队列 + DLQ，为未来消费者/外部系统铺路。

## 设计决策（留痕）

- **走 Outbox 发布**（与 `metrics.reported.v1` 一致）：`AlertEvaluationServiceImpl.handleTrigger`
  评估事务内与告警记录同事务登记 outbox 行；Broker 不可用时事件保留、恢复后补发，
  符合契约「至少一次投递」语义。
- **`message_outbox` 新增 `routing_key` 列（V25）**：发布器按行路由，多事件类型共存，
  无需应用内映射表；现有行默认 `metrics.reported.v1`（语义正确，历史行均为 Metrics 事件）。
- **信封构建单点**：`AlertTriggeredEnvelopeFactory` 契约常量（EVENT_TYPE/ROUTING_KEY/
  PRODUCER/SCHEMA_VERSION）与 `OutboxEnvelopeFactory` 同模式公开，杜绝硬编码漂移。
- **消费者本次不实现**：契约 §四 定义为「出站通知」事件，面向未来外部系统；本次只落地
  发布侧 + 拓扑声明（业务队列 + DLQ），消息堆积在业务队列等待消费者接入——与 MVP-10
  发布先行先例一致（「消息堆积在业务队列等待消费者接入，不视为丢失」）。
- **删除已失效的 `susumonitor.rabbitmq.routing-key` 配置项**：全仓仅 application.yml 一处
  引用，无部署资产依赖（routing key 下沉为每行字段）。

## 改动内容

### 数据库

- `db/migration/V25__add_message_outbox_routing_key.sql`：`message_outbox` 新增
  `routing_key VARCHAR(64) NOT NULL DEFAULT 'metrics.reported.v1'`（`AFTER event_type`，带 COMMENT）。

### Outbox 泛化（`module/metrics/outbox/`）

- `OutboxEntity`：新增 `routingKey` 字段（`@TableField("routing_key")`）。
- `OutboxMapper.xml`：resultMap、列清单、insert 语句增加 `routing_key`。
- `OutboxService`：`enqueue(MetricsEntity, String)` → `enqueue(String eventType, String routingKey,
  String payload, String eventId)`（调用方仅 `MetricsServiceImpl` 一处）。
- `OutboxServiceImpl`：不再注入 `OutboxEnvelopeFactory`；泛化方法登记完整行
  （event_id/event_type/routing_key/payload/status/attempts/next_attempt_at）。
- `OutboxEnvelopeFactory`：新增 `ROUTING_KEY = "metrics.reported.v1"` 常量（契约单点公开）。
- `MetricsServiceImpl.report`：生成 eventId → 构建信封 → 泛化 enqueue。
- `OutboxPublisherServiceImpl.publishRow`：改用 `row.getRoutingKey()` 发布（原全局配置删除）。
- `AppProperties.Rabbitmq`：删除 `routingKey` 字段与 getter/setter；`application.yml` 删除
  `routing-key` 行。

### alert 发布侧（`module/alert/`）

- 新建 `module/alert/outbox/AlertTriggeredEnvelopeFactory`：
  - 契约常量：`EVENT_TYPE="alert.triggered"` / `ROUTING_KEY="alert.triggered.v1"` /
    `PRODUCER="alert-service"` / `SCHEMA_VERSION=1`
  - `build(AlertRecordVo, eventId)`：信封 + payload（server_id/rule_id/record_id/metric/
    current_value/threshold_value/level/status/triggered_at，UTC 秒级 ISO-8601），
    只携带契约冻结字段，不携带 message 等展示字段。
- `AlertEvaluationServiceImpl`：注入 OutboxService + EnvelopeFactory；`handleTrigger`
  record 插入后同事务登记 outbox 行（publishEvent 之前）；现有 `AlertTriggeredEvent`
  （WS 推送/外部通知 AFTER_COMMIT 监听）完全不动。

### 拓扑（`config/RabbitMqTopologyConfig`）

- 新增 `susumonitor.alert.triggered`（DLX 参数：susumonitor.dlx / alert.triggered.v1）
  + `susumonitor.alert.triggered.dlq` + 两条绑定（events→业务队列；dlx→DLQ），
  全部 durable/non-auto-delete。

### 测试（Maven 全量 486 tests 全绿）

- 新建 `AlertTriggeredEnvelopeFactoryTests`（3 例）：信封头/载荷与契约 §四 示例逐字段一致；
  契约常量稳定性断言。
- 更新 `AlertEvaluationServiceTests`：触发场景断言 outbox 登记（eventType/routingKey）；
  非触发场景（持续越界/恢复/计数窗口）断言不登记；setupService 适配新构造参数。
- 更新 `OutboxMapperMybatisTests`：建表加 routing_key；轮询用例断言每行 routing_key 回读。
- 更新 `OutboxPublisherServiceTests`：删除已移除的 setRoutingKey 配置；新增
  `rowsShouldPublishWithPerRowRoutingKey`（同一批 metrics/alert 两行按各自 key 路由）。
- 更新 `MetricsServiceTests` / `MonitorMetricsPublisherIntegrationTests`：适配新构造参数
  与 enqueue 四参数签名。
