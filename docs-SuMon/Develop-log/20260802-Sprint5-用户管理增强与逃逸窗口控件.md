## 二、后端：分页/搜索/批量审核（commit `4fac50a`）

### 参数传递设计

- `GET /api/admin/users/pending?keyword=&page=&page_size=` → `ApiResponse<PageResult<PendingUserVo>>`
  - `keyword` 可选：`username LIKE CONCAT('%', #{keyword}, '%')`（Service 层 trim，空串不过滤）
  - `page`（默认 1，`@Min(1)`）、`page_size`（默认 20，`@Min(1) @Max(100)`）；offset=(page-1)*pageSize
  - 过滤 `role='user' AND review_status='pending'`，`ORDER BY created_at ASC, id ASC`（保持原语义）
- `PUT /api/admin/users/batch-approve|reject`，body `{ user_ids: [1,2,3] }` → `ApiResponse<BatchReviewResult{processed, failed}>`
  - `@Valid @RequestBody` + `@NotEmpty` → 空列表 40002
  - 事务：外层 `@Transactional`；循环逐 id 复用 `updateReviewStatus`（`WHERE role='user' AND review_status='pending'` 乐观条件），单条失败 catch 累计 `failed` **不传播不整体回滚**，部分成功可展示

### 关键文件
- `UserMapper.java/.xml`：`selectPagePendingUsers` / `countPendingUsers`（Like + LIMIT 双查询）
- `UserService(+Impl)`：`pagePendingUsers(keyword, page, pageSize)` → `PageResult<UserEntity>`（users 所有权契约）
- `AdminUserService(+Impl)`：`pagePendingUsers` → `PageResult<PendingUserVo>`；`batchUpdateReviewStatus`
- 新 `BatchReviewRequest(user_ids)` / `BatchReviewResult(processed/failed)`；`AdminUserController` 3+2 端点
- 测试：`AdminUserServiceTests` +9、`AdminUserControllerTests` +3、新增 `UserMapperMybatisTests`（H2 验证 LIKE/LIMIT/COUNT）

### 契约
- `openapi-admin.json`：pending 返回 PageResult + 3 query 参数；新增 batch 端点 + `BatchReviewRequest`/`BatchReviewResult` schema；`@Valid` 补上（首版缺 `@Valid` 导致 `@NotEmpty` 不触发——测试抓出）；**openapi:check 5/5**
