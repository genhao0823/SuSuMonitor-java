## 二、测试驱动修复（E2E 联调发现的真实问题）

1. **多构造器装配失败**：provider 增加测试构造器后 Spring 报 "No default constructor found"，主构造器补 `@Autowired`（MySQL IT 暴露）。
2. **模型输出 markdown 围栏**：真实网关实测 content 被 ```json 包裹导致严格解析失败 → system prompt 固化完整 JSON schema（severity/confidence/source 枚举），解析前剥离围栏（不放宽字段校验）。
3. **模型自造 evidence**：实测模型输出伪造证据行（`observed_at:"current"`、`evidence_count` 等不可解析/无来源行）→ 按威胁模型"模型不得创建或修改事实"原则，evidence 一律以 Java 白名单上下文整体替换；`AiEvidenceVo.observedAt` 改为服务端组装的 ISO-8601 字符串。
4. **IT 聚合用例贴合真实写入路径**：token 由 `completeRun` 落库而非 insert，聚合测试改为 insert→complete 两段写入。

| 路径 | 结果 |
|---|---|
| 真实模型诊断 | HTTP 200，`model_used=true`，中文摘要 + 人工排查建议（无执行指令），`severity=critical`（合法枚举），`total_tokens=1394/1318`，审计 `status=completed` |
| provider 读超时降级 | 真实 30s 超时 → 审计 `error_code=50401` → HTTP 200 确定性摘要 `model_used=false`（重试只针对 429/瞬时网络，超时按设计不重试） |
| 错误密钥降级 | provider 401 → 审计 `error_code=50303` → HTTP 200 降级，原始错误不透传 |
| 按管理员限流 | 上限 3 次，第 4 次 HTTP 429 `42906`，审计无新行 |
| 按天预算 | 预算 1000、当日已耗 2712 → 直接 429 `42906`；日志 `budget exhausted, usedTokens=2712, budget=1000` |

| 中文请求 | UTF-8 请求体正常处理（Git Bash 命令行直传中文会因 Windows 代码页转码失败，属客户端工具限制，非后端缺陷） |
