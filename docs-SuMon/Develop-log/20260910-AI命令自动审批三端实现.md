# 2026-09-10 AI 命令自动审批（中低风险免人工直接下发）—— 后端 + Web + Android 三端

**状态**：完成 ✅ 后端 749 测试全绿、Web lint/177 测试/build 全绿、Android 120 单测全绿 + APK 构建成功；已部署生产（release `auto-approval-20260910`，V33 应用成功）并通过真实 Agent E2E（#8 txcloud）
**前置基线**：V32（按用户 AI 配置）+ 前端 AI 对接 + 深色模式收尾

## 一、背景与范围

用户诉求：中低风险命令希望 AI "自己审批自己"——生成建议后直接下发执行，不再逐条人工点"通过"；Web 与 Android 都要有配置页面。

**关键澄清**：执行通道不变（Agent WebSocket `command.execute` 帧，不新开 SSH 通道）；自动审批只跳过人工点击，模板白名单双端校验、参数正则、无 shell argv 执行、输出脱敏截断等全部防线原样保留。

## 二、技术决策

| 项 | 选择 | 依据 |
|---|---|---|
| 策略存储 | DB 单行表（V33），默认禁用 | 用户选择"前端页面可配"；fail-closed 语义=部署后行为与今天完全一致 |
| 适用范围 | 仅 `source='ai'` 的建议命令 | 用户原话"AI 审批自己的命令"；手动命令保持人工审批 |
| 审批入口 | `CommandRunService.autoApprove` 内部方法，无 REST 路由 | 杜绝"把任意 pending 记录改为自动执行"的攻击面 |
| 风险等级 | 模板表新增 `low/medium/high`（当前 8 模板全 low） | 契约 v1 §五已有 L1/L2/L3 分层语义，medium/high 为 M2 预留 |
| 阈值约束 | 仅 low/medium 可作阈值；high 模板任何配置下不自动审批 | "中低风险"语义 + ordinal 硬比较兜底 |
| 审计标识 | `approval_mode='auto'` + `approver_id=NULL` + `risk_level` 快照 | 机器审批与人工审批可区分；模板改级不影响历史行 |
| 失败隔离 | 单条自动审批失败（Agent 离线 40906）不阻断其余建议，失败行照常返回 | 失败可见性优先 |
| Web 入口 | AiCommandsView 第 3 个 Tab「自动审批」 | 命令域同上下文闭环（用户已确认页面可配方案） |
| Android 入口 | CommandRunsScreen 顶栏「策略」→ 新 `AutoApprovalPolicyScreen` | 与 Web 同域；AI Tab 本身 admin-only，子路由继承 |

## 三、后端改动（server-java-SuMon）

- **V33__add_command_auto_approval.sql**：`ai_command_runs` 加 `risk_level`/`approval_mode` 两列；新表 `ai_command_auto_approval_policies`（单行 id=1，`enabled` 默认 0、`max_risk_level` 默认 medium、CHECK 约束拒绝非法阈值），INSERT 禁用种子行
- **CommandRiskLevel**（新枚举）：LOW/MEDIUM/HIGH + `parse()` fail-closed + `isAllowedThreshold()`（high 不可作阈值）
- **CommandTemplateRegistry**：`Template` record 加 `risk` 字段，8 模板全部 LOW
- **CommandAutoApprovalPolicyService**（新）：`get()`（行缺失/读库异常/阈值非法 → 禁用快照）、`update()`（校验后 upsert）、`allows(Template)`（ordinal 硬比较，HIGH 永拒）
- **CommandRunService**：`createPendingRun` 落 `risk_level` 快照 + `approval_mode='manual'`；新 `autoApprove(runId)`（`autoApproveRun` CAS：仅 pending_approval → approved + approval_mode='auto'，不写 approver_id；成功后复用 dispatch + markExecuting；离线置 failed 40906）
- **AiCommandSuggestionService**：建议创建后按策略 `maybeAutoApprove`；单条失败回读最新行返回（失败可见）
- **CommandRunController**：`GET/PUT /api/ai/commands/auto-approval-policy`（admin）；`GET /templates` 增 `risk_level`；`CommandRunVo`/`CommandRunVos` 增 `risk_level`/`approval_mode`
- **Mapper**：`CommandRunMapper.autoApproveRun` + XML；新 `CommandAutoApprovalPolicyMapper`（selectPolicy/upsertPolicy，时间注入便于测试）

## 七、安全复查清单

- 无新增"审批任意 run"公开端点（autoApprove 仅服务内部调用）
- 策略端点沿用 `/api/ai/commands/**` hasRole(ADMIN) 统一声明
- fail-closed 三重：行缺失/读库异常/阈值非法 → 禁用
- 部署后默认禁用；env 总熔断 AI_COMMAND_ENABLED 不变
- 限流（10 次/小时/管理员）对自动审批同样生效（不新建额外运行）
- 威胁模型 v2 §八：T4 补偿控制 7 项 + 新增 T9（策略篡改）/T10（静默失败）
