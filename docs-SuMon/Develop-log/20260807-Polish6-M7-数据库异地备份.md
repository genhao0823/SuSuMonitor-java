# 2026-08-07 Polish-6 M7：数据库异地备份脚本

**状态**：完成（全链路验证通过）
**前置基线**：云端只有 backup.sh（本机脚本），无异地留存机制

## 一、实现

1. **新增 `scripts/remote-backup.sh`**（本机 Git Bash 运行）：
   - [1/4] 自动同步仓库 `server-java-SuMon/deploy/backup.sh` 到云端 `/tmp` 并以 root 执行（云端保留 1 份中间产物）
   - [2/4] scp 拉取云端最新备份到本机临时文件
   - [3/4] openssl AES-256-CBC + pbkdf2(100000) 加密落盘 `D:/SuSuMonitor-Backups/`，生成 `.sha256`
   - [4/4] sha256 校验 + 按 `--keep`（默认 7）轮换
   - 参数：`ENCRYPT_PASS`（必需）、`REMOTE`/`SSH_KEY`/`REMOTE_DIR`/`LOCAL_DIR`/`KEEP` 可覆盖
2. **修复 `backup.sh` CRLF bug**：云端 `server.env` 为 CRLF 行尾，`DB_PASSWORD` 提取后带 `\r` 导致 `mysqldump` 认证失败（"Access denied for user 'susumonitor\r'"）。修复：`tr -d '\r'`。

## 二、验证（真实执行）

- 完整跑通：云端备份（16M）→ 拉回 → 加密 → sha256 校验 ✓
- Round-trip 解密验证：`openssl enc -d -pbkdf2` 0.17s 解密成功，`tar -tzf` 见 `susumonitor.sql` + `server.env` ✓
- 验证发现的两个坑：
  - `openssl -pass env:ENCRYPT_PASS` 在命令前缀赋值场景下可能解析失败导致等 stdin 口令 → 脚本改用 `-pass pass:"$ENCRYPT_PASS"`
  - 验证命令自身 `VAR=x openssl -pass pass:"$VAR"` 时 `$VAR` 是外层 shell 展开（为空）→ 需先 `export`
- 保留最新一份真实加密备份 `D:/SuSuMonitor-Backups/susumonitor-20260807-213825.tar.gz.enc`（口令 `polish6-verify-temp-pass`，仅验证用，正式使用请自行设置口令）
