## 一、口径决策（已拍板）

1. **维持「任一认证用户可读」，修契约不收紧代码。** 四重依据：产品规范「普通 approved user 只允许查看服务器」（查看指标是其自然延伸）；Web 前端监控页对非 admin 开放（路由层仅 `/admin/users` 有角色门槛）；`MetricsControllerTests` 既有非 admin（role=user/approved）成功 200 断言；两个 Controller 的 `@Operation` description 本就写 "Authenticated users only"，仅 `@ApiResponses` 的 403 行是早期从 admin 端点复制的陈旧文案。反向选项（收紧 SecurityConfig 为 admin-only）会破坏既有非 admin 行为且无产品诉求，否决。
2. **契约版本 0.3.0 → 0.3.1（patch）**：无端点增删、无结构/字段变更，纯响应声明口径修正。
3. **访问矩阵用测试固化**：metrics 面 4 端点已有非 admin 200 用例；`monitor-ticket` 补 Controller 层 WebMvcTest（此前仅服务层测试，HTTP 边界零覆盖）。
4. **范围独立核实**：以 SecurityConfig 全部 requestMatchers 规则为事实源，对 7 个契约文件 58 个端点操作逐一交叉核对——不可达 403 恰好 5 处（`POST /api/ws/monitor-ticket` + metrics 面 4 个 GET），其余 53 处 403（39 个 admin-only 端点 + 登录审核态 403 等）全部可达且正确，无同类问题。
