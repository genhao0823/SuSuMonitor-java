## 一、交付内容

三端打通「实时 Top 进程」：Agent 每采集周期（默认 5s）扫描进程表，上报 CPU 占用与内存占比两个 Top N 排行；后端不做持久化，仅内存保留每服务器最新快照（90 秒新鲜窗口），REST 暴露最近快照，WS 随既有 `metrics.update` 帧捎带可选 `processes` 节点；前端实时监控页新增「实时进程」卡片（CPU/内存两个排行 Tab）。

| 端 | 改动 | 关键文件 |

## 五、遗留与后续候选

1. **进程历史持久化**：本期明确不做；如需回看历史排行，需分区表专项（参照 metrics 规模测算）。
2. **kill/终止进程操作**：不并入监控面；如立项应挂 command 域审批制（白名单模板 + 风险分级）。
3. **多盘/多网卡下钻**：Agent 现仅采 `systemDiskPath()` 单盘（既有现状），多盘下钻与进程监控同属"任务管理器"能力面，可一并规划。
4. **环境备注**：Windows 本机 Go 工具链 GOROOT 残缺（std 子目录缺失），Go 测试/构建统一走 `golang:1.23-alpine` 容器（daocloud 镜像源）；alpine 容器内 `internal/command` 既有失败待专项确认（musl/超时行为，基线即失败）。
5. F4-M2 观察期、多实例化阶段二/三、告警语义两项口径决策等既有遗留不变，见 20260912/0914 两份日志。
