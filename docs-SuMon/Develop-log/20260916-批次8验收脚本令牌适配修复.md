## 二、缺陷修复（`ce68d79`，fix(api-test)）

统一修复模式：脚本先查公开端点 `GET /api/auth/bootstrap-status`，`bootstrapPending=true` 时携带令牌（各脚本按既有环境变量族命名传入），否则保持历史请求体。要点：

- 首管理员并发 E2E：bash/PowerShell 双编排器生成 32 字节 base64url 令牌，**双路注入**（服务器 `AUTH_BOOTSTRAP_TOKEN` + 验证器 `SUSUMONITOR_VALIDATION_BOOTSTRAP_TOKEN`）；验证器在并发注册前做长度预检，pending 缺令牌时给出可操作错误而非一批 40310。
- 「恰好一个 admin」并发契约不变：同一有效令牌 + 行锁事务保证只有首个提交者成为 admin。
- 六个「登录失败则注册」兜底脚本与 docker-compose P0、可靠投递 E2E 同模式适配；已初始化实例行为与历史完全一致。
- `susumonitor.http` 补 bootstrap-status 查询与 pending 态注册示例。

验证：静态检查（node --check / bash -n / PSParser）全过；临时 mock（实现批次 8 语义，不入库）三路冒烟——缺令牌快速失败、错令牌透传 40311、正确令牌 8 并发 PASS；四端测试回归全绿。真实空库 MySQL E2E 留待批次 9 隔离库复跑窗口。
