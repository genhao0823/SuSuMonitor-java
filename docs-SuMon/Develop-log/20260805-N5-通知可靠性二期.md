## 完成内容

### N5-1/2 通知投递记录 + 退避重试（V21）

- 提交：`feat(server): add alert notification attempts with backoff retry (V21)`
- 数据库：`V21__create_alert_notifications_table.sql` — 每渠道一行：`alert_record_id`、`channel`、`status(pending/sent/failed)`、`attempts`、`next_attempt_at`、`last_error(500)`、时间戳；索引 `idx_record_channel`、`idx_next_attempt`
- 新增：`AlertNotificationEntity`、`AlertNotificationMapper(+xml)`（insert / selectPendingForRetry / markAttempt）
- `AlertNotificationServiceImpl` 改造：
  - `notify()` 为每个配置渠道插入 pending 行（回写主键）→ 立即尝试一次
  - 成功 → `sent`；失败 → `attempts+1` + `next_attempt_at = now + min(2^attempts, 60)s`（复用 outbox markRetry 的指数退避语义）+ `last_error` 截断 500（复用 FailedConsumeRecordRecoverer 的 best-effort 留痕模式）
  - 达 5 次上限 → `failed` 且不再重试
  - 至少一渠道送达仍聚合回写 `alert_records.notified_at/notify_channels`；全失败不回写
  - `sendXxx` 改为抛异常由统一 `attemptChannel` 捕获（失败原因落库）
- 新增 `NotificationRetryScheduler`：`@Scheduled(fixedDelay=30s)` 扫 pending 到期行重试（单轮 ≤50）；记录缺失或规则删除/禁用 → 置 failed
- `AlertNotificationService` 接口新增 `retry(notification, rule, record)`

### N5-3 前端通知失败可见性

- 提交：`feat(web): mark failed alert notifications in record list`
