## 二、模块一：AI 个人 Provider SSRF 防护（commit `4910726`）

- **新组件** `module/ai/provider/AiEgressPolicy.java`：`check(baseUrl)` 返回 `Verdict(allowed, reason)`。deny-private（默认）下拦截环回/RFC1918/链路本地/组播/未指定/IPv6 ULA（fc00::/7，Java 自带判定只覆盖已废弃的 fec0::/10，故按首字节 `(b & 0xFE) == 0xFC` 单独判定）/云 metadata（`169.254.169.254`、`169.254.170.2`、`100.100.100.200`、`fd00:ec2::254`，名单对齐 SshOutboundPolicy）；IP 字面量直接判定（含 IPv6 方括号剥离）；域名解析上限 8 超出即拒；解析失败 fail-closed 拦截。
- **配置**：`susumonitor.ai.user-provider-egress-policy: deny-private | allow-private`（`AppProperties.Ai#userProviderEgressPolicy`，`@Pattern` 启动期校验）。
- **双重校验落点**：
  - 保存/测试期：`AiUserProviderConfigService.validateEndpoint` 末尾追加 egress 校验（40002）；
  - 调用期：`OpenAiCompatibleProvider.chat()` 与 `SpringAiChatClient.ask()` 入口 `validateEgress()`（仅按用户配置构造、挂接了策略的实例生效），拦截抛新错误码 `AI_PROVIDER_ENDPOINT_BLOCKED(50306, BAD_GATEWAY)`。
- **实现偏差说明（相对计划）**：计划原定通过自定义 `ClientHttpRequestFactory` 在 `createRequest` 挂钩；实施时发现工厂内抛出的受检异常会经 Spring RestClient 包装为 `ResourceAccessException`，从而落入 50303 错误面并触发既有退避重试（`ProviderRetryPolicy` 对非超时网络错误可重试）——语义错误。改为在受控出站路径（chat/ask）入口、重试模板之外校验，拦截以 50306 直达调用方，确定且不可重试。残余的"校验与连接之间 DNS TOCTOU 窗口"（受 OS 正向缓存影响，秒级）为已接受限制。
- **缓存一致性**：`AiProviderResolver` 指纹追加策略值——策略在 deny-private/allow-private 间切换后，已缓存实例立即失配重建，避免放宽后旧实例仍拒绝。
- **测试稳定性修复（提交于 `7d0bad7`）**：解析逻辑抽出包内可覆写钩子 `resolveAllByName`——本机/内网 DNS 存在 NXDOMAIN 劫持（`.invalid` 域名也可能返回地址，呼应 Difficulty-log 中"运营商劫持"记录），"解析失败被拒"用例改为注入确定性失败解析器。同时删除断言 `0177.0.0.1` 必须映射环回的用例——该写法的解析结果随 JDK 版本语义变化，但 Java 校验与连接使用同一 `getByName` 结果，语义自洽，无绕过。

## 三、模块二：Redis 黑名单 fail-closed 语义显式化（commit `641d63e`）

- **现状缺陷**：过滤器直接调 `RedisTokenBlacklist.isRevoked`，Redis 故障抛 `DataAccessException` 落入既有数据库异常分支 → 误导性的数据库 500；logout 写黑名单失败同样裸抛。
- **语义（决策一）**：`susumonitor.security.token-blacklist-on-error: fail_closed（默认）| fail_open`。
  - fail_closed：过滤器返回 **503/50302**（`SecurityErrorHandler.writeTokenBlacklistUnavailable`，复用既有 `REDIS_UNAVAILABLE`，不与 DB 错误混同）；logout 抛 `BusinessException(REDIS_UNAVAILABLE)`，客户端应重试（否则 Token 未被吊销）。
  - fail_open：记 warn 放行（登出 Token 在 Redis 故障窗口内可能复活至自然过期，契约已标注）。
- **实现**：过滤器 `checkBlacklist` 将 Redis 故障包装为私有 `TokenBlacklistUnavailableException`，catch 顺序：专用异常 → JwtException/BadCredentials → DataAccessException（DB 分支行为不变）→ RuntimeException。黑名单 Bean 经 `ObjectProvider` 注入 `AppProperties`（`WebMvcTest` 切片上下文无该 Bean，惰性解析缺席时按 fail_closed 兜底——首跑曾致 58 个切片用例上下文加载失败，已修正）。
- **决策二留痕**：`RedisTokenBlacklist` javadoc 与 `openapi-auth.json` logout 描述均标注"Redis 未启用时登出为无状态空操作"为已接受的单实例语义；logout 契约新增 503 响应（openapi-auth.json 0.1.0 → 0.2.0）。
- **测试**：过滤器 fail_closed 503/fail_open 放行/命中黑名单 401 回归；`AuthControllerRevokePolicyTests`（直构控制器，两策略）；`AuthControllerTests` 集成 fail_closed 503。

## 四、模块三：SSH TOCTOU 复核（commit `73a5dbb`）

- **复核结论（生产代码零改动）**：复查日志所指"校验与连接两次解析"在现网代码已闭合——全库 SSHJ 出站仅 `SshConnectionTester` 一处（终端经 `TerminalAgentRelayService` 走 Go Agent 中继，无 Java 直连 SSH）；`connect()` 首行 `outboundPolicy.resolveAndValidate(host, port)` 单次解析并逐地址校验（端口白名单 → 解析数上限 → anyLocal/multicast/linkLocal/云 metadata 拒绝 → 必须落入显式 CIDR），随后对校验后的 `InetAddress` 调用 `sshClient.connect(address, port)`，连接阶段不二次解析。
- **防御性回归新增**（`SshOutboundPolicyTests` 9 用例）：默认空 CIDR deny-all；`localhost` 域名在 `0.0.0.0/0` 宽放下因环回语义被拒（特殊地址校验与 CIDR 判定独立生效）；链路本地/组播/未指定地址宽放下仍拒；IPv6 云 metadata 在 `::/0` 下仍拒。既有用例：白名单端口+CIDR 放行、非白名单端口拒、CIDR 外拒、metadata 拒、CIDR 配置禁止主机名。

## 五、模块四 a：SSH 凭据驻留面收敛（commit `7d0bad7`）

- **新 API**：`CredentialCipher.decryptToCharArray(serverId, credentialType, envelope)`——GCM 解密后经 `UTF_8.decode` 直出 char[]，返回前 `Arrays.fill` 清零明文字节缓冲，全程不创建 String。
- **落点**：`ServerSshServiceImpl.testConnection` 密码与私钥口令两处 supplier 由 `decrypt(...).toCharArray()`（先产生中间 String 再拷贝）改为 `decryptToCharArray(...)`；测试同步断言密码路径不触发 String 版 `decrypt`。
- **已知残留（记录在案）**：私钥本体受 SSHJ `loadKeys(String, …)` API 限制仍以 String 解密，无法 zero-fill；AI 个人 API Key 因 Spring AI `OpenAiApi.apiKey(String)` 同理。二者为第三方 API 边界约束，待上游提供 char[] 重载后再收敛。

## 六、模块四 b：Agent Token 轮换宽限期（commit `7469d95`）

- **迁移** `V35__servers_agent_token_grace.sql`：`servers` 增列 `agent_token_hash_prev VARCHAR(64) NULL`（旧 Token SHA-256 摘要）与 `agent_token_grace_until DATETIME NULL`（宽限截止，UTC），逐列 COMMENT，未改动 V1–V34。
- **轮换链路**：`AgentTokenServiceImpl.rotate` 在既有 UPDATE 中将当前摘要移入 prev 列并写 `grace_until = now + susumonitor.agent.token-grace-seconds`（默认 300s，0–86400 可配；0 即轮换立即失效）；`revoke` 同时清空 prev/grace 两列。
- **认证链路**：`AgentAuthenticationServiceImpl.authenticate` 先匹配当前哈希；未命中且 `now(UTC) < grace_until` 时匹配 prev（命中记 info 留痕），否则 401。`agent_token_revoked_at` 非空在上游统一拦截——撤销后旧 Token 即使在窗口内也立即失效。
- **契约**：API 出入参形状不变；`openapi-server.json` rotate 描述补充宽限语义并升版。
- **测试**：rotate 登记 300s 宽限窗口（captor 断言）与 0s 立即失效；认证侧当前 Token 优先/窗口内旧 Token 放行/窗口过期拒/撤销后立即拒/未知 Token 拒 5 用例（测试桩使用与生产一致的 `sha256:` 真实摘要，避免 HexFormat 解析异常）。
