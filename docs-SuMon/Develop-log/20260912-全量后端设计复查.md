## 三、甄别为不成立的指控（防误改记录）

1. "AI 命令建议无数量上限，可批量自动执行"——不成立：`OpenAiCompatibleProvider.parseSuggestions` 强制 1-3 条，超限即 50305。
2. "告警通知 RestTemplate 无超时"——不成立：`AsyncConfig.restTemplate` 已按 `notification-http-*-timeout-ms`（默认 5s/10s）配置。
3. "CommandTemplateRegistry 正则 ReDoS"——不成立：参数正则为定长单字符集，O(N)。
4. "Outbox 发布在单实例会重复"——不成立：@Scheduled fixedDelay 单线程不重叠，重复仅在多实例出现（已列入多实例记录项）。

## 四、正面确认（复查中核实的设计优点）

- AES-GCM 随机 IV + 32 字节密钥校验；JWT 强制 HS256 防算法混淆、密钥 ≥32 字节启动校验
- ClientIpResolver 可信代理右到左遍历，XFF 伪造无法绕过限流
- Redis 限流 Lua 脚本 INCR+EXPIRE 原子；MonitorTicket 两实现均严格一次性
- GlobalExceptionHandler 不泄漏堆栈/SQL/入参；AppProperties @Validated 启动期强制校验
- Agent WebSocket 未认证连接 5s 清扫、消息双桶限流；终端双向限流与会话绑定
- Outbox 与告警记录同事务登记（"已入库告警必有待发布事件"），AI 解释/命令域消费链路幂等与 DLQ 语义完整
