# 2026-08-03 Agent 指标可靠投递（ACK 确认与离线缓冲）开发记录

## 完成内容

### M1：Server 入口确认

- 提交：`773fc4d feat(server): acknowledge agent metric delivery`
- `metrics.report` 在 `MetricsService.report(...)` 成功返回后回传 `metrics.ack`。
- ACK 使用原请求 `message_id`，payload 返回 `server_id`、`collected_at`。
- 失败路径只返回既有 `error`，不会误发 ACK；重复 ID 的既有入口幂等逻辑无需新增 migration。
- WebSocket 协议更新至 v1.2，明确 ACK 不代表 RabbitMQ、Monitor 推送或告警消费完成。

### M2：Agent 有界持久化 FIFO

- 提交：`7db29b6 feat(agent): buffer metrics until acknowledged`
- 新增 `internal/metricbuffer`：完整 `metrics.report` 外层帧以 JSON snapshot 原子写入；每次变更使用临时文件、`Sync`、rename。
- Reporter 先入队、后发送；只允许一个 in-flight 指标，只有匹配队首 ID 的 `metrics.ack` 才持久化删除并发送下一条。
- 断线或 ACK 丢失后，认证完成回调会用原 UUID 重放队首，服务端入口幂等处理重复上报。
- 新增 `SUSUMONITOR_METRICS_BUFFER_PATH` 与 `SUSUMONITOR_METRICS_BUFFER_MAX_ENTRIES`，安装脚本创建受限目录。
- 队列满时拒绝最新采样、保留现存 FIFO；损坏/不匹配 spool 启动失败，避免静默数据损失。

## 已知边界与后续

- 本次没有在真实隔离环境连接 M1 Server，不能宣称断网/重启联合 E2E 已完成。
- 当前 Server 没有 `metrics.nack`；非认证失效的普通 `error` 不会删除队首，保持安全但可能阻塞后续样本，后续需定义可重试/不可重试错误策略。
- 当前未实现队列字节上限、ACK 超时主动重发、恢复期节流及管理端积压展示；这些应拆为后续独立模块。
- 发布顺序必须先 Server M1，再部署 Agent M2；不能将 M2 Agent 连接到不支持 `metrics.ack` 的旧 Server。
