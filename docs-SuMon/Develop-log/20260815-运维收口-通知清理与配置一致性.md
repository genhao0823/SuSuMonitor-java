## 三、实现细节与参数传递

### A 模块（对称 `AlertRecordCleanup` 三件套）

- **V27**：`ALTER TABLE alert_notifications ADD INDEX idx_created_at (created_at);`
- **AppProperties.Alert** 5 字段：`notificationCleanupEnabled=true` / `notificationRetentionDays=90`（@Min 1 @Max 3650）/ `notificationCleanupCron="0 0 3 * * ?"`（@NotBlank）/ `notificationCleanupBatchSize=1000` / `notificationCleanupMaxBatchesPerRun=100`——yml 以 `ALERT_NOTIFICATION_*` 环境变量可配
- **Mapper**：`deleteExpiredBatch(cutoffTime, batchSize)`，XML 用 `WHERE id IN (SELECT id FROM ... WHERE created_at < #{cutoffTime} ORDER BY id LIMIT #{batchSize})` 子查询风格（与 `AlertRecordCleanupMapper.xml` 完全一致）
- **Service**：`cleanupExpiredNotifications()`（cutoff = now(UTC) − 保留天数）+ `(LocalDateTime cutoffTime)`（供边界验证）；`AtomicBoolean` 防重叠 → `TransactionTemplate` 每批独立事务 → `CleanupResult(cutoffTime, batchCount, deletedRows, durationMs)`
- **Scheduler**：`@Scheduled(cron = "${susumonitor.alert.notification-cleanup-cron}")` + `@ConditionalOnProperty`，`ifPresentOrElse` 日志、异常只影响当前轮

### B 模块

- `application.yml` `outbox-cleanup-enabled: ${OUTBOX_CLEANUP_ENABLED:true}`；`AppProperties.outboxCleanupEnabled = true`（两处默认一致）
- `OutboxPublisherScheduler` `@Scheduled(fixedDelayString = "${susumonitor.rabbitmq.poll-interval-ms:200}")`

### 测试上下文连带影响（B1 触发）

`OutboxCleanupServiceImpl`/`AlertNotificationCleanupServiceImpl` 默认 enabled=true 后，在排除 DataSource 自动配置的 controller 测试上下文中会被创建，其 Mapper 依赖触发真实 MyBatis 会话工厂加载失败——9 个 `@SpringBootTest` 类（`SuSuMonitorServerApplicationTests`、4 个 controller 测试组等）补 `@MockitoBean`：`AlertNotificationCleanupMapper` + `OutboxCleanupMapper`（与既有 `@MockitoBean` 清理 Mapper 模式一致）。
