## 一、背景与目标

MVP-11 收口后（386 tests 全绿，提交 `e7f713f`），两项"已声明未落地"的能力补齐：

1. **`ConsumeRecordMapper.markFailed` 名存实亡**：枚举注释声明 `failed=重试耗尽后的失败留痕`，但该方法是 `UPDATE ... WHERE id=?`，而失败路径从不插入行——永远更新不到任何行；且 `existsConsumed` 命中**所有**行（含 failed），一旦有 failed 行，DLQ 重放依赖幂等跳过会把失败消息**永久跳过**，与"重放用于处置"语义冲突。
2. **告警无逃逸窗口**：`AlertStateMachine` 单快照判定——首次越界立即 Trigger、恢复立即 Resolve，对瞬时抖动会误报。

## 二、消费失败留痕落地

### 设计决策

- `existsConsumed` 改为**仅认 `status='consumed'`**：failed 行不阻塞 DLQ 重放重试。
- 成功路径 `insert` → **upsert**（`ON DUPLICATE KEY UPDATE`）：failed 行可被翻转回 consumed，完成 `failed→consumed` 完整生命周期（重放成功场景）。
- `markFailed(by id)` → **`upsertFailed(consumer, eventId, attempts, lastError)`**：按唯一键 upsert，补全失败留痕语义。
- 新增 `FailedConsumeRecordRecoverer` + `AlertRabbitConfig` 注入：容器重试耗尽 / 不可重试拒绝时，在 reject 进 DLQ **之前**尽力写 failed 行。
  - 可解析出 event_id 才留痕；非法 JSON 无法定位事件仅告警日志。
  - `attempts`：不可重试（`AmqpRejectAndDontRequeueException` 链）记录 1；重试耗尽记录 `max-attempts`。
  - `last_error` 截断 500 字符（对齐 V15 列定义），best-effort：DB 异常不阻断 reject。

## 三、告警逃逸窗口

### 设计决策

- **V18 迁移**：`alert_rules.confirm_count INT NOT NULL DEFAULT 1`（规则级连续越界确认次数）+ `alert_states.breach_count INT NOT NULL DEFAULT 0`（当前累计计数）。默认 1 = 首次越界立即触发，**向后兼容**现行为。
- `AlertStateMachine` 新增三种决策（sealed interface 强制 exhaustive switch 编译期覆盖）：
  - `CountingStart`：首次越界且 confirm_count>1 → 创建 `active=false, breach_count=1` 计数行，不触发
  - `CountingProgress`：持续越界未达阈值 → `breach_count+1`
  - 达阈值（`breach_count+1 == confirm_count`）→ Trigger（计数行升级 active + 建 record + 发事件）
  - `CountingReset`：计数状态行 + 恢复 → 删除计数行（连续越界中断清零）
- `AlertStateMapper` 新增 `incrementBreachCount` / `activateOnBreachThreshold`；`AlertEvaluationServiceImpl` 新增三个 handler。
- **契约同步**：`openapi-alert.json` 三个 schema（AlertRule/CreateAlertRuleRequest/UpdateAlertRuleRequest）注入 `confirm_count`；前端 `api.d.ts` 类型同步（可选字段，前端逻辑零改动）。
- 一个语义澄清：原 `noBreachWithResolvedStateShouldReturnNoAction` 测试中 `active=false` 的"resolved state"在新模型下即计数状态行，不再越界 → 正确返回 `CountingReset`，测试已同步更新。

### 变更文件

- V18 迁移；`AlertRuleEntity`/`AlertStateEntity`/`CreateAlertRuleRequest`/`UpdateAlertRuleRequest`/`AlertRuleVo`
- `AlertStateMachine`/`AlertTransition`/`AlertEvaluationServiceImpl`/`AlertRuleServiceImpl`/两个 Mapper 接口与 XML
- 测试：`AlertStateMachineTests` +4 / `AlertEvaluationServiceTests` +4；两个 Mapper MyBatis 测试 H2 DDL 补列
- `openapi-alert.json` + 前端 `api.d.ts`
