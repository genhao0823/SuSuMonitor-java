### 内置浏览器联调补充（2026-09-09 晚）

以 `VITE_API_PROXY_TARGET=https://genhaosan.online npm run dev` 连接部署后端实测，发现并修复两个问题：

1. **登录后跳 403**：浏览器同源 POST 携带 `Origin: http://127.0.0.1:5173`，
   部署后端 CORS 白名单不含本地开发源，Spring CorsFilter 在业务层之前直接 403，
   触发前端全局 403 处理重定向 `/forbidden`。修复：`vite.config.ts` dev 代理对
   `/api`、`/ws` 剥离 `Origin` 头（`proxyReq.removeHeader`），仅影响本地开发；
   同时补上 `/ws` 的 `ws: true` 代理（此前本地 dev 下 WebSocket 无法经代理转发）。
2. **解释弹窗错误态混淆**：后端异常时弹窗误显示"暂无 AI 解释"空态。
   修复：`AiAlertExplanationDialog` 增加"解释加载失败"错误态（el-result + 重试按钮），
   与 404 空态严格区分；对应组件测试同步更新（27 文件 159 用例全绿）。

浏览器实测结论：登录、AI 问答页（提问/错误降级）、AI 命令域页（双 Tab/筛选/空态）、
服务器详情 AI 诊断弹窗、告警记录 AI 解释弹窗，前端链路与降级表现全部正常。

**遗留（部署端）**：该实例所有 `/api/ai/*` 接口（含不依赖 LLM 的 templates/runs/explanation）
一律返回 50000，而非 AI 接口正常——需要登录服务器查看后端日志定位 AI 模块问题
（疑似 AI 配置不完整或部署版本与 DB 迁移不一致）。服务端修复前，LLM 真实调用无法端到端验证。
