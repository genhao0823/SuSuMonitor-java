## 一、缺陷描述

**心跳超时路径（90s 无心跳）下，Agent 的终端会话整体不收口**：浏览器收不到 `terminal.closed`、Agent 侧 PTY 不关闭、DB `terminal_sessions` 残留 `OPEN` 并计入配额，仅靠每小时清理兜底。

证据链（修复前）：

```java
// AgentHeartbeatServiceImpl.markExpiredSessionsOffline（每 30s 扫描）
connectionRegistry.remove(session);                        // ← 先从注册表删除
session.socketSession().close(SESSION_NOT_RELIABLE);       // ← 再关 socket
// → afterConnectionClosed → closeAgentSessions：
if (!agentRegistry.isCurrent(agentSession)) return;        // ← 注册表已删，恒 false，直接跳过
```

正常 kill/网络断开路径无此问题（注册表未先删，`isCurrent=true`）。

## 三、修复语义

```java
// 扫描到心跳超时会话时（注册表仍指向该会话）：
terminalRelayLifecycleService.closeAgentSessions(session);  // isCurrent=true → 推 closed 帧 + 收口元数据 + 清路由 + 释放令牌桶
serverMapper.markAgentOffline(...);                          // DB 离线标记（原逻辑）
connectionRegistry.remove(session);                          // 之后才移除注册表
session.socketSession().close(SESSION_NOT_RELIABLE);         // 关 socket → afterConnectionClosed 幂等（绑定已清空）
```

- **幂等性**：`closeAgentSessions` 二次进入时 `removeByServerId` 返回空集，无副作用
- **顶号竞态**：`registry.remove` 用 `serverSessions.remove(serverId, sessionId)` 条件删除，不误删新连接索引
- **浏览器侧**：与 kill 路径一致收到 `terminal.closed`（`reason=agent_disconnected`），Web 显示 `[closed] agent_disconnected`，Android 触发自动重连
