## 一、改动内容摘要（`509a193`）

### B2-1 登录失败单提示（根因比计划盘点更深一层）

- 根因确认：`src/api/client.ts` 响应拦截器 `handleBusinessError` 对非 silent 请求弹窗一次，`LoginView.vue` catch 分支再弹一次——一次失败两条提示。
- **补充发现**：错误密码（HTTP 401→40100）会触发 `onUnauthorized` 回调清空本地态；待审核账户登录（HTTP 403→40300，后端 `UserServiceImpl` 对非 approved 明确抛 `FORBIDDEN`）会触发 `onForbidden` 把用户从登录页推向 `/forbidden`——登录尝试失败被误判为"会话失效/权限不足"。
- 修法（决策留痕）：不改变 `silent` 既有语义（"跳弹窗、回调仍触发"被既有调用方依赖），新增独立 `authAttempt` 配置位——标记"认证尝试"类请求，40100/40300 表示本次尝试被拒而非登录态变化，拦截器跳过全局回调；`loginUser` 请求携带 `{ silent: true, authAttempt: true }`，弹窗与文案由 LoginView `explainLoginError` 统一处理。`LoginView.vue` 本身零改动。

### B2-2 路由守卫判定顺序

- 根因：`src/router/guards.ts` 先判 `requiresAdmin` 再判 `requiresAuth`，未登录用户 `isAdmin=false` 直接落 `/forbidden`，丢失带 `redirect` 的登录入口。
- 修法：判定顺序改为**认证 → 角色 → publicOnly**，与 `main.ts` `enforceInitialAuth` 对齐；文件头流程图与分支注释同步更新。

### 测试

- 新增 `src/api/auth.spec.ts`（4 例）：锁定 `loginUser` 携带 `silent+authAttempt` 的配置形态（B2-1 回归防线），顺带补齐 register/me/logout 的 URL/Method 断言。
- 新增 `src/api/client.spec.ts`（4 例）：伪 adapter 注入 401/403 响应，验证 authAttempt 请求不触发回调、silent 只影响弹窗、普通请求回调语义不回归。
- 新增 `src/router/guards.spec.ts`（6 例）：认证/角色/publicOnly 六态矩阵，含"未登录访问 requiresAdmin → login redirect"修复点断言。
- 新增 `src/views/LoginView.spec.ts`（3 例）：失败（40001/40300）各仅一条提示且不跳转、成功跳 `/dashboard`。
