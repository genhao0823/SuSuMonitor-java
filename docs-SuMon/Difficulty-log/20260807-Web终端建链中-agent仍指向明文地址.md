# 2026-08-07 Web 终端"建链中"-agent 仍指向明文旧地址(HTTPS 迁移遗漏)

**日期**: 2026-08-07
**操作人**: opencode / 用户
**关联**: HTTPS/WSS 迁移完成后的遗留问题;Web 终端 `https://genhaosan.online/terminal/4` 一直显示"建链中"

## 一、现象

HTTPS 迁移(域名 genhaosan.online + 证书 + nginx 443 + 前端 `wss://` 自适应)完成后:
- 登录、dashboard、指标订阅等**普通功能正常**
- 但 Web 终端 `/terminal/4` 页面右上角**一直显示"建链中"**,终端黑框无任何输出
- Android/Web 其它 WS 功能正常(alert.push、metrics.update 正常推送)

## 二、排查过程

### 1. 确认连接层正常(排除 nginx/WSS/证书)
- `POST /api/ws/monitor-ticket` 取 ticket ✓
- 公网 `wss://genhaosan.online/ws/monitor?ticket=...` 握手返回 `HTTP 101` ✓
- 前端部署包检查:`websocket-BtswdTmu.js` 中 URL 构造为
  `window.location.protocol==="https:"?"wss:":"ws:"` + `window.location.host` ✓
  —— 前端代码没有残留 `ws://82.156.245.102` 硬编码

### 2. 写脚本模拟浏览器全链路(api-test/verify-terminal-ws.py)
- 登录 → 取 ticket → 连 WSS → 发 `metrics.subscribe` + `terminal.open` → 等 `terminal.opened`
- 第一次跑:收到 `error 40003 terminal invalid payload` —— 是**脚本自己** message_id 生成不合
  UUID 格式(无连字符),后端 `TerminalProtocolValidator.isUuid` 用 `UUID.fromString` 校验,**必须带连字符**;
  修正为标准 UUID v4 后通过
- 第二次跑:**`error 40904 terminal agent offline`**

### 3. 定位到 agent 不在线
- 后端 `TerminalMonitorRelayService.relay()` → `agentRegistry.sendToServer(serverId)` 返回
  false → `TERMINAL_AGENT_OFFLINE(40904)`。即:**目标服务器 wsl111(server_id=4)的 agent
  没有和后端保持 /ws/agent 长连接**
- 状态接口显示 `agent_status: online`,但 `last_heartbeat_at` 停在 17:55:23(正好是后端重启时刻),
  重启后再无心跳——agent 没有重连成功

### 4. 本机 WSL 查 agent(铁证)
wsl111 的 agent 跑在本机 WSL 的 systemd 服务 `susumonitor-agent` 里,配置在
`/etc/susumonitor/agent.env`(`EnvironmentFile`),日志在 `/var/log/susumonitor/agent.log`:

```
{"level":"WARN","msg":"connect or authenticate failed, reconnecting",
 "error":"dial ws://82.156.245.102/ws/agent: failed to WebSocket dial:
          expected handshake response status code 101 but got 404","backoff":60000000000}
```

**agent.env 里的 `SUSUMONITOR_BACKEND_URL` 仍是 `ws://82.156.245.102`**(明文 + 旧 IP)。

## 三、根因

**HTTPS 迁移遗漏了 agent 的连后端地址**:

1. HTTPS 迁移把 nginx 改成了 genhaosan.online 443(SSL),80 端口 server_name 只写了
   `genhaosan.online www.genhaosan.online`
2. 但 WSL agent 的 `SUSUMONITOR_BACKEND_URL=ws://82.156.245.102` 没同步更新:
   - 明文 `ws://`,被运营商/中间层可劫持
   - Host 头是 IP `82.156.245.102`,nginx 没有匹配的 server_name,落到**默认站点** → 404
     (所以报 404 而不是 301)
3. agent 永远握手失败 → 重试(backoff 60s)→ 无法上报心跳/指标
   ("agent is not authenticated")→ 后端 agent 判定 offline
4. 浏览器 terminal.open 请求后端转发到不存在的 agent 会话 → `40904 agent offline`

**注意**:这个问题的直接表现是"建链中"(terminal.open 未得到 opened),而不是 WebSocket 连接失败
(握手 101 是正常的)——**连接层没有问题,问题在 agent 这一层**。

## 四、修复

1. 改 WSL 里 agent 配置 `/etc/susumonitor/agent.env`:
   ```
   SUSUMONITOR_BACKEND_URL=ws://82.156.245.102
   SUSUMONITOR_BACKEND_URL=wss://genhaosan.online
   ```
2. 重启 agent:
   ```
   systemctl restart susumonitor-agent
   ```
3. 验证 agent 日志:
   ```
   {"level":"INFO","msg":"susumonitor agent starting","backend_url":"wss://genhaosan.online",...}
   {"level":"INFO","msg":"agent authenticated","server_id":4}
   ```

## 六、教训

1. **HTTPS 迁移要全量审计"连到服务器的客户端"**:除了浏览器前端(js 里的 URL),还有
   agent(Go 客户端)、Android App(Constants.kt 的 BASE_URL/WS_URL)、通知 webhook 等
   所有指向服务器的地址都要一起切。这次只改了前端和 Android,漏了 agent。
2. **"连接层 101 正常"不代表终端链路正常**:Web 终端是 浏览器→/ws/monitor→后端→agent→PTY
   两级转发,浏览器那级通了,还有后端→agent 这一级。遇到"建链中"先查 agent 是否在线
   (状态接口 last_heartbeat_at 是否新鲜),别只看浏览器 WS 握手。
3. **agent 用 IP 做 Host 头会落到 nginx 默认站点**:nginx 按 server_name 分流,IP 直连时
   不匹配任何站点配置,行为(404/403/默认页)不可预期。agent 配置必须用域名。
4. **agent 报 404 而非 301**:80 端口 server 块有 `return 301`,但 agent 的 Host 是 IP,
   命中的是默认站点而不是该 server 块,所以是 404。看日志别被"应该是 301"带偏。
