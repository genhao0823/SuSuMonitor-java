## 一、计划目标

### 1.1 总目标

在 Java 后端 WebSocket Agent 通道（`/ws/agent`）、Agent Token 生命周期、Metrics 接收/存储/查询/实时推送链路均已实现的基础上，开发正式 Go 跨平台监控采集 Agent，完成以下闭环：

```text
Go Agent 启动
→ 读取配置
→ 连接 ws://<backend>/ws/agent
→ 首帧 agent.authenticate（server_id + agent_token）
→ 收到 agent.authenticated
→ 每 5 秒采集系统指标 + metrics.report
→ 每 30 秒 heartbeat
→ 断线指数退避重连
→ 后端写入 MySQL metrics 表
→ REST /metrics/latest 与 /metrics 返回真实指标
→ Monitor WebSocket 广播 metrics.update
```

### 1.2 本计划包含

- Go Agent 工程骨架（`agent-go-SuMon/`）。
- 配置加载与校验。
- WebSocket 连接、首帧鉴权、心跳、指标上报。
- 指数退避重连。
- 跨平台系统指标采集（CPU、内存、磁盘、网络）。
- Windows 本机直接运行验证。
- 单元测试与极简链路冒烟测试。

### 1.3 本计划不包含

- Linux systemd service、安装脚本、一键部署（属阶段 4 后续）。
- 温度采集在 Windows 上的强制实现（Windows 多数机器无传感器，置 null）。
- load_avg 在 Windows 上的强制实现（Windows 无 loadavg 概念，置 null）。
- 前端 MetricsView 挂路由与 WebSocket 鉴权修复（属 MVP-3 前端收口）。
- AI 分析、AI 运维、Android 客户端（属 MVP-8 之后增强）。
- Docker、Kubernetes、远程 Linux 生产部署。

## 二、当前基线与事实

### 2.1 后端已实现能力

执行本计划前，Java 后端已实现以下能力，Go Agent 直接对接：

- WebSocket 路径 `/ws/agent`（`AgentWebSocketConfig.java:25`）。
- 首帧鉴权 `agent.authenticate`，payload 含 `server_id` 和 `token`（`AgentWebSocketHandler.java:72,105-117`）。
- 鉴权成功返回 `agent.authenticated`（`AgentMessageType.java:8`）。
- 心跳 `heartbeat` / `heartbeat.ack`（`AgentMessageType.java:9-10`）。
- 指标上报 `metrics.report`，payload 为固定宽表快照（`AgentWebSocketHandler.java:78-81`）。
- 首帧认证超时 10 秒，超时关闭连接（`AgentWebSocketHandler.java:120-130`）。
- 90 秒无心跳标记离线（`AgentHeartbeatService.java:16,37-53`）。
- 新连接替换旧连接（`AgentConnectionRegistry.java:21-28`）。
- 消息字段 `message_id`、`timestamp`（UTC ISO-8601）（`AgentMessage.java`、`AgentWebSocketHandler.java:137-138`）。
- 消息大小上限 64 KiB（`AgentWebSocketHandler.java:30`）。
- Agent Token 通过 REST `POST /api/servers/{id}/agent/register` 由 admin 预发放，明文仅一次性返回（`AgentTokenService.java:39-43,89`）。
- Metrics 写入后发 `MetricsReportedEvent`，事务提交后广播 `metrics.update`（`MetricsService.java:49`、`MonitorMetricsPublisher.java:28-40`）。

### 5.2 优先级

环境变量 > 配置文件 > 默认值。

### 5.3 敏感信息处理

- `agent_token` 优先从环境变量 `SUSUMONITOR_AGENT_TOKEN` 读取。
- 本机测试可从配置文件读，但配置文件必须加入 `.gitignore`。
- 日志中不得输出 `agent_token` 明文；只输出前 8 字符用于排障。
- 日志中不得输出完整 `agent_token`、密钥或完整 WebSocket URL（含 token 参数）。

### 5.4 配置校验

启动时校验：

- `backend_url` 非空，且以 `ws://` 或 `wss://` 开头。
- `server_id` 为正整数。
- `agent_token` 非空。
- `collect_interval_seconds` >= 1。
- `heartbeat_interval_seconds` >= 1。
- `reconnect_initial_seconds` >= 1。
- `reconnect_max_seconds` >= `reconnect_initial_seconds`。

非法配置启动失败，不退化为默认值。

## 六、WebSocket 连接与状态机

### 6.1 状态定义

```text
Disconnected → Connecting → Authenticating → Connected → Reconnecting
```

| 状态 | 说明 |
|------|------|
| Disconnected | 初始状态或关闭后 |
| Connecting | WebSocket 握手中 |
| Authenticating | 已发 agent.authenticate，等待 agent.authenticated |
| Connected | 鉴权成功，可发 heartbeat 和 metrics.report |
| Reconnecting | 连接断开，指数退避等待重连 |

### 6.2 首帧鉴权流程

1. 连接 `ws://<backend_url>/ws/agent`。
2. 构造 `agent.authenticate` 消息：

```json
{
  "type": "agent.authenticate",
  "message_id": "<UUID>",
  "timestamp": "<UTC ISO-8601>",
  "payload": {
    "server_id": <配置的 server_id>,
    "token": "<配置的 agent_token>"
  }
}
```

3. 发送首帧，启动 10 秒超时。
4. 收到 `agent.authenticated` → 进入 Connected 状态。
5. 10 秒内未收到响应 → 关闭连接，进入 Reconnecting。
6. 收到 `error` 或被关闭 → 进入 Reconnecting。

### 6.3 心跳

Connected 状态下每 `heartbeat_interval_seconds`（默认 30 秒）发送：

```json
{
  "type": "heartbeat",
  "message_id": "<UUID>",
  "timestamp": "<UTC ISO-8601>",
  "payload": {}
}
```

等待 `heartbeat.ack`。未收到 ack 不阻塞采集，只记日志。

### 6.4 指标上报

Connected 状态下每 `collect_interval_seconds`（默认 5 秒）采集并上报：

```json
{
  "type": "metrics.report",
  "message_id": "<UUID>",
  "timestamp": "<UTC ISO-8601>",
  "payload": {
    "server_id": <id>,
    "collected_at": "<UTC ISO-8601>",
    "cpu_percent": <0-100>,
    "memory_percent": <0-100>,
    "memory_used": <bytes>,
    "memory_total": <bytes>,
    "disk_percent": <0-100>,
    "disk_used": <bytes>,
    "disk_total": <bytes>,
    "net_rx": <累计字节>,
    "net_tx": <累计字节>,
    "temperature": null,
    "load_avg": null
  }
}
```

### 6.5 重连

连接断开后：

1. 进入 Reconnecting。
2. 等待 `reconnect_initial_seconds`（默认 5 秒）。
3. 尝试重连。
4. 失败则等待时间翻倍，上限 `reconnect_max_seconds`（默认 60 秒）。
5. 成功后重置等待时间为初始值。

### 6.6 优雅关闭

收到 `SIGINT` 或 `SIGTERM`：

1. 停止采集和心跳 ticker。
2. 发送 WebSocket Close 帧。
3. 等待 5 秒强制退出。

## 七、系统指标采集策略

### 7.1 采集库

统一使用 `github.com/shirou/gopsutil/v3`，跨平台支持 Linux/Windows/macOS。

### 7.2 各指标采集方式

| 指标 | gopsutil 调用 | 说明 |
|------|--------------|------|
| cpu_percent | `cpu.Percent(time.Second, false)` | 采样 1 秒，返回使用率 |
| memory_percent | `mem.VirtualMemory()` 取 `UsedPercent` | 已用/总 |
| memory_used | `mem.VirtualMemory()` 取 `Used` | 字节 |
| memory_total | `mem.VirtualMemory()` 取 `Total` | 字节 |
| disk_percent | `disk.Usage("/")` 取 `UsedPercent` | 系统盘；Linux 用 `/`，Windows 用 `C:` |
| disk_used | `disk.Usage(mount)` 取 `Used` | 字节 |
| disk_total | `disk.Usage(mount)` 取 `Total` | 字节 |
| net_rx | `net.IOCounters(false)` 取 `BytesRecv` | 累计字节，非速率 |
| net_tx | `net.IOCounters(false)` 取 `BytesSent` | 累计字节，非速率 |
| temperature | `host.SensorsTemperatures()` | Windows 多数无传感器 → null |
| load_avg | `load.Avg()` 取 `Load1` | Windows 无 loadavg → null |

### 7.3 net_rx/net_tx 语义

上报**累计字节数**（从操作系统启动开始计），不是速率。后端存储累计值，查询时由前端或查询接口计算增量。

### 7.4 磁盘挂载点

- Linux：`/`
- Windows：`C:`

通过 `disk.Partitions(false)` 获取第一个物理分区，或配置指定。

### 7.5 temperature 和 load_avg 的 null 处理

- Windows 上 `host.SensorsTemperatures()` 通常返回空或错误 → payload 中 `temperature` 设为 `null`。
- Windows 上 `load.Avg()` 通常返回错误 → payload 中 `load_avg` 设为 `null`。
- 后端 `MetricsService.validatePayload` 对 null 跳过校验（`MetricsService.java:110-120`），允许 null。

### 7.6 精度

- 百分比：保留 2 位小数（如 `35.23`）。
- 字节数：整数。
- Go 用 `float64`，JSON 序列化时 `encoding/json` 自动处理。
- 后端用 `BigDecimal` 接收，不丢失精度。

## 八、时间与 JSON 规范

| 项 | 规范 |
|----|------|
| 时间格式 | UTC ISO-8601 字符串，如 `2026-07-21T12:00:00Z` |
| message_id | UUID v4（`crypto/rand` 或 `google/uuid`，优先用标准库） |
| JSON 字段名 | snake_case（`server_id`、`cpu_percent` 等） |
| timestamp | UTC ISO-8601 |
| collected_at | UTC ISO-8601 |
| 消息大小 | 不超过 64 KiB |

Go 结构体用 `json` tag 控制字段名：

```go
type MetricsPayload struct {
    ServerID       int64    `json:"server_id"`
    CollectedAt    string   `json:"collected_at"`
    CPUPercent     *float64 `json:"cpu_percent"`
    MemoryPercent  *float64 `json:"memory_percent"`
    MemoryUsed     *uint64  `json:"memory_used"`
    MemoryTotal    *uint64  `json:"memory_total"`
    DiskPercent    *float64 `json:"disk_percent"`
    DiskUsed       *uint64  `json:"disk_used"`
    DiskTotal      *uint64  `json:"disk_total"`
    NetRx          *uint64  `json:"net_rx"`
    NetTx          *uint64  `json:"net_tx"`
    Temperature    *float64 `json:"temperature"`
    LoadAvg        *float64 `json:"load_avg"`
}
```

用指针类型表示可空字段，`nil` 序列化为 `null`。

## 十、并发与背压

### 10.1 goroutine 模型

```text
main goroutine
├── wsclient goroutine    WebSocket 收发
├── collector ticker      每 5 秒采集
└── heartbeat ticker      每 30 秒心跳
```

### 10.2 背压策略

- 采集 ticker 和心跳 ticker 通过 channel 向 wsclient 发送消息。
- channel 容量为 1。
- 如果 channel 满（wsclient 阻塞），采集/心跳跳过当前批次，记日志。
- 不排队积压；优先保证最新指标。

### 10.3 context 取消

- 启动时创建根 `context.Context`。
- 收到信号后 `cancel()`，所有 goroutine 退出。
- wsclient 的 `context` 超时控制首帧认证和写操作。

## 十一、日志规范

### 11.1 日志库

标准库 `log/slog`，JSON handler。

### 11.2 日志级别

| 级别 | 用途 |
|------|------|
| INFO | 连接、鉴权、重连、关闭 |
| DEBUG | 指标摘要、心跳 ack |
| WARN | 背压跳过、采集失败 |
| ERROR | 鉴权失败、连接断开 |

### 11.3 日志脱敏

禁止输出：

- 完整 `agent_token`（只输出前 8 字符）
- 完整 WebSocket URL（如果含 token 参数）
- 密钥、密码、私钥

允许输出：

- `server_id`
- 连接状态
- 指标摘要（cpu_percent、memory_percent 数值）
- 重连次数和等待时间

## 十六、风险与处理

| 风险 | 处理 |
|------|------|
| gopsultil 在 Windows 上部分指标不可用 | temperature/load_avg 置 null，后端已支持 |
| WebSocket 连接不稳定 | 指数退避重连，不丢数据（跳过积压） |
| 首帧超时 10 秒 | Agent 设 10 秒超时，超时后重连 |
| 消息超过 64 KiB | metrics.report 单条固定宽表，不会超限 |
| agent_token 泄露 | 环境变量读取，日志脱敏，配置文件不入 Git |
