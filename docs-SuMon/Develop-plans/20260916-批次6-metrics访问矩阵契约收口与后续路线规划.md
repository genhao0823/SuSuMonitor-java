## 二、口径决策（本次已拍板）

1. **D1 访问矩阵意图：维持「任一认证用户可读」，修契约不收紧代码。** 依据四重：(a) 产品规范「普通 approved user 只允许查看服务器」，查看服务器天然含查看其指标与监控快照；(b) Web 前端监控页对非 admin 开放（路由层仅 `/admin/users` 有角色门槛）；(c) `MetricsControllerTests` 已存在非 admin（role=user, approved）成功 200 的既有断言；(d) 两个 Controller 的 `@Operation` description 本就写 "Authenticated users only"，仅 `@ApiResponses` 的 403 行是早期从 admin 端点复制的陈旧文案。反向选项（收紧 SecurityConfig 为 admin-only）会破坏既有非 admin 用户行为且无产品诉求支撑，否决。
2. **D2 契约版本 0.3.0 → 0.3.1（patch）。** 无端点增删、无结构变更、无字段变更，仅删除不可达的 403 响应声明——纯文档口径修正按 semver 记 patch。
3. **D3 访问矩阵用测试固化。** metrics 面 4 端点已有非 admin 200 用例；`monitor-ticket` 端点补 Controller 层 WebMvcTest（非 admin 200 + 未认证 401），防止将来误收紧或误改契约时无回归防线。
4. **D4 统计漂移一并收口。** 契约目录 README 与根 README 的路径/端点统计数字同步为真实值（49 路径 / 58 端点操作），并在收口日志中留痕。
5. **D5 不改 `openapi-auth.json` 登录端点的 403。** 该 403 为审核态业务拒绝（pending/rejected 用户登录），可达且正确，与本次「不可达 403」性质不同，不动。
6. **D6 Docker Desktop 未运行，隔离库 MySQL IT 复跑保持 B 级专项**，本批次不启动重型系统组件，仅在路线图中给出 runbook。
