## 二、N3：Agent 队列字节上限

### 背景
当前 metricbuffer 仅有条数上限（`SUSUMONITOR_METRICS_BUFFER_MAX_ENTRIES`，默认 720 条），无字节级保护。单条帧约 350–420 B，720 条约 300 KB，字节压力不大但缺防御性配置。`framesBytes()` 辅助函数已存在，只需接入增量计数。

### 备份目标
`C:\Backup\SuSuMonitor\<时间戳>-n3-queue-byte-cap\N3-before-change`

改动文件：
- `agent-go-SuMon/internal/config/config.go`
- `agent-go-SuMon/internal/config/config_test.go`
- `agent-go-SuMon/internal/metricbuffer/buffer.go`
- `agent-go-SuMon/internal/metricbuffer/buffer_test.go`
- `agent-go-SuMon/cmd/susumonitor-agent/main.go`
- `agent-go-SuMon/.env.example`
- `agent-go-SuMon/deploy/agent.env`（若存在）

### 代码细节

#### `internal/config/config.go`
- `Config` 结构体新增字段 `MetricsBufferMaxBytes int`（0 = 不限制）
- `Load()` 新增：`getenvIntDefault("SUSUMONITOR_METRICS_BUFFER_MAX_BYTES", 0)`
- `validate()` 新增：若非 0 且 < 1024 则报错

#### `internal/metricbuffer/buffer.go`
- `Queue` 结构体新增 `maxBytes int`、`currentBytes int`（增量计数，不再重复序列化）
- `Open(path, serverID, capacity, maxBytes int)` 签名新增参数；初始化时 `q.currentBytes = framesBytes(entries)`
- `Enqueue`：条数检查后追加字节检查，超限时 `drops++`，返回错误；持久化成功后 `q.currentBytes += frameSize(message)`
- `Acknowledge`/`RejectHead`：移除队首后 `q.currentBytes -= frameSize(removed)`
- `Stats()`：`PendingBytes` 直接返回 `q.currentBytes`
- 新增私有函数 `frameSize(msg AgentMessage) int`（json.Marshal → len）

#### `cmd/susumonitor-agent/main.go`
- `metricbuffer.Open(cfg.MetricsBufferPath, cfg.ServerID, cfg.MetricsBufferMaxEntries, cfg.MetricsBufferMaxBytes)`

#### `.env.example`
```ini
# SUSUMONITOR_METRICS_BUFFER_MAX_BYTES=0  # 字节上限，0 = 不限制（建议留空），最小 1024
```

### 测试
- `TestQueueRejectsOnByteCap`（字节超限拒绝最新条并计 drops）
- `TestBytesTrackedAfterAcknowledge`（ACK 后字节计数减少）
- `TestBytesTrackedAfterRejectHead`（NACK 死信后字节减少）
- `TestByteCapAndCountCapIndependent`（两种上限独立触发）
- `TestInvalidByteCapBelowMin`（< 1024 应报错）

## 三、N1：告警外部通知渠道（邮件 + 钉钉 + Webhook）

### 背景
`AlertTriggeredEvent` 在告警记录落库事务提交后发布（`@TransactionalEventListener AFTER_COMMIT`），`AlertPushPublisher` 已监听它推送 WebSocket。新增 `AlertNotificationPublisher` 监听同一事件，异步发送邮件 / 钉钉 / Webhook，每条规则独立配置，缺失则不发。

### 备份目标
`C:\Backup\SuSuMonitor\<时间戳>-n1-alert-notification\N1-before-change`

### 技术依赖
| 依赖 | 状态 | 说明 |
|---|---|---|
| `spring-boot-starter-mail` | 新增 | Spring Boot 3.4.7 BOM 内置，零冲突 |
| `RestTemplate` | 已有 | spring-boot-starter-web 包含 |
| `@Async + @EnableAsync` | 验证后决定 | 若无则新建 AsyncConfig.java |

### 数据库：Flyway V20
```sql
ALTER TABLE `alert_rules`
    ADD COLUMN `notify_email`    VARCHAR(500) DEFAULT NULL COMMENT '通知邮件地址，多个用英文逗号分隔' AFTER `confirm_count`,
    ADD COLUMN `notify_dingtalk` VARCHAR(500) DEFAULT NULL COMMENT '钉钉机器人 Webhook URL' AFTER `notify_email`,
    ADD COLUMN `notify_webhook`  VARCHAR(500) DEFAULT NULL COMMENT '自定义 Webhook URL（POST JSON）' AFTER `notify_dingtalk`;
ALTER TABLE `alert_records`
    ADD COLUMN `notified_at`     DATETIME(6)  DEFAULT NULL COMMENT '外部通知发送完成时间' AFTER `triggered_at`,
    ADD COLUMN `notify_channels` VARCHAR(100) DEFAULT NULL COMMENT '已发出通知的渠道（email/dingtalk/webhook）' AFTER `notified_at`;
```
