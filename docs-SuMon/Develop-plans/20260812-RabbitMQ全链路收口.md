## 四、代码细节

### M2 DLQ 工具泛化（`api-test/`）

`replay-dlq.mjs`（全量处理版）：
- 新增 `--event metrics|alert` 参数（默认 metrics），常量二元组：
  `{metrics: {dlq: 'susumonitor.alert.metrics.dlq', routingKey: 'metrics.reported.v1'}, alert: {dlq: 'susumonitor.alert.triggered.dlq', routingKey: 'alert.triggered.v1'}}`
- `extractEventId` 为通用 JSON 解析（无需按类型）；发布/计数/防循环逻辑不变

`replay-mvp11-dlq.mjs`（安全审查版：dry-run 默认 + `--execute` + 确认环境变量 + localhost 限定）：
- 同 `--event` 参数；`validateEnvelope()` 按事件类型校验：
  - metrics：event_type=metrics.reported / schema_version=1 / event_id UUID / payload.server_id 整数
  - alert：event_type=alert.triggered / schema_version=1 / event_id UUID / payload 三 ID 正整数 / metric 冻结集
- 不合法 SKIP（不输出 payload）

### M3 验收脚本（`api-test/verify-alert-triggered-chain.mjs`）

仿 verify-mvp11.mjs 模式：
- P0 准备：管理员注册/登录、验证用户审批、建服务器、建告警规则（cpu>80 + 渠道）
- publishEnvelope：管理 API 发布合法 alert.triggered.v1 信封（routing_key=alert.triggered.v1），断言 routed=true
- C1 消费：`susumonitor.alert.triggered` 队列归零 + `alert_notifications` 出现 pending 行（MySQL）
- C2 幂等：同 event_id 重投 → 通知行数不变
- C3 DLQ：非法 JSON / schema_version=2 / 非法 metric → DLQ 增量 ≥3
- C4 失败留痕：consume_records failed 行（consumer=alert-notifier）+ DB 确认指引
- 结尾 `{ status:'PASS', checks:N }`
