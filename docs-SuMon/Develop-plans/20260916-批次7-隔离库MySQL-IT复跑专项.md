## 二、口径决策（本次拍板）

1. **D1 全量复跑而非抽查。** pom.xml `mysql-validation` profile 的 failsafe includes 即 `**/*IT.java` 全集（11 类），按 profile 默认口径一次跑完，不做子集挑选——子集挑选会留下「其余类未在当前基线验证」的尾巴，与专项目的相悖。
2. **D2 一次性容器 + 随机 root 密码 + 非默认端口。** `docker run`（非 compose）起 `mysql:8.4`：与生产 compose（volume 持久化、健康检查、固定网段）完全隔离，跑完即 `docker rm -f`，无残留 volume；root 密码用 24 字节随机 hex 现场生成、仅经 shell 环境变量传递，不落盘不入档；宿主端口取 **13307**（非常规 3306/3307），避免与本机任何现存 MySQL/WSL 发行版端口冲突，同时验证 IT 对非默认 `DB_PORT` 的参数贯通。
3. **D3 库名 `susumonitor_it_validation_20260916`。** 同时满足 `TargetDatabaseGuard` 三条校验：非空、非 `susumonitor`、含 `validation`（小写）。由容器 `MYSQL_DATABASE` 环境变量首次启动自动建库，Flyway 在测试上下文启动时自动执行 V1→最新全部迁移，无需手工 DDL。
4. **D4 密钥用 test profile 同款非生产测试密钥。** `JWT_SECRET` / `AES_GCM_KEY` 取 `src/test/resources/application-test.yml` 已入库的 Base64 测试值（`MDEyMzQ1Njc4...`），与单测同源、非生产密钥，经环境变量注入满足 Spring 配置校验（B1 验收 2026-07-22 已验证此路径）。
5. **D5 IT 走 `mvnw verify -Pmysql-validation`。** failsafe 同时执行 `integration-test` 与 `verify` 两个 goal，失败即 BUILD FAILURE；`surefire` 单测不在本 profile 重复执行（includes 仅 `**/*IT.java`），口径与既有 B 级验收一致。
6. **D6 复跑结果只回填两处文档 + 本计划勾选**，不改 README 第 20 行 AI 能力长条目内的历史时点数字（那是 2026-09-07 F2 收口时的真实快照），在质量基线区新增当前基线条目，避免篡改历史记录语义。

### 3.2 容器启动参数（P1）

```bash
IT_DB_PASSWORD=$(head -c 24 /dev/urandom | od -An -tx1 | tr -d ' \n')   # 48 位 hex，现场生成不落盘
docker run -d --name susumonitor-it-mysql-20260916 \
  -e TZ=Asia/Shanghai \
  -e MYSQL_ROOT_PASSWORD="$IT_DB_PASSWORD" \
  -e MYSQL_DATABASE=susumonitor_it_validation_20260916 \
  -p 127.0.0.1:13307:3306 \
  mysql:8.4
# 就绪探针：循环 mysqladmin ping（容器内）直至 OK，超时 180s
```

- `-p 127.0.0.1:13307:3306`：仅绑定回环，不对局域网暴露；容器内 `mysqladmin ping` 作就绪判据（镜像自带客户端，宿主机无需 mysql CLI）。
- 命名带日期，与历史调试容器可分辨；跑完 `docker rm -f` 即全量清理（无 volume，数据随容器销毁）。
