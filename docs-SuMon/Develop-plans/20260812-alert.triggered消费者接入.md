# 2026-08-12 alert.triggered.v1 消费者接入（消息驱动外部通知）

**状态**：✅ 已收口（2026-08-12，M1→M7 全部完成，Maven 506 tests 全绿）
**前置基线**：告警事件 RabbitMQ 发布收口（f64b412，V25 + Outbox 泛化 + 发布器 + 拓扑）
**技术栈**：Java 21 / Spring Boot 3.4.7 / Spring AMQP（RabbitMQ）/ MyBatis-Plus / JUnit 5 + Mockito

## 一、目标

将 `susumonitor.alert.triggered` 队列的消费者落地，使外部通知（邮件/钉钉/Webhook）从
「本地 AFTER_COMMIT 事件直呼」切换为「Broker 消息驱动」：

1. 新消费者 `alert-notifier` 幂等消费 `alert.triggered.v1`（复用 V15 消费幂等表）
2. 消费事务内排程通知（插 `alert_notifications` pending 行），事务提交后 @Async 异步发送
3. 删除 `AlertNotificationPublisher` 的 AFTER_COMMIT 直呼触发（避免双发）；WS 推送 `AlertPushPublisher` 保留本地事件（低延迟）
4. 失败留痕 recoverer 支持多消费者命名（按队列映射 consumer 名）
5. 数据错误消息直接进 DLQ（复用容器工厂重试/分类语义）

## 四、代码细节

### M2 消息模型（`module/alert/consume/`）

`AlertTriggeredMessage`（record，仿 MetricsReportedMessage）：信封 5 字段（event_id/event_type/schema_version/occurred_at/producer）+ Payload 9 字段（server_id/rule_id/record_id/metric/current_value/threshold_value/level/status/triggered_at），全部 snake_case @JsonProperty，与 AlertTriggeredEnvelopeFactory payload 一一对应；occurred_at/triggered_at 用 String 承载（解析在 validator）。

`AlertTriggeredMessageValidator`（仿 MetricsReportedMessageValidator）：
- 信封：eventId 合法 UUID、producer=="alert-service"（对照工厂常量）、occurredAt UTC OffsetDateTime、payload 非空
- payload：serverId/ruleId/recordId 非空且 >0；metric 非空且 ∈ {cpu,memory,disk,temperature,load_avg}；currentValue/thresholdValue 非空；level/status 非空；triggeredAt UTC OffsetDateTime
- 失败抛 IllegalArgumentException（消费方分类不可重试）

### M3 通知排程拆分（`module/alert/notification/`）

- `AlertNotificationService` 新增：
  - `List<AlertNotificationEntity> scheduleNotifications(AlertRuleEntity rule, AlertRecordVo record)`：同步、调用方事务内插 pending 行（抽出 notify 的插行段）
  - `void sendScheduled(Long recordId, List<AlertNotificationEntity> notifications, AlertRuleEntity rule, AlertRecordVo record)`：@Async、逐渠道 attemptChannel(...,1) + 至少一渠道送达回写 updateNotifiedInfo（现逻辑平移）
- 现有 `notify(rule, record)` 保留（兼容测试 12 例），实现委托为 schedule + sendScheduled

### M4 消费者（`module/alert/consume/`）

`AlertTriggeredConsumer`（仿 AlertMessageConsumer，构造注入：ObjectMapper、AlertNotificationService、AlertRuleMapper、AlertRecordMapper、ConsumeRecordMapper、TransactionTemplate、Clock、AlertTriggeredMessageValidator）：

- `@RabbitListener(queues = "susumonitor.alert.triggered")`
- `onMessage`：parseEnvelope（schemaVersion/eventType 对照 AlertTriggeredEnvelopeFactory 常量 + validator）→ existsConsumed("alert-notifier", eventId) 幂等命中 return → 事务内：
  1. `ruleMapper.selectActiveRuleById(ruleId)`：规则不存在/禁用/无渠道 → 仅 upsert 幂等行
  2. `recordMapper.selectRecordById(recordId)`：record 缺失 → 仅 upsert 幂等行（重试无意义）
  3. `notificationService.scheduleNotifications(rule, record)`（同事务插 pending 行）
  4. `upsertConsumed`（consumer="alert-notifier"、attempts=0、consumedAt=clock）
- `sendScheduled` 在事务提交后调用（@Async，天然不阻塞消费线程）

`FailedConsumeRecordRecoverer` 参数化：
- `recordFailure`/`extractEventId` 中硬编码 `AlertMessageConsumer.CONSUMER_NAME` 与 metrics record 反序列化 → 从 `message.getMessageProperties().getConsumerQueue()` 映射 consumer 名与 record 类型：
  `{"susumonitor.alert.metrics": "alert-evaluator", "susumonitor.alert.triggered": "alert-notifier"}`，缺省回退 alert-evaluator/metrics 类型
- 容器工厂全局唯一，1 个 recoverer bean 兼容两个 listener

### 参数传递与依赖链

```
评估事务 → outbox 登记 alert.triggered.v1（V25 routing_key）
  → OutboxPublisherServiceImpl 按行路由 → susumonitor.events
  → susumonitor.alert.triggered 队列
  → AlertTriggeredConsumer.onMessage(Message)
      → parseEnvelope → AlertTriggeredMessage
      → existsConsumed("alert-notifier", eventId)
      → [事务] selectActiveRuleById + selectRecordById → scheduleNotifications → upsertConsumed
      → [提交后] @Async sendScheduled(notifications, rule, record) → attemptChannel → markAttempt
```

配置复用：`spring.rabbitmq.listener.simple.*`（全局容器工厂，两监听自动套用同一重试/并发）。无新配置键。
