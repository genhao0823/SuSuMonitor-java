## 一、目标

1. **处理耗时/失败率监控**：AOP 计时拦截器统计 3 个消费者（alert-evaluator / alert-notifier / alert-resolved-notifier）处理耗时（含重试整轮）；失败率由 `message_consume_records`（V15 consumed/failed 行）按 consumer 窗口聚合；暴露 ADMIN 状态端点
2. **队列积压告警**：定时用 AMQP `queueDeclarePassive`（零新依赖、无副作用）探测 6 个队列消息数；业务队列（3 个）超阈值 `log.warn`；快照暴露 ADMIN 端点

**技术栈**：全复用——Spring AMQP（`RabbitTemplate.execute`/`ChannelCallback`、AOP `MethodInterceptor`）、MyBatis 聚合 SQL、Spring Scheduling、JUnit5/Mockito/H2。不改拓扑、不改协议、不加 pom 依赖。

## 三、实现细节与参数传递

### 消费统计（M2）
- `consume/ConsumerQueueNames`：`QUEUE_TO_CONSUMER`（3 队列→3 consumer）+ `DEFAULT`（alert-evaluator）；`FailedConsumeRecordRecoverer` 改引用，消除重复映射
- `consume/ConsumeTimingInterceptor implements MethodInterceptor`：`invoke` 对 `onMessage(Message)` 计时（`System.nanoTime`），按 `MessageProperties.consumerQueue` 映射 consumer 名，`registry.record(consumer, durationMs)`；异常 rethrow 不吞
- `consume/ConsumeTimingStatsRegistry`：ConcurrentHashMap，窗口 `{totalCount, totalMs, maxMs, lastSampleAt}`；`snapshot()` 返回不可变副本
- `AlertRabbitConfig.adviceChain = [timingInterceptor, retryAdvice]`（timing 最外层 → 记录含重试整轮耗时）
- `ConsumeRecordMapper.countByConsumerAndStatus(status, since)`：`created_at >= #{since} GROUP BY consumer`（窗口失败率 = failed/(consumed+failed)）
- 配置：`susumonitor.rabbitmq.consume-stats-window-minutes`（默认 60，@Min 1 @Max 1440）

### 队列积压（M3）
- `RabbitMqTopologyConfig` 6 个队列常量 `static final` → `public static final`
- `system/QueueBacklogSnapshotRegistry`：volatile Map（queue → `{messages, checkedAt, error}`）
- `system/QueueBacklogProbeService.probe()`：`rabbitTemplate.execute(ChannelCallback)` 逐个 `queueDeclarePassive(name).getMessageCount()`；单队列失败标记 error 不中断；业务队列超阈值 `log.warn`
- `scheduler/QueueBacklogProbeScheduler`：`@Scheduled(fixedDelayString = "${susumonitor.rabbitmq.queue-monitor-interval-ms:60000}")` + `@ConditionalOnProperty(queue-monitor-enabled)`
- 配置：`queue-monitor-enabled`（默认 true）、`queue-monitor-interval-ms`（默认 60000，@Min 5000）、`queue-backlog-warn-threshold`（默认 10000，@Min 1）

### 端点（M4）
- `GET /api/system/rabbitmq/consumers`（ADMIN）→ `ConsumeStatsVo{consumer, totalCount, avgMs, maxMs, lastSampleAt, failedWindow, consumedWindow, failureRate}`
- `GET /api/system/rabbitmq/queues`（ADMIN）→ `QueueBacklogVo{queue, type(business|dead-letter), messages, warnThreshold, checkedAt}`
- 权限沿用 SecurityConfig 现有 ADMIN 端点匹配模式；openapi-system.json 同步

## 四、验证边界（诚实声明）

- 统计为单 JVM 内存窗口（多实例各自统计，与现有单 JVM 口径一致）；重启清零（窗口语义）；失败率窗口按 `created_at`（应用时钟 UTC 写入）
