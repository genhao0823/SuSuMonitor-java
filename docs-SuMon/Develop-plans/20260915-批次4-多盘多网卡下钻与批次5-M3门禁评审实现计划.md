## 二、批次 4：多盘/多网卡下钻（协议 v1.4 → v1.5，三端）

### 2.1 需求口径

固定宽表 `metrics` 只有单盘/聚合网卡一行（`disk_percent/disk_used/disk_total/net_rx/net_tx`），多盘服务器上其他盘与分网卡速率不可见。批次 4 新增**每挂载点磁盘容量**与**每网卡收发速率**两类实时快照：不入宽表、零 Flyway 迁移，复制进程快照的"内存注册表 + REST latest + `metrics.update` 捎带"三件套。

### 2.2 决策记录（本次拍板）

- **D4-1 注册表与存量进程注册表同构**：`ResourcesSnapshotRegistry` = `ConcurrentHashMap<Long, TimedSnapshot>` + 90 秒 `FRESHNESS_WINDOW` + `Clock` 注入 + **读取侧惰性过期**，无后台扫描（盘点结论 2）。原草案"每 30s 扫描"作废，理由：与 `ProcessSnapshotRegistry` 保持同一实现形态，行为一致、测试一致、少一条调度路径。
- **D4-2 协议形状：上行扁平、下行包节点**。Agent→Java `metrics.report` 在顶层加可选 `disks`/`nics` 数组（与 `process_cpu_top` 同级同语义）；Java→浏览器 `metrics.update` 加可选 `resources` 节点（与 `processes` 节点同构，内含完整快照 `server_id/collected_at/disks/nics`）。REST `GET /api/servers/{id}/resources/latest` 返回同一快照形状。
- **D4-3 扩展字段校验语义=超限/非法丢节点+告警日志，不断链**：`metrics.report` 携带的 `disks`/`nics` 若任一列表超限（disks>32、nics>64）或任一元素非法（null/空白或超 128 字符的名称/负数值）→ **丢弃整个 `resources` 快照（不注册表、不推送）+ WARN 日志（含 server_id 与原因），核心指标行照常入库、照常 `metrics.ack`**。与进程字段"非法即整报永久 nack"（v1.4 严格语义）刻意不同：资源扩展是可选增强，不应让畸形扩展把核心遥测链路打死；Agent 侧采集时已截断，超限只可能来自行为异常客户端，WARN 即运维信号。协议文档明示该差异。
- **D4-4 REST 端点挂 `MetricsController`**：不新建 `ServerResourcesController`。`processes/latest` 先例就在 `MetricsController`（tag=`servers`），资源快照的数据源同为 `MetricsService`，模块内聚优于原草案字面。权限面与 metrics 读取一致（任意已认证用户，Bearer JWT）。
- **D4-5 Agent 网卡速率差分窗口=采集周期**：`ExtendedSampler` 与 `ProcessSampler` 同样采用"上次扫描基线 + 本周期差分"，间隔即 `SUSUMONITOR_COLLECT_INTERVAL_SECONDS`（默认 5s）；`kbps = Δbytes × 8 ÷ Δsec ÷ 1000`，保留 2 位小数。首周期仅建基线：**disks 点值即得首周期即带，nics 首周期为 nil 整体省略**。
- **D4-6 开关默认开**：`SUSUMONITOR_EXTENDED_RESOURCES` 布尔，默认 `true`（`getenvBoolDefault`，`0/false` 显式关闭）。与 `SUSUMONITOR_PROCESS_TOP_N=0` 关进程采集同一套运维语义。
- **D4-7 Android 零改动**：App 端既有页面不消费新端点/新节点；协议为纯增量字段，旧客户端不感知。验证口径写进开发日志，不产生代码提交。
