## 一、目标

让位于家庭网络且没有公网入站端口的 Linux 主机，通过现有 Go Agent 主动建立到云端 Java 后端的 `WSS` 长连接。外部用户登录 Web 后，由云端在既有连接上反向下发终端消息，Agent 在家庭主机创建本地 PTY 和 Shell，实现浏览器交互式终端。

首版不使用 FRP、反向 SSH、VPN、家庭路由器端口映射或独立 WebSocket 中继服务。云端 Java 后端同时承担认证、会话路由、流量边界和审计职责。

## 二、已确认决策

| 决策项 | 结论 |
|---|---|
| 家庭主机系统 | Linux |
| 网络方向 | 家庭 Agent 主动出站连接云端，家庭网络不开放入站端口 |
| 远程形态 | 浏览器交互式终端，不是单次命令模板 |
| Agent 与终端系统权限 | `root` |
| 业务权限 | `admin` 和所有 `approved user` 均可打开终端 |
| 云服务器 | 2 核 4 GB、60 GB SSD、OpenCloudOS 9.6 |
| 公网入口 | 已绑定域名，由宝塔 Nginx 提供 HTTPS/WSS |
| 云端进程 | Java 后端由 systemd 管理，只监听 `127.0.0.1:18080` |
| 数据库 | 复用宝塔 MySQL，MySQL 端口不开放公网 |
| Web 部署 | Vue 构建产物由宝塔 Nginx 托管 |
| 首版实例数 | 单 Java 实例；连接与路由状态保存在单 JVM 内存中 |
| 终端内容 | 输入和输出不落库、不写日志，只保存会话元数据 |
| 传输协议 | 复用 `/ws/monitor` 和 `/ws/agent`，新增 `terminal.*` 消息 |

`root` 终端是用户明确选择的高风险能力。所有 `approved user` 均能取得家庭主机完整控制权，因此账号审核等同于 root 权限授予。实现和部署不得把该风险描述为低权限或普通监控能力。

## 三、目标拓扑

```text
外部浏览器
    │ HTTPS/WSS 443
    ▼
宝塔 Nginx（域名与 TLS）
    │ /api、/ws 反向代理
    ▼
SuSuMonitor Java 后端（127.0.0.1:18080，单实例）
    │ /ws/agent 已鉴权双向长连接
    ▼
家庭 Linux 主机 Go Agent（root）
    │ 本地 PTY
    ▼
root Shell
```

公网地址、域名和证书信息属于部署环境数据，仓库示例统一使用 `SERVER_IP_OR_DOMAIN`，不记录真实 IPv4、真实域名或凭据。

## 四、职责边界

| 组件 | 职责 |
|---|---|
| Vue Web | 获取一次性 Monitor Ticket、呈现 xterm.js、发送输入/resize/close、展示连接状态 |
| 宝塔 Nginx | TLS 终止、Vue 静态资源、同域 `/api` 和 `/ws` 反向代理 |
| Java 后端 | 用户与 Agent 鉴权、会话所有权、状态机、并发限制、双向路由、元数据审计 |
| Go Agent | 维护主动 WSS 连接、创建 root PTY、转发输入输出、resize、终止并清理子进程 |
| MySQL | 保存终端会话元数据，不保存命令和终端输入输出 |

Java 后端不得解释或执行终端内容。浏览器不得指定任意 Shell 路径；Agent 从受保护的本地配置读取固定 Shell，首版默认 `/bin/bash`，启动前验证其为绝对路径且可执行。

## 五、协议和会话状态

正式消息定义见 `docs-SuMon/Protocol-SuMon/websocket-protocol.md`。本计划固定以下双向路由：

```text
Web /ws/monitor                Java                  Agent /ws/agent
terminal.open        ------->  validate  ---------> terminal.open
terminal.opened      <-------  route     <--------- terminal.opened
terminal.input       ------->  route     ---------> terminal.input
terminal.output      <-------  route     <--------- terminal.output
terminal.resize      ------->  validate  ---------> terminal.resize
terminal.close       ------->  close     ---------> terminal.close
terminal.closed      <-------  persist   <--------- terminal.closed
terminal.error       <-------  route     <--------> terminal.error
```

会话状态固定为：

```text
opening -> open -> closed
opening -> error
open -> timeout
open -> error
```

- `session_id` 只能由 Java 后端生成 UUID，浏览器和 Agent 不得自选。
- 同一个 `terminal.open` 的 `message_id` 必须幂等，重复消息不得创建第二个 PTY。
- 用户只能输入、resize 或关闭自己创建的会话。
- Agent 只接受已由 Java 绑定到当前 `server_id` 的会话。
- 关闭操作幂等；重复关闭不得返回内部错误或重新创建资源。
- Java 或 Agent 重启后，不恢复旧 PTY，会把遗留的 `opening/open` 元数据收口为 `error`。

## 六、安全与资源限制

### 6.1 身份和授权

- 浏览器先使用 JWT 调用 `POST /api/ws/monitor-ticket`，再用 30 秒一次性 Ticket 握手 `/ws/monitor`。
- 只有数据库最新状态为 `approved` 的用户可以打开终端，角色可以是 `admin` 或 `user`。
- Java 在 `terminal.open/input/resize/close` 时回查数据库最新用户状态，不只信任 Monitor 握手时的用户快照。用户被拒绝、删除或失去有效认证后，不得继续操作，新消息触发关闭其已有终端。
- Agent 继续使用首帧 `agent.authenticate`，Agent Token 不进入 URL、日志或终端消息。
- Agent Token 吊销、轮换、服务器软删除或 Agent 连接被替换时，关闭该服务器全部终端。

### 6.2 root 风险控制

- Agent systemd 服务使用 `User=root`，PTY 和 Shell 继承 root 权限。
- Agent 二进制、systemd unit 和环境文件必须由 `root:root` 所有，普通用户不可写。
- `/etc/susumonitor/agent.env` 权限固定为 `0600`，不得沿用低权限 Agent 的 `0640`。
- 不允许浏览器覆盖 Shell、环境变量、工作目录、UID、GID 或启动参数。
- 不记录终端输入输出并不能消除 root 风险；审计只能证明谁在何时打开了哪个会话。
- 任何 `approved user` 账号失陷都等同家庭主机 root 失陷。上线前必须启用强密码，后续优先补充 MFA 和逐服务器授权。

### 6.3 首版限制

| 限制项 | 首版值 |
|---|---|
| 单用户并发终端 | 2 |
| 单服务器并发终端 | 4 |
| 全局并发终端 | 16 |
| 初始/resize 列数 | 1-300 |
| 初始/resize 行数 | 1-100 |
| 单条输入解码后大小 | 16 KiB |
| 单条输出解码后大小 | 16 KiB |
| 空闲超时 | 20 分钟无输入 |
| 最大会话时长 | 8 小时 |
| WebSocket 消息上限 | 64 KiB |

终端字节使用 Base64 放入 JSON。每个会话必须使用有界输出队列；浏览器消费过慢、队列溢出或 WebSocket 写超时时，关闭会话，禁止无限缓存输出。

## 七、数据库规划

现有 `commands` 表面向单次命令，`ssh_sessions` 表面向未来云端主动 SSH，均不直接复用为 Agent PTY 会话。新增 Flyway 迁移：

```text
V12__create_terminal_sessions_table.sql
```

建议字段：

| 字段 | 说明 |
|---|---|
| `id` | 数据库主键 |
| `session_id` | Java 生成的唯一 UUID |
| `server_id` | 目标服务器 ID |
| `user_id` | 创建终端的用户 ID |
| `status` | `opening/open/closed/timeout/error` |
| `shell` | Agent 实际使用的固定 Shell 标识 |
| `opened_at` | PTY 成功打开时间 |
| `last_input_at` | 最近输入时间，用于空闲超时 |
| `closed_at` | 关闭时间 |
| `close_reason` | 受限长度的关闭原因，不包含终端内容 |
| `created_at/updated_at` | 审计时间 |

不得修改已经执行过的 V4 或 V6 迁移。数据库迁移实施前按项目规则备份目标库并验证备份可读；数据库删除、清空或 Flyway 历史重置不属于本计划。

## 九、宝塔 Nginx 规划

同一域名承载 Web、REST 和 WebSocket：

```text
https://SERVER_IP_OR_DOMAIN/          -> Vue dist
https://SERVER_IP_OR_DOMAIN/api/      -> http://127.0.0.1:18080/api/
wss://SERVER_IP_OR_DOMAIN/ws/agent    -> http://127.0.0.1:18080/ws/agent
wss://SERVER_IP_OR_DOMAIN/ws/monitor  -> http://127.0.0.1:18080/ws/monitor
```

WebSocket 代理至少需要：

```nginx
proxy_http_version 1.1;
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
proxy_set_header Host $host;
proxy_set_header X-Forwarded-Proto $scheme;
proxy_read_timeout 3600s;
proxy_send_timeout 3600s;
```

实施时必须合并到宝塔实际生成的站点配置，不能用示例整体覆盖现有配置。TLS 证书、真实域名和面板信息不写入仓库。

## 十三、出口条件

- 文档、Java、Go、Vue 和部署配置使用同一版 `terminal.*` 协议。
- 真实公网链路中家庭 Agent 只发起出站 WSS，家庭网络不开放入站端口。

- Agent、浏览器或云端断开后无遗留 PTY 和孤儿 Shell。
- 终端输入输出不进入 MySQL、应用日志、Nginx 日志正文或错误响应。
- 并发、帧大小、空闲超时、最大时长和慢消费者限制经过自动化或运行时验证。
- 云端只公开 80/443，Java 和 MySQL 不直接暴露公网。
- 分别记录代码检查、编译、单元测试、MySQL 集成、真实 WebSocket、服务启动和公网部署验证，互不替代。
