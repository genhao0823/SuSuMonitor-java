当前后端已经通过事务和数据库行锁实现首管理员初始化：

- `UserServiceImpl.register()` 使用 `@Transactional`。
- `AuthBootstrapStateMapper.xml` 通过 `SELECT ... FOR UPDATE` 锁定 `auth_bootstrap_state.id=1`。
- 首个用户写入 `admin/approved`，后续用户写入 `user/pending`。
- `markAdminInitialized` 通过 `admin_initialized=0` 条件更新提供第二层保护。
- 单元测试已覆盖首用户、后续用户、状态缺失和更新失败回滚。

现有真实验收脚本有两个契约问题：

1. 默认用户名 `first-admin-` 含连字符，不符合 `RegisterRequest` 的 `[A-Za-z0-9_]+` 校验。
2. 脚本把“恰好一个 HTTP 200”作为成功条件，但业务契约是所有不同用户名都可以注册成功，只有一个用户成为 `admin/approved`，其余为 `user/pending`。

## 二、模块目标

在独立空 MySQL schema 中并发注册 N 个不同用户，验证：

1. N 个注册请求均返回 HTTP 200 且业务 `code=0`。
2. 恰好一个用户为 `admin/approved`。
3. 其余 N-1 个用户为 `user/pending`。
4. 管理员可登录，`GET /api/auth/me` 返回 `admin/approved`。
5. 抽样待审核用户登录返回 HTTP 403。
6. 数据库中的 `auth_bootstrap_state` 已初始化，且 `initialized_user_id` 指向唯一管理员。

默认并发数为 8，边界验证使用 20；并发数允许 2-20。

## 三、实现范围

### 1. Node 验证器

文件：`api-test/verify-first-admin-concurrency.mjs`

- 默认前缀改为合法的 `first_admin_`。
- 校验前缀只能包含字母、数字和下划线，并保证生成用户名长度在 3-50 之间。
- 严格校验并发数为 2-20 的整数，不静默修正非法输入。
- 固定本次运行的时间戳和用户名数组，保留请求与响应对应关系。
- 断言全部注册成功、业务码为 0、返回用户名与请求一致。
- 按 `role` 与 `reviewStatus` 统计并断言唯一管理员及 N-1 个待审核用户。
- 验证管理员登录、`/me` 和待审核用户 403。
- 输出脱敏 JSON 摘要，不输出密码、Token、数据库名或连接凭据。

### 2. PowerShell 编排器

文件：`api-test/run-first-admin-concurrency-e2e.ps1`

- 保留独立 schema、端口 18182 和 `FIRST_ADMIN_CONCURRENCY` 硬性确认。
- 增加 `$runSucceeded`，避免清理数据库后的 `$LASTEXITCODE` 覆盖真实验证结果。
- 在 API 验证成功后使用 MySQL CLI 复核 `users` 与 `auth_bootstrap_state` 的最终状态。
- 成功时清理 schema 和临时日志；失败时保留故障日志并打印人工清理信息。
- 敏感环境变量只通过进程环境传递，不写入代码、文档或运行摘要。

## 四、参数与调用链

```text
SUSUMONITOR_VALIDATION_CONCURRENCY (2..20)
  -> verifier 生成 N 个合法 username
  -> POST /api/auth/register
  -> AuthController.register(RegisterRequest)
  -> UserServiceImpl.register(@Transactional)
  -> auth_bootstrap_state.id=1 FOR UPDATE
  -> UserMapper.insert(UserEntity)
       first: admin/approved
       following: user/pending
  -> markAdminInitialized(initialized_user_id, initialized_at)
  -> ApiResponse<CurrentUserVo>
  -> verifier 校验 API 状态、角色和登录边界
  -> PowerShell/MySQL 校验持久化状态
```
