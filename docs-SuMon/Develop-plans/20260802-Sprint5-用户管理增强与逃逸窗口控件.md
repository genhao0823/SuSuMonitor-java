## 功能模块与提交（每模块一次 git commit）

### M1 后端：admin 用户分页+搜索+批量审核

**参数传递设计**：
- `GET /api/admin/users/pending?keyword=&page=&page_size=` → `ApiResponse<PageResult<PendingUserVo>>`
  - `keyword`（可选 String）：`username LIKE CONCAT('%', #{keyword}, '%')`，空串/空白忽略
  - `page`（默认 1，@Min(1)）、`page_size`（默认 20，@Min(1) @Max(100)）；offset=(page-1)*pageSize
  - 仍过滤 `role='user' AND review_status='pending'`，`ORDER BY created_at ASC, id ASC`（保持现有语义）
- `PUT /api/admin/users/batch-approve|reject`，body `{ user_ids: [1,2,3] }` → `ApiResponse<BatchReviewResult>`
  - `BatchReviewResult{ processed: int, failed: int }`；`user_ids` 为空 → 参数错误
  - 事务：外层 @Transactional；循环逐 id 调 `UserMapper.updateReviewStatus`（`WHERE role='user' AND review_status='pending'` 乐观条件），单条失败（返回 0 或异常）**catch 收集 failed 不传播**，不整体回滚 → 部分成功可展示

**技术栈**：Spring Boot 3.4.7 + MyBatis（XML 手写分页，与项目一致）+ Jakarta Validation

**改动文件**：
- `UserMapper.java/.xml`：`selectPagePendingUsers`（keyword 可选 + LIMIT offset/pageSize）+ `countPendingUsers`（keyword 可选）
- `UserService.java`/`UserServiceImpl.java`：`pagePendingUsers(keyword, page, pageSize)` → `PageResult<UserEntity>`
- `AdminUserService`/`AdminUserServiceImpl`：`pagePendingUsers(...)` → `PageResult<PendingUserVo>`；`batchUpdateReviewStatus(userIds, targetStatus, operator)` → `BatchReviewResult`
- 新 `dto/BatchReviewRequest`（`user_ids` List<Long>，@NotEmpty）+ 新 `vo/BatchReviewResult`（processed/failed）
- `AdminUserController`：pending 加 @RequestParam 三参；新增 batch-approve / batch-reject
