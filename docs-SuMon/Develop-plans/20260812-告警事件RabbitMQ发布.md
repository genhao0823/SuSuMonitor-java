## 四、代码细节

### M2 V25 迁移

- 新建 `db/migration/V25__add_message_outbox_routing_key.sql`：
  `ALTER TABLE message_outbox ADD COLUMN routing_key VARCHAR(64) NOT NULL DEFAULT 'metrics.reported.v1'`
  现有行默认值语义正确（历史行均为 metrics 事件），加 COMMENT。

### M3 Outbox 泛化

- `OutboxEntity` + `routingKey` 字段；`OutboxMapper.xml` resultMap/列清单/insert 同步
- `OutboxService.enqueue(MetricsEntity, String)` → `enqueue(String eventType, String routingKey, String payload, String eventId)`
  （调用方仅 `MetricsServiceImpl.report` 一处）
- `OutboxServiceImpl` 不再注入 `OutboxEnvelopeFactory`；泛化方法登记完整行
- `OutboxEnvelopeFactory` + `ROUTING_KEY = "metrics.reported.v1"` 常量（契约单点公开）
- `MetricsServiceImpl.report`：生成 eventId → 构建信封 → 泛化 enqueue
- `OutboxPublisherServiceImpl.publishRow` 改用 `row.getRoutingKey()` 发布
- `AppProperties.Rabbitmq` 删除 `routingKey`；`application.yml` 删除 `routing-key` 行

### M4 alert.triggered.v1 发布器

- 新建 `module/alert/outbox/AlertTriggeredEnvelopeFactory`：
  `EVENT_TYPE="alert.triggered"` / `ROUTING_KEY="alert.triggered.v1"` / `PRODUCER="alert-service"` /
  `SCHEMA_VERSION=1`；`build(AlertRecordVo, eventId)` 输出契约 §四 信封
  （payload: server_id/rule_id/record_id/metric/current_value/threshold_value/level/status/triggered_at，UTC 秒级）
- `AlertEvaluationServiceImpl.handleTrigger`：record 插入后同事务登记 outbox 行；
  现有 `AlertTriggeredEvent`（WS 推送/外部通知）不动

### M5 拓扑

- `RabbitMqTopologyConfig` 新增：
  - 队列 `susumonitor.alert.triggered`（DLX 参数：susumonitor.dlx / alert.triggered.v1）
  - 队列 `susumonitor.alert.triggered.dlq`
  - 绑定：events --alert.triggered.v1--> 业务队列；dlx --alert.triggered.v1--> DLQ

### M6 测试

- 新建 `AlertTriggeredEnvelopeFactoryTests`（信封与契约 §四 示例逐字段一致）
- 更新 `OutboxMapperMybatisTests`（routing_key 读写）、`OutboxPublisherServiceTests`（按行路由）、
  `AlertEvaluationServiceTests`（触发登记断言）
- `mvnw test` 全量回归
