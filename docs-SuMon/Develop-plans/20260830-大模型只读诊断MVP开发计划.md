# 20260830-大模型只读诊断MVP开发计划

**日期**：2026-08-30  
**状态**：规划中  
**并行关系**：与 `20260829-RC1单实例生产可靠性收口计划.md` 并行推进；本计划不修改 RC1 发布门槛，也不将 AI MVP 的文档、契约或代码状态表述为 RC1 或生产验收通过。

## 一、目标

在现有 SuSuMonitor 服务器监控数据之上定义一个面向管理员的只读大模型诊断 MVP：管理员提交 `server_id`、问题和历史窗口，系统从白名单监控数据生成脱敏上下文，调用受控的第三方 provider，并返回可审计的结构化诊断结果。

目标包括：

- 冻结 `POST /api/ai/diagnoses` 的请求、响应、权限和错误码候选契约。
- 明确第三方 provider、数据白名单、脱敏、密钥、成本、限流、kill switch 和审计边界。
- 保证 AI 只消费监控诊断所需的只读摘要，不具备终端、SSH、命令执行、数据库写入或服务器配置修改能力。
- 为后续 Java 实现提供可验证的验收门槛，同时保留 Java 主线对最终字段和错误码的调整权。

## 二、非目标

- 不在本计划中实现 Java Controller、Service、DTO/VO、数据库表、Flyway/SQL 或第三方 provider SDK。
- 不修改 `/ws/agent`、`/ws/monitor` 的终端协议，不让 AI 直接读取或发送任何终端帧。
- 不执行 SSH 握手、命令、脚本、终端输入、服务器重启、配置变更、告警规则变更或其他写操作。
- 不把模型输出当作事实、运维指令、自动修复结果或生产变更审批。
- 不承诺 provider 可用性、模型准确率、生产成本或 RC1 发布资格。
- 不将当前 OpenAPI 计划契约视为 Java Controller 已实现；契约检查中的并行例外仅用于文档阶段。

## 三、依赖与前置条件

- RC1 单实例基线和其安全审计结论，尤其是 admin-only 终端边界、凭据不出站和现有审计/限流约定。
- 已冻结的服务器、指标、告警和认证数据语义；AI 只读取经白名单批准的字段。
- 管理员 Bearer JWT 鉴权、服务器归属/软删除校验和统一 `{ code, message, data }` 响应信封。
- provider 白名单、出站域名/网络策略、API 密钥托管、超时和重试策略。
- 脱敏规则及其 fail-closed 测试；规则未加载、字段不确定或脱敏失败时必须拒绝外发。
- 成本预算、按管理员/服务器/IP 的限流配额、全局和 provider 级 kill switch。
- Java 主线对最终 endpoint、字段命名、错误映射、模型/usage 结构的实现确认。

## 四、任务清单

### 阶段 A：契约与边界冻结

- [ ] 评审并冻结 `POST /api/ai/diagnoses` 的请求参数：`server_id`、`question`、`history_minutes` 的类型、范围、默认值和最大窗口。
- [ ] 评审结构化响应：`summary`、`severity`、`findings`、`evidence`、`recommendations`、`limitations`、`model_used`、`provider`、`model`、`prompt_version`、`usage`。
- [ ] 由 Java 主线确认统一响应信封、HTTP 状态与业务错误码（候选码见 OpenAPI）。
- [ ] 明确契约状态标记为 planned/unimplemented，禁止把文档检查通过写成接口验收通过。

### 阶段 B：只读数据流与安全控制

- [ ] 建立监控数据白名单和字段级 schema；默认拒绝未知字段、原始日志、凭据、Token、私钥、环境变量和终端内容。
- [ ] 实现/评审脱敏流水线：字段选择 → 类型/长度校验 → 规则化脱敏 → 二次扫描 → provider 请求；任一步失败均 fail-closed。
- [ ] 固定 system prompt、prompt 模板版本和输出 schema；模型输出只作为建议，必须携带证据、限制和不确定性。
- [ ] 建立 prompt injection 防护：将服务器名称、描述、告警文本等外部内容视为不可信数据，不能覆盖系统约束或触发工具调用。
- [ ] 配置 provider 白名单、TLS、出站网络限制、密钥轮换与最小权限；禁止动态 provider URL 和用户提供的模型/工具参数。

### 阶段 C：运行治理与审计

- [ ] 实现管理员/服务器/IP/全局限流、并发上限、请求体和历史窗口上限、provider 超时和有界重试。
- [ ] 实现预算/用量统计和 kill switch；开关关闭、预算耗尽、provider 不在白名单或脱敏失败时不发起外部请求。
- [ ] 定义保留期：原始问题、脱敏上下文、provider 请求/响应和 usage 分开设置最短必要保留期；默认不长期保存原文。
- [ ] 审计记录 request_id、admin_id、server_id、provider/model、prompt_version、结果状态、耗时、usage 和拒绝原因，不记录 Token、密钥、原始终端/SSH 内容或完整 prompt。
- [ ] 对日志、指标、审计和错误响应做秘密扫描，确保 provider 错误不会回显请求上下文或密钥。

### 阶段 D：验证与交付

- [ ] 补充 Java 单元/集成测试：admin-only、服务器不存在/已删除、参数边界、白名单、脱敏 fail-closed、kill switch、限流、超时、provider 错误和审计字段。
- [ ] 补充安全测试：prompt injection、越权服务器、敏感字段回显、终端/SSH/写操作诱导、重放和并发限流。
- [ ] 在隔离环境以固定 fixture 验证 provider mock 请求只含白名单脱敏数据，且永不产生终端帧或 SSH 调用。
- [ ] Java 主线确认最终字段/错误码后同步更新 OpenAPI、前端类型和验收脚本；文档阶段的例外随实现合入后移除。
- [ ] 形成独立 AI MVP 验收记录。仅在真实环境证据、当前 commit 和明确版本齐备后描述为该 MVP 已验收，不能替代 RC1 门槛。

## 五、时间与阶段

- **阶段 A，0.5 天**：请求/响应、权限、错误码和 planned 状态评审。
- **阶段 B，1.5 天**：白名单、脱敏、provider 边界、prompt injection 和禁止能力评审。
- **阶段 C，1 天**：密钥、保留期、成本/限流、kill switch、审计设计。
- **阶段 D，2 天**：Java 实现、测试、mock provider 联调和安全回归；实际排期以 Java 主线确认依赖为准。
- **阶段出口**：阶段 A-C 文档评审通过后才进入实现；阶段 D 通过后仍需独立 AI MVP 验收，不能借用 RC1 的 PASS 结论。

## 六、验收门槛

### 文档与契约门槛

- [ ] OpenAPI 3.0 JSON 可解析，所有本地 `$ref` 可解析，端点明确 `admin` Bearer，且请求/响应字段与 Java 最终实现完成对齐。
- [ ] README/索引列出 AI 契约为第 6 份 JSON，并标注 1 条 planned endpoint 不计入 Java 已实现端点。
- [ ] websocket 协议明确 `terminal.*` 仅 admin，且 AI 永不直接使用终端帧。

### 安全门槛

- [ ] 非 admin 始终得到拒绝；server_id 只能访问允许的服务器，软删除服务器不可诊断。
- [ ] provider 只能是配置白名单中的固定目标；密钥来自受控配置/secret，不进入日志、响应或 prompt。
- [ ] 数据白名单和脱敏链路任一异常均不发出 provider 请求；敏感字段和原始终端/SSH 数据零出站。
- [ ] prompt injection fixture 不得改变系统约束、产生工具调用或获得写/终端/SSH 能力。
- [ ] kill switch、预算、限流、超时和审计可通过自动化测试验证。

### 功能与可靠性门槛

- [ ] 成功响应包含全部结构化诊断字段，`limitations` 能表达数据不足、模型不确定性和“不得据此执行变更”。
- [ ] provider 超时、不可用、配置关闭、预算耗尽、脱敏失败和内部异常映射到稳定错误响应，不泄露内部细节。
- [ ] 结果可由 request_id/admin_id/server_id/prompt_version/provider/model/usage 追溯；原始敏感上下文按保留策略清理。
- [ ] 仅在 Java 主线实现、测试、当前 commit 和隔离/真实环境证据均具备后，才可记录“AI MVP 验收通过”；该记录仍不等同于 RC1 生产验收。

## 七、需 Java 主线确认的开放项

- `history_minutes` 是否必填、默认值、最大值以及是否允许 `0`。
- `question` 最大长度、允许字符和是否需要语言/内容策略字段。
- `findings`、`evidence`、`recommendations` 的最终对象字段，以及 `usage` 的 token/cost 字段命名和可空性。
- `model_used` 的类型（布尔值或模型元数据对象）与 `provider`/`model` 的脱敏展示规则。
- 候选错误码 `50303`、`50304`、`50401`、`42906`、`50003` 的最终枚举、HTTP 映射和 message；Java 主线可调整，调整后必须同步本计划、OpenAPI 和验收测试。
