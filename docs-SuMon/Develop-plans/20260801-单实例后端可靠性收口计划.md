# 单实例后端可靠性收口计划

**日期**：2026-08-01  
**范围**：Java 后端 MVP-11 已提交能力复核，以及当前工作区的字段级消息契约校验、Outbox 清理、Agent 状态转换推送增量。

## 目标

以当前云端单 Java 进程、单 RabbitMQ 告警消费者的部署模型为准，完成增量能力的备份、验收、模块化本地提交和文档同步。当前不将双实例/多消费者并发作为发布门禁。

## 架构与参数

```text
Agent / Outbox -> susumonitor.events -> susumonitor.alert.metrics
                                          -> 单 AlertMessageConsumer
                                          -> MySQL alert_* / message_consume_records
                                          -> alert.push / server.status.update
```

- Java 21、Spring Boot 3.4.7、MySQL 8.4、RabbitMQ 4.3.4。
- 告警消费者保持 AUTO ACK：业务事务成功返回后 ACK；不可重试契约错误直接 DLQ；其他错误按 3 次、1s、2 倍、10s 上限重试。
- Outbox 轮询保持 200ms；cleanup 默认关闭，30 天保留、03:30、每批 1000、每轮最多 100 批。
- 当前不配置 Listener 并发；`verify-mvp11-concurrency.mjs` 仅保留为未来扩容前资产。

## 执行任务

1. **回归基线**：核查单实例 Java、MySQL、RabbitMQ；执行 Maven 回归及现有单实例消息验收。
2. **字段级消息契约**：在 JSON/schema/type 检查后、幂等查询前校验 UUID、producer、UTC 时间、指标范围和容量不变量；字段非法消息零重试进入 DLQ。
3. **Outbox 清理与 V16**：验证 Flyway、索引、仅删除过期 published 行、批量边界与默认关闭策略。
4. **状态推送与 V17**：验证 `DATETIME(6)` 迁移、在线/离线转换推送、订阅过滤和普通心跳去重。
5. **文档与提交**：每个模块修改前备份、测试后精确暂存并本地提交；最后同步路线图、协议、运维手册和开发日志。
