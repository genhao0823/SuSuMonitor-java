## 1. 目标与范围

将 Agent 指标上报由“WebSocket 写入成功即视为成功”的在线 best-effort 模式，收口为“服务端入口事务接受并回传 `metrics.ack` 后才删除本地待确认项”的有界可靠投递。

本轮不引入新的消息中间件、跨 JVM 状态、数据库迁移或浏览器端投递状态页面；指标进入 Java 后的 Metrics Outbox 与 RabbitMQ 告警链路仍沿用既有职责边界。

## 2. 协议与参数

### 2.1 `metrics.ack`

Server 在 `MetricsService.report(...)` 成功返回后回传：

```json
{
  "type": "metrics.ack",
  "message_id": "<原 metrics.report UUID>",
  "timestamp": "<UTC ISO-8601>",
  "payload": {"server_id": 1, "collected_at": "<UTC ISO-8601>"}
}
```

它只确认 Metrics 入口事务（包含重复 `message_id` 的幂等接受）已成功；不确认 Outbox 发布、RabbitMQ、`metrics.update` 或异步告警评估。

### 2.2 Agent 环境变量

| 参数 | 默认值 | 传递链路 | 约束 |
|---|---:|---|---|
| `SUSUMONITOR_METRICS_BUFFER_PATH` | `/var/lib/susumonitor/metrics-buffer.json` | env → `config.Config` → `metricbuffer.Open` | 必须是 clean absolute path |
| `SUSUMONITOR_METRICS_BUFFER_MAX_ENTRIES` | `720` | env → `config.Config` → Queue capacity | 1–100000；默认对应 5 秒采集约 1 小时 |
| `SUSUMONITOR_METRICS_ACK_TIMEOUT_SECONDS` | `15` | env → `config.Config` → `reporter.Options.AckTimeout` | 1–300 秒；超时后保留原帧 |
| `SUSUMONITOR_METRICS_RETRY_INITIAL_SECONDS` | `2` | env → `config.Config` → `reporter.Options.RetryInitial` | 必须为正数 |
| `SUSUMONITOR_METRICS_RETRY_MAX_SECONDS` | `60` | env → `config.Config` → `reporter.Options.RetryMax` | 必须不小于 initial |
| `SUSUMONITOR_METRICS_RETRY_JITTER_ENABLED` | `true` | env → `config.Config` → `reporter.Options.RetryJitter` | 严格布尔；使用 equal jitter |
| `SUSUMONITOR_METRICS_REPLAY_MIN_INTERVAL_MILLIS` | `2500` | env → `config.Config` → `reporter.Options.ReplayMinInterval` | 0–60000；积压下一条的最小等待 |

队列文件和父目录分别以 `0600`、`0700` 创建；安装脚本预建 `/var/lib/susumonitor` 并设为 `root:root/0700`。

## 3. 状态机和数据流

```text
collector
  → Reporter 创建带固定 UUID 的完整 metrics.report
  → Queue 原子写入 JSON snapshot（FIFO）
  → 唯一 in-flight sender 写入 WebSocket
  → ACK deadline 未确认时按退避/抖动重传同 UUID
  → Server metrics ingress transaction
  → metrics.ack(message_id)
  → Queue 仅匹配 FIFO 头部后原子删除
  → 若仍有积压，等待最小重放间隔后发送下一条
```

- 断线、写错误或 ACK 丢失：记录仍在磁盘；认证恢复或 ACK deadline 超时后均以**同一 UUID**重放。
- ACK deadline 超时以 `initial → max` 指数退避重传；启用 jitter 时实际等待为当前退避值的 1/2–1 倍，避免多个 Agent 同步重传。
- 一个时刻仅发送一个未确认指标，避免服务端 `collected_at` 严格递增约束下的乱序；ACK 后存在 backlog 时，以最小重放间隔限速。
- 缓冲满时拒绝**最新**采样并记录错误，保留最旧的可恢复 FIFO 前缀；本轮不静默丢弃。
- 缓冲文件损坏、版本不支持或所属 `server_id` 不匹配时启动失败，不猜测性丢弃待确认数据。
- M2/M3 Agent 的部署依赖 M1 Server（`773fc4d` 或后续版本）；旧 Server 不发 `metrics.ack` 会使队首持续保留，不能将超时伪装成投递成功。
