### 1.2 选题依据

根 README「已知遗留」明确列有：**「首用户注册即管理员（先到先得）：公网部署后应尽快注册首管理员，避免新环境被抢先接管；后续接入一次性 bootstrap token 可根治」**。这是当前唯一可在本地完成的产品级安全缺口——其余遗留项（真实 SMTP、Android 真机、限速代理、异地备份 crontab、多实例化阶段二）全部依赖外部环境或未满足的触发条件。

现行注册链路（`UserServiceImpl.register`）在 `auth_bootstrap_state.admin_initialized=0` 时把首个注册者直接提权为 `admin/approved`，攻击者只需在部署者之前调用公开端点 `POST /api/auth/register` 即可抢夺管理员。本批次以「一次性初始化令牌」根治：**系统尚无管理员时，注册必须携带服务器只投递给运维的一次性令牌**。

### 1.3 现行代码事实（本批次改造点）

- `AuthController.register`：`RegisterRateLimiter.checkAttempt(ip)` → `UserService.register(request)`；`SecurityConfig.java:96` 对 `POST /api/auth/register` permitAll。
- `UserServiceImpl.register`（`@Transactional`）：用户名冲突检查（40900）→ `authBootstrapStateMapper.selectForUpdate()` 行锁 → `firstUser = !adminInitialized` → admin/approved 或 user/pending → insert → `markAdminInitialized`。
- `AuthBootstrapStateMapper.xml`：仅 `selectForUpdate` 与 `markAdminInitialized` 两条语句。
- `CredentialCipher`：AES-256-GCM，`v1:` + Base64(12B IV + 密文+Tag)，AAD 绑定上下文（服务器维度 / 用户维度），可扩展。
- 契约 `openapi-auth.json` 0.2.0：4 端点；`RegisterRequest` required 仅 username/password。

## 二、口径决策（本次全部拍板）

1. **D1 语义**：`admin_initialized=0` 时注册**必须**携带有效一次性令牌，成功后该用户仍为 admin/approved，令牌立即作废；`admin_initialized=1` 后注册行为与现状完全一致（user/pending），令牌字段被忽略——**已部署且已有管理员的实例零影响、零迁移负担**（V37 只加列不回填）。
2. **D2 令牌来源优先级**：环境变量 `AUTH_BOOTSTRAP_TOKEN`（32-128 字符，非法长度启动 fail-fast，供 IaC 预置）> 数据库未消费密文（重启后从日志重新打印）> 自动生成（`SecureRandom` 32 字节 → base64url，43 字符 ≈ 256-bit 熵）。
3. **D3 存储**：AES-256-GCM 密文存 `auth_bootstrap_state` 新列，不存明文不存哈希（需要重启后回显明文，故选择可逆加密；验证用解密后 `MessageDigest.isEqual` 常量时间比较）。AAD 新增固定系统维度上下文 `susumonitor:bootstrap:token:v1`，与服务器/用户维度密文隔离。
4. **D4 投递**：启动横幅打印到控制台/日志（Jenkins initialAdminPassword / GitLab initial_root_password 同模式）。这是「日志不输出敏感信息」规范中**唯一显式例外**：令牌是一次性投递给运维的初始化凭据，消费后即失效，且不进任何请求日志/审计日志明文。载入/生成/消费各打一行不含令牌值的过程日志。
5. **D5 错误码**：新增 `40310 AUTH_BOOTSTRAP_REQUIRED`（未携带令牌）与 `40311 AUTH_BOOTSTRAP_TOKEN_INVALID`（令牌错误），均 403。同步 ErrorCode 枚举、前端 error-code.ts、契约。
6. **D6 新公开端点**：`GET /api/auth/bootstrap-status`（permitAll，无需认证）→ `{ bootstrap_pending: boolean }`。三端据此条件渲染令牌输入框/初始化提示。仅暴露一个布尔值，无增量信息泄露（注册 40310 亦可推断）。
7. **D7 并发与限流**：令牌校验与消费全部位于既有 `selectForUpdate()` 行锁事务内，与 20260824 首管理员并发验收同机制（并发注册最多一个首管理员、令牌至多消费一次）。令牌爆破尝试受既有 `RegisterRateLimiter`（42905）约束；256-bit 随机令牌爆破不可行，不新增专用限流器。
8. **D8 契约版本**：`openapi-auth.json` 0.2.0 → **0.3.0**（minor：新增 1 端点 + 1 可选请求字段 + register 403 响应 + 2 schema）。
9. **D9 三端同步**：后端 + Web + Android。Android 注册表单加令牌输入框（pending 时显示）并透传字段。
10. **D10 兼容性核验**：`api-e2e-test.mjs` 等脚本注册的是管理员已存在后的 user/pending 账号，不受影响零改动；本地/文档中涉及「空库首管理员注册」的运维说明在 P5 一并更新。

## 三、数据库迁移（Flyway V37）

`server-java-SuMon/src/main/resources/db/migration/V37__auth_bootstrap_token.sql`（H2/MySQL 双兼容，对齐 V7 风格）：

```sql
ALTER TABLE `auth_bootstrap_state` ADD COLUMN `bootstrap_token_cipher` VARCHAR(512) DEFAULT NULL COMMENT '一次性初始化令牌 AES-256-GCM 密文信封（v1: 前缀），消费后置空';
ALTER TABLE `auth_bootstrap_state` ADD COLUMN `bootstrap_token_generated_at` DATETIME DEFAULT NULL COMMENT '当前令牌生成/载入时间';
ALTER TABLE `auth_bootstrap_state` ADD COLUMN `bootstrap_token_consumed_at` DATETIME DEFAULT NULL COMMENT '令牌消费时间（首管理员创建时刻）';
```

- 密文长度估算：43 字符明文 → 59 字节密文 → Base64 ≈ 80 字符 + `v1:` = 83 字符，VARCHAR(512) 充裕（环境变量令牌上限 128 字符时约 172 字符，仍充裕）。
- 零数据回填：已部署实例三列均为 NULL 且 `admin_initialized=1`，运行时永不读取。
- `AuthBootstrapStateEntity` 加三个字段；resultMap 与 `selectForUpdate`/新 `selectState` 查询列同步补齐。

`RegisterRequest.java`：新增字段 `bootstrapToken`（Java 命名规范，`@JsonProperty`/springdoc 映射为 `bootstrap_token`——项目既有 DTO 用 `@Schema` + 属性名直映，需核对项目 JSON 命名策略；若全局 snake_case 策略已配置则字段名自动映射，实现时以 `AuthControllerTests` 既有断言为准）。校验注解仅 `@Size(min=32, max=128)`（可空；为空时 Service 层判定是否强制）。`@ToString.Exclude` 防泄漏。

### 4.2 后端核心（P2）

**新增 `ErrorCode`**：`AUTH_BOOTSTRAP_REQUIRED(40310, "bootstrap token required", HttpStatus.FORBIDDEN)`、`AUTH_BOOTSTRAP_TOKEN_INVALID(40311, "bootstrap token invalid", HttpStatus.FORBIDDEN)`。

**`CredentialCipher` 扩展**（新增方法，不改既有）：
- `encryptForBootstrap(String plaintext)` / `decryptForBootstrap(String envelope)`：固定 AAD `susumonitor:bootstrap:token:v1`，复用 `encryptWithAad`/`decryptWithAad` 私有通道。

**新增 `AuthBootstrapStateMapper` 方法**（XML 同步）：
- `AuthBootstrapStateEntity selectState();`——无锁读（bootstrap-status 端点与启动器用）。
- `int saveBootstrapToken(@Param("cipher") String cipher, @Param("generatedAt") LocalDateTime generatedAt);`——`UPDATE ... SET bootstrap_token_cipher=?, bootstrap_token_generated_at=?, bootstrap_token_consumed_at=NULL WHERE id=1 AND admin_initialized=0`。
- `int consumeBootstrapToken(@Param("consumedAt") LocalDateTime consumedAt);`——`UPDATE ... SET bootstrap_token_cipher=NULL, bootstrap_token_consumed_at=? WHERE id=1 AND admin_initialized=0`（返回 0 视为状态已被并发改变，事务回滚走 40900/DATABASE_ERROR 防御）。
- `selectForUpdate` 查询列补齐三个新列。

**新增 `BootstrapTokenService`（接口）+ `BootstrapTokenServiceImpl`**（`module/auth/service/`）：
- `String ensureTokenReady()`：启动器调用。读 `selectState()`；`adminInitialized=true` → 直接返回 null；否则 env `AUTH_BOOTSTRAP_TOKEN`（`appProperties.getSecurity().getBootstrapToken()`）非空 → 校验长度 32-128（非法抛 `IllegalStateException` fail-fast）→ `saveBootstrapToken(encryptForBootstrap(env值), now)` → 打印「已从环境变量载入」横幅（不回显值）；DB 已有 cipher → 解密回显横幅；否则生成 32 字节 `SecureRandom` → base64url → 存储打印横幅。
- `void verifyAgainst(AuthBootstrapStateEntity state, String candidate)`：`state.getBootstrapTokenCipher()` 为空 → 抛 `AUTH_BOOTSTRAP_REQUIRED` 之外的防御路径（理论上不发生，走 50001）；candidate 空 → 抛 40310；解密后 `MessageDigest.isEqual` 比较 → 不等抛 40311。
- 配置注入：`AppProperties.Security` 新增 `bootstrapToken` 字段（`@Value` 映射 `susumonitor.security.bootstrap-token`，默认空串），`application.yml` 加 `bootstrap-token: ${AUTH_BOOTSTRAP_TOKEN:}`。

**新增 `security/BootstrapTokenInitializer`**（`ApplicationRunner`）：启动时调 `bootstrapTokenService.ensureTokenReady()`，异常向上传播阻止启动（fail-fast 语义对齐 AesGcmKeyConfig）。横幅格式：

```
================================================================
  [SuSuMonitor] 系统尚未初始化管理员（一次性初始化令牌）：
      <TOKEN>
  请尽快使用该令牌调用 POST /api/auth/register 完成首管理员注册；
  令牌消费后立即失效。也可通过环境变量 AUTH_BOOTSTRAP_TOKEN 预置。
================================================================
```

**`UserServiceImpl.register` 改造**（参数传递链：`RegisterRequest.bootstrapToken` → Service）：
```
username 冲突检查(40900) → selectForUpdate()
→ if (!adminInitialized):
     bootstrapTokenService.verifyAgainst(state, request.getBootstrapToken())  // 40310/40311
     insert admin → markAdminInitialized → consumeBootstrapToken(now)
→ else: 现有 user/pending 逻辑，bootstrapToken 字段忽略
```
构造器新增 `BootstrapTokenService` 依赖（与既有构造器注入风格一致）。

**`AuthController` 变更**：
- 新增 `GET /api/auth/bootstrap-status` → `userService.getBootstrapPending()`（`UserService` 接口新增默认实现方法，读 `selectState()`，null 视为 pending=false 防御）→ `ApiResponse.success(new BootstrapStatusVo(pending))`。`@ApiResponses` 仅 200；permitAll 在 SecurityConfig 第 96 行追加 `GET /api/auth/bootstrap-status`（方法级 matcher 由 POST 改为 GET+POST 两条或合并写法，保持风格）。
- register 的 `@Operation` description 与 `@ApiResponses` 增加 403 行，与契约 0.3.0 同批对齐。

**VO**：`module/auth/vo/BootstrapStatusVo.java`：`private boolean bootstrapPending;`（布尔不取 is 前缀；Jackson 序列化为 `bootstrap_pending`——以项目全局命名策略为准，实现时核对 `CurrentUserVo` 既有字段 `review_status` 的序列化方式并对齐）。
