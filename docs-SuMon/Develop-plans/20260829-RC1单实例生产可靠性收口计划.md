## 五、阶段 2：单实例生产可靠性验收（P0，依赖外部环境）

### 2.1 HTTPS/WSS 与网络边界

1. DNS 指向正式域名并部署有效证书。
2. Nginx 443 配置 HTTPS/WSS，80 强制 301，验证 Upgrade、长连接、HSTS 和证书链。
3. `CORS_ALLOWED_ORIGINS` 只允许正式 HTTPS 前端来源。
4. Java 只监听回环或受控容器网络；MySQL 3306/33060、RabbitMQ 5672/15672、Redis 不向公网开放。
5. 显式配置并验证 `SSH_ALLOWED_CIDRS`；未授权目标必须返回 `40301`。
6. 生产启用 Redis 时设置强密码并验证 Ticket、JWT blacklist、登录/注册限流和 ready 探针。
7. Agent 只走出站 WSS，不开放入站端口；禁止使用 compose 默认 `ws://` 作为公网配置。

### 2.2 真实 Agent 可靠投递联合 E2E

使用真实 Linux Agent、Java、MySQL、RabbitMQ 和正式 WSS，依次验证：正常 ACK、断网缓冲、Agent 重启、Java 重启、ACK 丢失重传、FIFO 无重复、永久 NACK 死信、临时错误有限重试、Token rotate/revoke 和恢复后状态可追溯。

现有 loopback fixture 只能证明算法和组件行为，不能替代真实网络验收。

### 2.3 告警与通知

若产品开启外部通知：

- 专用测试邮箱验证 SMTP 成功、认证失败、网络失败、退避、最终失败、恢复通知和清理。
- 受控 Webhook endpoint 验证成功、超时、非 2xx、重试和幂等。
- 真实执行 `alert.triggered.v1`、`alert.resolved.v1` 的评估器→Outbox→Broker→消费者→通知→WebSocket 全链路。

若暂不开启 SMTP，生产保持 `ALERT_NOTIFICATION_ENABLED=false`，并在验收记录中明确“代码已实现、外部发送未启用”。

### 2.4 备份、恢复和回滚

1. 为 `remote-backup.sh` 配置 cron 或 systemd timer。
2. 将备份放到受控异地存储，明确密钥责任人、保留周期和磁盘告警。
3. 在隔离数据库恢复，验证数据、Flyway 版本、密钥和当前 JAR 能启动。
4. 定义 RPO/RTO 并记录校验结果。
5. 演练旧 JAR 回滚与数据库只向前迁移的边界；不得假设 Flyway 自动 down migration。
6. 记录发布失败后的服务恢复路径。

## 六、阶段 3：最小发布工程化（P1）

RC1 单实例验收通过后再做：

- GitHub Actions 或等价 CI：Java、Go race/vet、Web、Android、OpenAPI、Docker 和依赖漏洞扫描。
- clean checkout 构建，禁止依赖 `target/dist/build` 旧产物。
- JAR、Agent、APK 统一版本、commit、构建时间、SHA-256；逐步加入签名和 SBOM。
- Docker 镜像使用版本 tag + digest，补资源限制、日志轮转、secrets 和生产 overlay。
- 验收脚本增加当前 commit、动态端口、迁移版本、失败日志和清理校验。
- 将 Compose Monitor push 从可选观察改为硬断言。
- 接入 Actuator/Micrometer/Prometheus 或等价指标，覆盖 HTTP、JVM、DB pool、Outbox、DLQ、通知、Agent 在线率和备份失败。
- 为通知发送补连接/读取超时、有界线程池和多实例领取锁。

## 七、由产品决策触发的后续方向

### 多人/公网权限模型（P1/P2）

若系统面向多人或开放公网，再启动 bootstrap token、服务器级授权、短 access token + refresh token、设备会话、审计日志、通知渠道权限和 Agent root 权限收缩。当前首用户先到先得按已确认决策保持不变，但不应据此宣称适合开放公网。

### 多 JVM 分布式化（P1/P2）

仅在有明确并发/可用性要求后启动：Agent 连接租约、Monitor 订阅路由、指标/告警广播、终端跨实例中继、通知调度互斥和两实例滚动升级验收。当前 Agent/Monitor/Terminal Registry 仍是单 JVM 内存状态。

### 产品增强（P2）

忘记密码、Web 终端自动恢复、Android 进程杀死后的订阅恢复、通知重试 UI、Agent 多架构发布、`commands` 表业务以及 ANSI 模拟器超出当前边界的特性，均不作为 RC1 主线。
