## 一、计划目的

本计划以当前仓库、最新 OpenAPI 正式契约和已有运行时验证为基线，接替建立于
`web-vue-SuMon/` 空目录时期的初始前端计划。目标不是一次性堆完所有页面，而是按可验证
的业务闭环推进：先收口认证、路由、布局和类型基线，再完成服务器管理、SSH 安全操作、
管理员审核和自动化验收，最后在对应后端能力及协议正式就绪后扩展实时指标、告警和 Web
SSH 终端。

本计划必须遵循以下原则：

1. `docs-SuMon/OpenApi-SuMon/*.json` 是 REST API 唯一正式契约。
2. 只渲染后端已实现且已形成正式契约的入口，未就绪能力不显示空菜单。
3. 每个里程碑独立完成代码、类型检查、Lint、单元测试、构建和真实浏览器联调。
4. 编译通过、测试通过、浏览器运行时验证和真实外部服务验证分别记录，不互相替代。
5. JWT、密码、SSH 密码、私钥、私钥口令和其他密钥材料不得进入 URL、普通日志、
   控制台、测试输出、开发文档或非必要的持久化存储。
6. 前端权限控制只负责交互和导航，后端鉴权始终是最终安全边界。
7. 优先使用最小、清晰的页面和组件，不提前建立通用 CRUD 框架或推测性抽象。

## 四、技术与安全决策

| 项目 | 当前决策 |
|---|---|
| 框架 | Vue 3.5、`<script setup lang="ts">`、Composition API |
| 构建 | Vite；版本安全升级在 F0 独立验证，不与业务页面混改 |
| 组件库 | Element Plus，保持按需组件注册方向 |
| 路由 | Vue Router 4，受保护页面统一使用 `MainLayout` 父路由 |
| 状态 | Pinia 3；异步认证操作放在 Store action |
| HTTP | axios 单一实例；组件内禁止裸用 axios |
| 类型 | `openapi-typescript` 从三份正式 OpenAPI 生成，生成文件禁止手改 |
| Token | 保留“记住我”：勾选时将 token 和最小用户快照持久化到 `localStorage`，未勾选时仅保留于当前页面内存 |
| 单元测试 | Vitest + `@vue/test-utils`，测试就近放置 `*.spec.ts` |
| E2E | Playwright，连接真实本机后端和隔离测试数据 |
| 响应式 | 至少验证 360px、768px、1280px 三档宽度 |
| 可观测性 | 从响应头读取 `X-Request-ID`；错误详情可显示 request ID |
| 敏感数据 | 不持久化、不记录、不回显密码、私钥和口令；Token 仅按上述白名单策略存储 |

Token 决策说明：后端当前只接受 `Authorization: Bearer <token>`，尚无 HttpOnly Cookie
契约。产品决策保留“记住我”：勾选后使用 `localStorage` 跨刷新和浏览器重启恢复登录；
未勾选时 Token 只保留在当前 Pinia 内存中，刷新或关闭页面后不恢复。axios 必须同时支持
读取当前内存 Token 和已持久化 Token，不能因未勾选“记住我”而使当前页面后续请求丢失
Authorization。`localStorage` 不能抵御 XSS，已接受其较长暴露周期，必须通过依赖审计、
禁止未审计脚本、后端 JWT 过期和权限校验降低风险。若后续采用 HttpOnly Cookie，必须先
修改后端认证、CSRF、CORS 和 OpenAPI 契约，再单独迁移前端，不兼容两套认证机制。

## 十一、主要风险与处理

| 风险 | 影响 | 处理 |
|---|---|---|
| OpenAPI 与实现漂移 | 类型正确但运行时失败 | 生成类型、真实 API 验收和后端漂移检查共同约束 |
| localStorage 受 XSS 且跨浏览器会话保留 | JWT 泄漏与暴露周期延长 | 仅白名单保存 token/最小用户快照，不引入未审计脚本，401/退出立即清理，后端控制 JWT 有效期，部署阶段启用严格 CSP |
| 全局错误处理过度导航 | 登录或局部业务错误被错误重定向 | 仅 401 全局清理，403 由路由和页面上下文处理 |
| 敏感表单残留 | 密码或私钥进入内存快照、日志或附件 | 关闭即清空，不持久化，不记录，E2E 限制 trace |
| SSH 指纹交互误导 | 管理员错误信任攻击者主机 | 强制带外核对，禁止自动信任，轮换二次确认 |
| 固定侧栏不适配移动端 | 手机无法使用 | F1 引入抽屉菜单并验证三档宽度 |
| 测试数据误删 | 影响开发资产 | 测试前缀、目标确认、只通过业务软删除测试记录 |
| Vite 依赖漏洞 | 开发服务暴露风险 | F0 独立评估升级并记录 `npm audit` 实际结果 |
| E2E 依赖真实环境 | 用例不稳定 | 固定本机后端、隔离数据、明确重试边界，不掩盖真实失败 |
| 后端后续字段变更 | 重复返工 | 先冻结并更新 OpenAPI，再开发对应页面 |
