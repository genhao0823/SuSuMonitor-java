## 〇、根因（已确认，非崩溃）

Microsoft 官方文档（learn.microsoft.com/windows/wsl/wsl-config）：`.wslconfig` 的 **`vmIdleTimeout` 默认 60000 毫秒 = VM 空闲 60 秒后自动关闭**。阶段一观察到的"每 1-2 分钟 uptime 归零 + redis 自愈"实为 **idle 自动关闭**（每次 wsl 命令结束后 VM 空闲 60s 关闭，下次命令重新启动），不是崩溃。升级 WSL 2.7.3→2.7.11、停 dockerd、memory 限制均"无效"符合此解释。**修复 = 调大 vmIdleTimeout**（已应用 600000ms=10 分钟，静置 3 分钟验证 uptime 保持、redis 在线、localhost 转发稳定）。

## 一、目标

1. **环境修复**：`.wslconfig` 合并重复 `[wsl2]` 段 + `vmIdleTimeout=600000`；重启生效并验证稳定性。
2. **完成阶段一遗留验收**：双实例跨实例 ticket（A 签发→B 消费等 4 项）+ 失效演练 + verify-alert-ws 回归。
3. **Redis 安全加固一期**：
   - **JWT 黑名单**：`POST /api/auth/logout` 真实失效（jti 写 Redis，TTL=剩余有效期），任意实例携带已登出 token → 401

   - 两者 `REDIS_ENABLED=true` 才生效，默认 false 行为与现状完全一致

## 三、代码细节（安全加固一期）

### M3 JWT 黑名单
- `JwtTokenService.ParsedToken` + `Instant expiresAt`（parseToken 已有 claims.getExpiration()）
- `security/RedisTokenBlacklist`（@ConditionalOnProperty redis.enabled=true）：`revoke(tokenId, ttl)` = SET `susumonitor:jwt-blacklist:<jti>` EX ttl；`isRevoked` = hasKey
- `JwtAuthenticationFilter`：ObjectProvider 注入；parseToken 后 isRevoked → 401；认证后 ParsedToken 放 request attribute
- `SecurityConfig` bean 传参；`AuthController.logout` 从 attribute 取 ParsedToken → revoke（Redis 未启用时空操作）

### M4 登录防爆破
- `AppProperties.Security`：loginLimitMaxAttempts（默认 10）/ loginLimitWindowSeconds（默认 60）+ yml `LOGIN_LIMIT_*`
- `ErrorCode`：LOGIN_RATE_LIMIT_REACHED(42905)
- `LoginRateLimiter` 接口 + InMemory（默认）/ Redis（INCR+首次 EXPIRE）互斥
- `common/ClientIpResolver`：HttpServletRequest 版，复用 trusted-proxy CIDR，XFF 右起首个非代理
- `AuthController.login` 开头 checkAttempt；`GlobalExceptionHandler` 42905 加 Retry-After 头
