## 一、缺陷事实链（代码证据）

`AgentHeartbeatServiceImpl.markExpiredSessionsOffline`（扫描周期 30s，超时 90s）在判定 Agent 心跳超时后**先 `connectionRegistry.remove(session)` 再关闭 socket**（修复前 `AgentHeartbeatServiceImpl.java:85`）→ 触发 `AgentWebSocketHandler.afterConnectionClosed` → `TerminalRelayLifecycleService.closeAgentSessions` 的 `isCurrent` 检查**恒为 false** → 直接 return，终端收口被整体跳过。

**后果**：Agent 断网/休眠等心跳超时场景（连接未走 TCP 断开回调）下——
- 浏览器终端收不到 `terminal.closed(agent_disconnected)`，界面悬空
- Agent 侧 PTY 不关闭、`TerminalRelayRegistry` 路由绑定残留
- DB `terminal_sessions` 状态残留 `OPEN`，计入单 JVM 配额，仅靠每小时 `TerminalSessionCleanupScheduler` 兜底

正常 kill/网络断开路径无此问题（此时注册表尚未删除，`isCurrent=true`）。20260814 E2E 验收 dev-log 已留痕"未做 90s 心跳超时路径"。

## 二、修复方案

### M1 服务端修复
1. `AgentHeartbeatServiceImpl` 注入 `TerminalRelayLifecycleService`；`markExpiredSessionsOffline` 在 `connectionRegistry.remove(session)` **之前**调用 `closeAgentSessions(session)`：
   - 注册表仍指向该会话 → `isCurrent=true` → 正常完整收口（推 `terminal.closed(agent_disconnected)` 给浏览器 + DB `status=error` + 释放输出令牌桶 + 清路由绑定）
   - 随后 remove + 关 socket 触发的 `afterConnectionClosed` 再调 `closeAgentSessions` 时 `removeByServerId` 已空，**幂等安全**；`remove` 的 `serverSessions.remove(key,value)` 为条件删除，顶号竞态安全
2. `HEARTBEAT_TIMEOUT` 参数化：常量 90s → `AppProperties.Agent.heartbeatTimeoutSeconds`（默认 90，`@Min(1)/@Max(3600)`）+ yml `agent.heartbeat-timeout-seconds:${AGENT_HEARTBEAT_TIMEOUT_SECONDS:90}`——便于 E2E 快速验收与运维调优
3. 单测：`AgentHeartbeatServiceTests` 更新 4 个既有用例构造器 + 新增 2 用例（①InOrder 断言 `closeAgentSessions` 先于 `registry.remove`；②未过期不触发收口）

### M2 E2E 真实验收（沿用 20260814 WSL 隔离模式）
