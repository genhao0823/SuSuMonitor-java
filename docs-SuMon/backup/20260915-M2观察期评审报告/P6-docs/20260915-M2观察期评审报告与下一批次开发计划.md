## 二、批次 1（本期实施）：F4-M2 观察期评审报告

### 2.1 目标

给 M2 自动审批的出口评审提供**数据核对面**：admin 在 Web 端选择观察窗口（默认 14 天），系统对 `ai_command_runs` 审计行做窗口聚合，输出总量/结构分布/自动执行质量指标，并按**评审基线 v1**逐项给出 PASS/FAIL/样本不足结论。只读、零迁移、零新依赖。

### 2.2 口径决策（本次已拍板）

1. **查询时聚合，不建快照表**——`ai_command_runs` 已有 `idx_ai_command_runs_created_at` 索引，30 天窗口聚合为单次扫描；评审是低频管理动作，物化反而引入一致性问题。
2. **评审基线 v1 常量定义在 Service**（含 javadoc 说明），不引入配置项——基线本身需要评审通过才能变更，做成配置会削弱其"门禁"语义。
3. **rejected 不细分原因**——V29 表无拒绝理由列（rejectRun 仅记审批人），报告不做"安全拒绝"分类，防虚构口径。
4. **策略无历史快照**——单行策略表只反映当前值，报告如实携带当前策略并在前端标注"窗口内策略变更未追踪"，列为本批次已知边界。
5. **命令域 kill switch 语义不变**——端点挂在 `CommandRunController`（`@ConditionalOnProperty(susumonitor.ai.command.enabled)`），关闭时 404，与既有命令端点一致。
6. **窗口上限 90 天**，实际覆盖受审计保留期（默认 30 天）约束，报告携带 `window_start/window_end` 让读者知晓真实覆盖面。

### 2.3 接口契约（契约先行，openapi-command.json 0.1.0 → 0.2.0）

```
GET /api/ai/commands/observation-report?window_days=14
权限：ROLE_ADMIN（SecurityConfig 既有 /api/ai/commands/** 规则覆盖，零改动）
200：ApiResponse<CommandObservationReport>
401/403：同既有命令端点
```

响应 data 结构（对外 snake_case，VO 用 `@JsonProperty` 镜像既有风格）：

```json
{
  "window_days": 14,
  "window_start": "2026-09-01T10:00:00+08:00",
  "window_end": "2026-09-15T10:00:00+08:00",
  "total_runs": 123,
  "by_status": { "succeeded": 100, "failed": 5, "timeout": 2, "expired": 6, "rejected": 8, "pending_approval": 1, "approved": 0, "executing": 1 },
  "by_approval_mode": { "manual": 100, "auto": 23 },
  "by_risk_level": { "low": 120, "medium": 3, "high": 0 },
  "by_source": { "ai": 60, "manual": 63 },
  "auto_executed": 23,
  "auto_failed": 2,
  "manual_executed": 100,
  "manual_failed": 1,
  "distinct_servers": 4,
  "avg_duration_ms": 812,
  "max_duration_ms": 4300,
  "template_usage": [ { "template_id": "systemctl_status", "runs": 40 } ],
  "policy": { "enabled": true, "max_risk_level": "medium", "updated_at": "..." },
  "criteria": [
    { "key": "sample_size", "value": 123, "threshold": ">= 30", "passed": true },
    { "key": "auto_failure_rate", "value": 0.087, "threshold": "<= 0.05 且 auto 样本 >= 10", "passed": false },
    { "key": "timeout_rate", "value": 0.016, "threshold": "<= 0.02", "passed": true },
    { "key": "high_risk_auto", "value": 0, "threshold": "= 0", "passed": true },
    { "key": "expired_rate", "value": 0.049, "threshold": "<= 0.20", "passed": true }
  ],
  "overall": "fail"
}
```

- `passed` 三态：`true` / `false` / `null`（该项样本不足，无法评判）；`overall` ∈ `pass` / `fail` / `insufficient`。
- 比率字段统一 BigDecimal scale=4 序列化为数字；无样本时 `avg_duration_ms` 为 null。
- criteria 中文标签由前端按 `key` 映射（后端不出标签，保持契约稳定）。

### 2.4 评审基线 v1（Service 常量， javadoc 说明出处）

| key | 基线 | 不足样本判定 |
|---|---|---|
| `sample_size` | 窗口内总运行数 ≥ 30 | total_runs < 30 → overall=insufficient |
| `auto_failure_rate` | (auto failed+timeout) / auto 终态 ≤ 5% | auto 终态 < 10 → passed=null |
| `timeout_rate` | timeout / 已执行终态(succeeded+failed+timeout) ≤ 2% | 终态 < 10 → passed=null |
| `high_risk_auto` | approval_mode=auto 且 risk_level=high 的行数 = 0（策略不变量守护，防越权/脏数据） | 恒可评判；>0 硬 FAIL |
| `expired_rate` | expired / total_runs ≤ 20%（审批时效/关注度） | total_runs < 30 → passed=null |

`overall` 规则：任一可评判项 FAIL → `fail`；否则 `sample_size` 不足 → `insufficient`；否则 `pass`。

### 2.5 代码细节与参数传递

**后端**（`module/command/`，全部 `@ConditionalOnProperty(susumonitor.ai.command.enabled=true)`）：

- `mapper/CommandRunMapper.java` 新增两个方法（XML 同批）：
  - `CommandObservationAggregate selectObservationAggregate(@Param("windowStart") LocalDateTime windowStart)` —— 单条聚合 SQL：`COUNT(*)`、8 个 `SUM(CASE WHEN status=...)`、approval_mode/risk_level/source 各 2-3 个 SUM、`COUNT(DISTINCT server_id)`、`AVG(duration_ms)`、`MAX(duration_ms)`、`auto_executed`/`auto_failed`/`manual_executed`/`manual_failed` 组合 SUM。`WHERE created_at >= #{windowStart}`（命中 `idx_ai_command_runs_created_at`）。SUM 映射 Long（MySQL DECIMAL→BIGINT 由 resultMap 显式转换），AVG 映射 BigDecimal。
  - `List<TemplateUsageAggregate> selectTemplateUsage(@Param("windowStart") LocalDateTime windowStart, @Param("limit") int limit)` —— `GROUP BY template_id ORDER BY COUNT(*) DESC LIMIT #{limit}`（limit 常量 10，服务端传入）。
- 新建 `dto/CommandObservationAggregate.java`、`dto/TemplateUsageAggregate.java`（纯数据载体，MyBatis 别名直映射）。
- 新建 `CommandObservationReportService.java`：
  - `generate(int windowDays)`：`windowStart = LocalDateTime.now(clock).minusDays(windowDays)`；聚合 → 比率计算（BigDecimal.divide，scale 4, HALF_UP，分母 0 时 null）→ criteria 组装（Key/Value/Threshold/Passed record）→ overall 判定 → 组装 `vo/CommandObservationReportVo`（嵌套 `CriterionVo`、`TemplateUsageVo`、`PolicyVo`，`@JsonProperty` snake_case）。
  - 策略快照复用 `CommandAutoApprovalPolicyService.get()`。
- `controller/CommandRunController.java` 新增：`@GetMapping("/observation-report")`，`@RequestParam(value="window_days", defaultValue="14") @Min(1) @Max(90) Integer windowDays`，薄委托 Service。
- 测试（JUnit5 + Mockito，对齐 `CommandRunServiceTests` 惯例，Clock 注入固定时刻）：
  - Service：基线全 PASS → overall=pass；auto 失败率超限 → fail 且该项 passed=false；auto 样本不足 → passed=null；总量不足 → insufficient；比率分母为 0 → null 不 NPE；high_risk_auto>0 → fail；窗口参数边界。
  - Controller：WebMvcTest（对齐 `CommandRunControllerTests`）——admin 200 结构、非 admin 403、缺省 window_days=14、越界 400。

**前端**（`web-vue-SuMon/`）：
